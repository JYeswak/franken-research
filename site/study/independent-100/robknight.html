Relevance to our work

5 of 5 lenses: agents, orchestration, verification

terminal-browser is an MIT tool that fits our tmux fleet directly: agents get an in-pane browser with an agent-browser compatible CLI, it works over SSH on remote workers, and it can show HTML plans next to the agent. It is a candidate for UI verification by agents without a separate headed Chromium.

Scored 0 to 5 against the study’s relevance rubric: 5 means public, openly licensed work squarely in our lanes that we could study or adopt now, and 1 means little connection to our work. The score is one reviewer’s judgement of how much this public work bears on our own work. It is not a ranking of people and says nothing about the person or the quality of their work.

What we would study next

  1. Try terminal-browser in an NTM tmux pane, and test terminal-browser action against our agent-browser skill (github.com/zenbu-labs/terminal-browser). It could give fleet agents browser verification inside the same tmux session, including on remote hosts over SSH. Effort: small.
  2. Read the terminal-browser Claude Code plugin (github.com/zenbu-labs/terminal-browser/tree/main/claude-code-plugin). It shows how a browser CLI is packaged as an agent plugin; compare with our skills and hooks. Effort: small.
  3. Skim zenbu.js for the 'hackable software' architecture (github.com/zenbu-labs/zenbu.js). Context on what Zenbu is building; low priority. Effort: medium.

Before reusing anything: terminal-browser, terminal-code, zenbu.js and react-scan are MIT per the GitHub license API (2026-09-25). react-scratch has no license. The installer is curl|bash from terminal-browser.sh; review it before running on fleet hosts. A browser driven by an agent is a prompt-injection surface (PI_WEB).
