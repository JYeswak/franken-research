Learn → run → inspect → adapt

Put the research to work.

Start with tools you can run in your own project. Inspect what they actually check, then decide what to adopt.

Download the runnable kit   Hashes and file manifest

Code revision bb105a93280a1b58 · 3 worked entry points · MIT first-party code. No third-party source snapshots or private experiment logs are bundled.

Extract the ZIP and start in fr-starter-kit/. Compare its SHA-256 with the manifest before running it. For existing projects, review and copy selected files; reinstalling is not an upgrade procedure.

Give an AI project gates that can actually fail

Catch an incomplete plan and unsupported evidence labels before work is signed off.

Requires: POSIX shell utilities; Git recommended. Use a new project directory.

sh scripts/init.sh ../my-new-project
cd ../my-new-project
sh scripts/check-readiness.sh

Expected: A pristine project reports NOT READY (exit 1). Complete and review the packet before expecting success.

Limits: Structural completeness is not execution authorization. The installer is not an upgrade command; it reinstalls the live hook.

Run, invalidate and transfer an evidence-backed decision

Learn how to stop an old experiment result silently supporting changed code.

Requires: Python 3.9+, POSIX shell utilities. Give the exercise a destination that does not exist.

python3 examples/decision-cycle/run.py ../decision-exercise

Expected: A real local execution receipt, a stale-input failure, a demoted claim, and a standalone public transfer. See the exercise README for generated paths.

Limits: This deliberately small exercise teaches identity checking; it does not prove research quality or a speedup on your workload.

Resume the decisions that need attention

Hand an agent the specific next check and the evidence that made it necessary.

Requires: Python 3.9+ and your own maintained version-1 decision record; paths are relative to your project root.

python3 scripts/review-decisions.py path/to/decisions.json --root /path/to/project --json
python3 scripts/check-decisions.py path/to/decisions.json --root /path/to/project --refresh

Expected: A ranked review queue; refresh demotes stale labels and never promotes claims.

Limits: A zero exit can still mean REVIEW or defer. Read the state. Metadata must already be safe to share; export is not a rights classifier.

What counts as better?

Measure a fresh user task: correct application, missed or false claims, transfer failures, and total setup, review and maintenance effort. These tools have bounded regression checks. A 100× improvement in research value has not been demonstrated.
