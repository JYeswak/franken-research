## 1. OWN-PACKET DISTILLATION

- **Verdict (one line):** A 2,851-line, 3-crate Rust experiment that compiles native code with Cranelift and then refuses to run its own compiler output unless it is byte-identical to one frozen 39-byte audited machine-code constant — arguably the most adversarially honest small repo in the program [Inference, Medium] ("bring-up evidence only," "not enabled by FrankenEngine"), whose own packet concludes: adopt the patterns, not the package.
- **TRL:** 3–4 — "the strongest slice of mechanism executes in a lab environment (relevant-environment validation), short of TRL 5 (no integration in a relevant environment)" [Inference, Medium].
- **NODUS ring:** **Explore**, explicitly **"Explore-with-a-ceiling"** [Inference, Medium] — "Substantive-but-unproven is the textbook Explore case."
- **What it is:** a 3-crate Rust workspace — 2,851 first-party lines across 6 files [Counted, High] — Linux x86-64-v3 only, with an optional `embedded-fixed-probe` path: a Cranelift 0.134.2 compiler worker that lowers a wrapping `u64 -> u64` sum loop, and a runtime that maps, invokes, and retires executable images.
- **Strongest strength:** the adversarial honesty plus the byte-exact admission gate. "Cranelift 0.134.2 compiles a wrapping `u64 -> u64` sum loop, but output is rejected unless byte-identical to a frozen **39-byte** machine-code constant" [Code-verified, High]; the README calls the implementation "bring-up evidence only," "not enabled by FrankenEngine," and says it "establishes no production containment or performance claim" [Maintainer claim, High]. The packet's own verdict on the mechanism: the worker "distrusts its own output."
- **Strongest ceiling:** there is no consumer — "FrankenEngine does not enable it" [Maintainer claim, High] — and a grep over all 44 assessment packets finds **no other packet mentions `franken_native_capsule` at all**: the dependency claim is one-sided. The missing-controls list is named: NRP/RCO v1, issuer signature verifier, durable nonce store, worker supervisor, process sandbox/supervisor, unwind/CFI registration [Maintainer claim/Code-verified, High].
- **Unsafe discipline:** 13 counted `unsafe {}` blocks, all inside two explicitly allowed modules; exactly 13 stable `NCC-SAFETY-*` invariant IDs, one per block, each with a per-module safety section and linked test; the API and worker crates carry `#![forbid(unsafe_code)]` [Counted + Code-verified, High].
- **Executable-memory lifecycle:** guard-paged `PROT_NONE -> RW -> RX`, never RWX; retirement removes execute, zeroes the image, and unmaps it [Code-verified, High].
- **Receipt chain:** canonical postcard encoding, SHA-256 binding of the plan, the compiler identity, the RCO, the activation image, and the retirement event [Code-verified, High] — but the receipts are **unsigned**.
- **Tests:** 10 counted test functions, read but not executed; there is no CI and no `.github/` directory [Counted/Verified, High].
- **Governance:** a single squashed commit as the entire history, bus factor 1, no tags, no releases, no contribution policy, no CI [Git-observed/External, High].
- **License posture:** the root `Cargo.toml` declares `license = "MIT"`, but there is no LICENSE text in the repo, GitHub detects no license, and there is no OpenAI/Anthropic rider — unlike the rider-bearing suite majority [Code-verified/Verified/External, High].
- **Metadata drift:** `repository` points to the nonexistent `https://github.com/franken-suite/franken_native_capsule` [Code-verified + Verified, High], and the AGENTS.md unsafe allowlist names modules that do not exist.
- **Inventory mismatch:** the assigned run-inventory description (an audio player) is disproven in full — "no audio/UI/asupersync terms in the repository" [Verified, High].
- **Benchmark posture:** no benchmark exists, and the README expressly disavows performance claims [Maintainer claim, High].

## 3. CI/EVIDENCE BAR — what franken_native_capsule demonstrates that others lack

Honest caveat first: the capsule has **no CI and its tests were read, not executed** [Counted/Verified, High] — while frankenredis runs CI #7679 against the pinned commit [CI-observed, High], frankenscipy is G1–G9 green at the pin [CI-observed, High], and franken_threed has independently re-executable green differential tests. What follows is not CI maturity but the specific *evidence mechanisms* for which no other packet shows an instance:

1. **Executable-memory permission assertions.** Tests inspect `/proc/self/maps` and assert RX-without-W on every mapped region [Code-verified, High]. A grep across all 44 packets finds `/proc/self/maps` mentioned in exactly one: this one.
2. **A byte-exact executable-admission gate.** The worker's compiled output is "rejected unless byte-identical to a frozen **39-byte** machine-code constant" [Code-verified, High] — and `cranelift-jit` is deliberately forbidden, so there is no bypass path. Any codegen or toolchain change fails closed: the packet's skeptic notes the gate's "generality of zero" is the design, not a bug. Byte-exactness *as a property* is shared (franken_tts: browser PCM matches CLI "sample-for-sample (96,000/96,000, max 0 LSB)" [Verified, High]; franken_nlp's byte-identical tensor-census replay; frankenredis's byte-exact wire parity) — but no other packet gates *executable machine code admission* on byte-identity to an audited constant.
3. **Compiler-identity binding into the artifact chain.** The full Cranelift 0.134.2 dependency graph is pinned with exact `=` versions (with comment rationale); the compiler identity string is SHA-256-hashed into the receipt chain; a compiler upgrade is a breaking change by design [Code-verified, High]. Peers pin oracles and toolchains (franken_whisper's pinned truth pack, frankensympy's pinned SymPy 1.14.0 oracle [Maintainer claim, High], franken_snowflake's dependency admissibility gate), but no peer packet describes the compiler identity hash being bound into an artifact receipt as a versioning rule [Inference, Medium on the sweep].
4. **The exact-1:1 unsafe census — honestly, a shared family, not a unique artifact.** The capsule has 13 `NCC-SAFETY-*` invariant IDs for 13 counted `unsafe` blocks with linked tests [Counted + Code-verified, High]. But frankengraphdb has the ledgered cousin at 735k-line scale: `registries/unsafe_boundary_ledger.toml` tracking exactly 6 `unsafe {}` sites in three `fgdb-unsafe-*` crates, plus stable invariant IDs `FG-INV-01 … FG-INV-20` in a machine-readable registry with CI cross-checks [Code-verified, High]; franken_lean has a 697-row `ci/UNSAFE_LEDGER.txt` with a "bidirectional CI census" that passed at the pin [CI-observed, High]; frankentorch carries `SAFETY`-invariant comments across 116 counted unsafe sites [Code-verified, High]. The capsule's is the most *exact* specimen (the count matches by construction in a 2,851-line tree), not the only one.
5. **The bring-up disavowal convention** — the README enumerates non-capabilities in writing ("bring-up evidence only," no containment or performance claims) [Maintainer claim, High]. Strong but shared: franken_drone_geometry_reconstruction ("~18 explicit non-claims"), franken_remote (explicit non-claims), franken_ocr (published losses — "negative results as product"), franken_lean (`council.rs`'s "What this does NOT claim" and the README's tense note), frankentui (explicit non-goals, "out of scope for October"). The capsule's is among the clearest minimal examples.
6. **The receipt chain is honest-party provenance, not third-party evidence.** Canonical postcard encoding, SHA-256 binding plan → compiler identity → RCO → activation image → retirement [Code-verified, High] — but unsigned, which is why frankenterm's sigstore-signed attestation bundles ([Verified, High], §6.5) and franken_engine's signed evidence ledger with MMR inclusion proofs [Code-verified, High] remain the bar the capsule does not clear.

## 6. CROSS-POLLINATION IN

1. **Planted-mutation qualification of the refusal behavior → from franken_alignment → why it fits:** the capsule's entire security claim is that the worker *refuses* — wrong bytes, replayed nonces, mutated receipts. franken_alignment runs "planted-mutation testing (defects deliberately introduced, required to fail after controls pass)" [Code-verified, High]. **Expected payoff:** apply to RCO/receipt/nonce/entrypoint mutations and the refusal claim becomes measured negative evidence instead of ten read tests — the packet's own next-step 2 (a mutation harness with a refusal taxonomy) gets its discipline from a project that already runs the practice. *Falsifiable:* a one-byte mutation of the frozen constant must be refused with the correct typed error [Inference, Medium].

2. **A claim-to-proof matrix gating README wording in CI → from franken_engine → why it fits:** the capsule's honesty engine is README prose plus AGENTS.md, and both have already drifted (allowlist naming nonexistent modules; nonexistent `repository` URL; v1/v0 vocabulary confusion). franken_engine's "binding claim-to-proof matrix (28 claims: 13 OBSERVED / 8 TARGETED / 7 HYPOTHESIS… that gates README wording in CI" with "exact downgrade text" when "wording outruns its evidence" [Code-verified, High] is the machine that prevents exactly this. **Expected payoff:** the "bring-up evidence only" status, the missing-controls list, and the NRP/RCO vocabulary become rows with verification commands instead of prose that rots.

3. **A machine-readable unsafe-boundary registry with an enforcement tool → from frankengraphdb → why it fits:** the capsule's 13/13 `NCC-SAFETY-*` census is prose + tests today, and its allowlist already names modules that don't exist. frankengraphdb's `registries/unsafe_boundary_ledger.toml` is "enforced by a std-only `tools/registry-check`" [Code-verified, High]. **Expected payoff:** the capsule's exact census becomes a build failure on drift rather than a counted coincidence — the drift the packet already documents would not have survived a registry-check.

4. **Anchor-bound contracts with `expect=` drift tokens → from franken_lean → why it fits:** the frozen 39-byte constant is the capsule's single most load-bearing artifact, and "frozen" is currently a prose promise. franken_lean's `KERNEL_CONTRACT.md` gives each rule "an `anchor:` line naming the exact upstream file and line at the pin… and a conformance test… fails CI if the token on that line ever changes" [Code-verified, High]. **Expected payoff:** bind the constant's audit rationale to the exact audit artifact with `expect=` tokens, so any silent change to the constant or its rationale is machine-flagged before any human notices — the lean packet's falsification ("if humans find them first, the mechanism is ornament") applies directly.

5. **Sigstore-signed attestation bundles for the receipt chain → from frankenterm → why it fits:** capsule receipts are hash-chained but unsigned; the packet's next step 4 asks for an issuer signature. frankenterm ships "content-addressed, sigstore-signed release attestation bundles" with "per-category producing-bead provenance," a claim registry, negative-evidence slots, and "`ft attestation verify <bundle>` is the claimed one-command flow" for cold third-party verification [Verified, High]. **Expected payoff:** converts the capsule's honest-party hash provenance into third-party-verifiable attestation without inventing a signing scheme — and the negative-evidence slots have a natural home in the capsule's refusal ledger.

6. **A measurement-integrity gate for the refusal ledger → from frankentorch → why it fits:** once the mutation harness exists, its refusal statistics must be quotable under rules. frankentorch's standing gate "states the quotable-vs-PyTorch position plainly" via the rules "(name the worker, name the harness, quote both estimators, replicate before quoting)" [Maintainer claim, High]. **Expected payoff:** the capsule's refusal taxonomy (typed refusal classes per the packet's next step 2) ships with the quoting discipline that keeps it from becoming self-graded statistics.

## 7. CROSS-POLLINATION OUT

1. **The frozen-byte executable admission gate → to franken_engine → why it fits them:** the capsule is engine's declared-but-unenabled downstream; engine's AOT/tiering modules are "plans, guards, or provenance" that "should not be read as machine-code execution" [Maintainer claim, High] — a compiler backend held as design, not execution; and its "end-to-end capability-typed TS-to-IR contract — the headline security promise — is TARGETED by the maintainer's own matrix" [Maintainer claim, High]. The capsule packet's own next step 1 proposes exactly this: "export as program's native-code execution template." **Expected payoff:** if engine ever builds the compiler backend it holds as design, the frozen-byte gate is the only audited-bootstrap admission discipline in the program — admit exactly one known-good machine-code blob, refuse everything else, fail closed on toolchain change. (And engine's signed-receipt machinery, §6.5's import, is the natural return trade: the gate becomes attestable.)

2. **The frozen-byte gate, forward-looking → to frankensympy → why it fits them:** its dual-lane architecture lowers "eligible expression regions" into "a deterministic, proof-carrying native kernel" [Maintainer claim, Medium] — the one other project in the program whose architecture points at executing lowered code, even though the sweep found no JIT/Cranelift/LLVM in its packet (so this is forward-looking, not a current fit). **Expected payoff:** when that kernel is mapped executable, the byte-exact admission gate is the trust boundary to adopt — proof-carrying claims meet an execution gate that refuses anything unproven.

3. **The allowlisted-unsafe census (NCC-SAFETY-* IDs, exact 13/13 count, named allow modules, `forbid` elsewhere) → to frankentorch (primary), frankenredis, frankensqlite, frankenlibc → why it fits them:** frankentorch is the exact pathology the capsule's census prevents — "the docs claim 'unsafe forbidden' while the tree holds **116** counted unsafe sites under deny-gates with documented allows and SAFETY-invariant comments" [Counted, High]; the census turns a stale "forbidden" claim into a checkable 1:1 ledger.
