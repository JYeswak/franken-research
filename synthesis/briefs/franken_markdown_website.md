## 1. OWN-PACKET DISTILLATION

**Verdict:** "a credibility machine for the FrankenMarkdown engine — the rare marketing site whose central claims re-derive from its own tree — currently undermined by the exact failure mode it was built to prevent: its transparency copy has drifted two engine versions behind the binary it ships" [Inference, Medium].

**TRL:** 8 ("Complete system deployed and serving at franken-markdown.com with local test/verify suites — but production (0.4.1) lags the assessed pin (0.4.2) and no automation runs the suites") [Inference, Medium].

**NODUS ring:** **Monitor** [Inference, High] — "the Rulebook's explicit bucket for web properties. The site is a finished, deployed, live artifact (TRL 8), but as a research-program object it is *support infrastructure for the engine's credibility story*, not an advancement candidate. Its durable export is the verifiability pattern (prove-don't-promise marketing), not the pages."

**Strongest strength:** The site's own-mechanics claims verify at High confidence — the demo *is* the engine (wasm-bindgen module in a module Web Worker with transferable ArrayBuffers [Code-verified, High]); zero external script/stylesheet URLs and zero analytics identifiers [Code-verified, High]; the fragment-share format proven by execution (analyst decoded the README's own example share URL: 202 payload chars → deflate-raw → 197 bytes of Markdown) [Verified, High]; the 0.3.5 artifact receipt re-derives exactly on two of three legs (sha256 `1da66d98…` and raw 4,028,677 bytes match) [Counted, High].

**Strongest ceiling:** The honesty apparatus has no automation behind it and has already failed its own standard: no CI at all (no `.github`; "every verification script is a manual `bun run`") [Code-verified, High]; the Lab Notes strip is two engine versions stale (0.3.5 claimed vs 0.4.2 shipped vs 0.4.1 live) [Verified, High]; and the executed kill test proved production is not reproducible from the repo — "8 stale assets… the live wasm wrapper/glue match *no* committed tree — production was deployed from a working tree that exists nowhere in the repo" [Verified, High].

**3 most important pieces of evidence (with packet tiers):**
1. **Executed kill test (claim 21), disproven [Verified, High]:** ran `node dev/verify-live-assets.mjs` against https://franken-markdown.com on 2026-09-22 — 8 stale of the refs checked (all five JS modules, `site.css`, 0.4.2 wasm wrapper + glue differ from pin; fonts, og.png, and the 0.4.2 wasm *binary* match). Edge-transformation ruled out (Cloudflare Pages does not rewrite asset bytes; the matching assets prove it).
2. **Self-contradicting live page (claims 7/18), disproven [Verified, High]:** fetched 2026-09-22 — the header strip says "Renderer v0.4.1 in this page" while the Lab Notes section on the same page says "This page runs engine 0.3.5 WASM." The page contradicts itself.
3. **Dual-0.3.5 binaries (claim 17), disproven [Counted, High]:** `assets/wasm/0.3.5/pkg/franken_markdown_bg.wasm` (sha256 `5c0135b3…`, 4,151,165 B) matches neither the README receipt sha nor its byte count — only the unversioned legacy tree matches. Two different binaries in the tree both wear the 0.3.5 label with no manifest disambiguating which one production served.

## 3. CI/EVIDENCE BAR — what franken_markdown_website demonstrates that others lack

**`verify:live` — content-hash deploy verification with transitive closure.** Mechanism: a 67-line script that regex-scrapes `href/src="assets/…"` from `index.html`, then follows the JS import chain (`from "…"` specifiers, `new URL(…, import.meta.url)`) down through the wasm-bindgen glue to the `.wasm` binary — "so a new reference can't silently escape verification"; fetches each live with `cache: no-store`, strips `?v=` for local reads but keeps it for remote fetches (verifying the cache-bust strings themselves), reports `cf-cache-status` per asset, compares 12-char sha256 prefixes, nonzero exit on any stale asset; rationale: "verify content, not headers" [Code-verified, High]. Who lacks it: **every other website packet** — frankensqlite_website ("158 counted test call sites… no CI workflows," analyst "never verified the… Vercel deployment configuration"), frankentui_website ("no `.github/workflows` directory… Playwright suites run locally or not at all"), frankensim_website ("no CI at all"), the two beads sites (stale snapshots with no freshness check). No other packet documents a mechanism that sha-compares live production bytes against the pinned tree.

**Analyst-executed production kill test.** Mine ran the repo's own tool against production and reported the disproof (8 stale assets, exit nonzero) [Verified, High]. Other packets' kill tests are conceptual: frankenredis's kill test was the CI-red-at-pin finding via the Actions API [CI-observed, High]; frankentui's was the phantom-v0.9.0 ledger test [Inference, Medium]. Mine is the only packet whose analyst executed the project's own verification script against its own production and published the failing result.

**Public negative-evidence content strip.** The Lab Notes "Honest scar tissue" strip, the Limitations section, and `_headers` caching notes "recording the maintainer's own stale-deploy incidents and their mechanism" [Code-verified, High] — marketed weakness with dates and mechanisms, i.e. negative evidence as page content. The nearest sibling is franken_whisper's `no_canned_phrases` regression guard — "the scar tissue is in the test suite" [Verified, High] — which is test-suite scar tissue, not public-facing content. franken_alignment and franken_tts publish NEGATIVE_EVIDENCE.md / discrepancies ledgers, but as docs, not as the product's own homepage strip.

**Privacy-by-architecture share design.** The fragment-share's privacy property "holds even if you distrust the operator" because URL fragments are never sent to the server and there is no backend — architecture, not copy [Code-verified, High]. No sibling packet claims an equivalent operator-independent property for a user-facing feature.

**What is NOT unique (honest accounting):** the sha256 artifact receipt pattern is shared with **beads-for-frankentui** ("a real SHA-256 chunk manifest whose hashes the analyst re-verified 11/11" [Verified, High]) and with the **franken_markdown engine** itself (releases ship `.sha256` sidecars; verified via the releases API). The e2e/stress/smoke *suites* as artifacts are common (e.g. frankensqlite_website's 158 counted test call sites; frankentui's `doctor_frankentui` harness) — what is distinctive about mine is that the *deploy-vs-live* comparison tool exists and was executed.

## 5. GENUINE UNIQUENESS (only things no other packet does)

1. **`verify:live` content-hash deploy verifier with transitive-closure asset following** (script → follows JS import chain → wasm-bindgen glue → binary; compares content, not headers; distinguishes edge-vs-origin staleness via `cf-cache-status`). Grep for `verify:live`/deploy-verifier across all 44 packets returns only this one.
2. **The fragment-share URL protocol as a documented, execution-proven micro-protocol** (`zdoc=`/`doc=` + `view=`/`fmt=` params; deflate-raw → base64url in the `#` fragment; analyst decoded a real share URL to prove it). No other packet has a backendless sharing protocol.
3. **Versioned wasm-trio directory discipline** (wrapper/glue/binary pinned in per-version directories so they update atomically — "the design explicitly defeats edge-cache skew," with per-version `_headers` rules). No other packet versions vendored artifacts by directory; frankensim_website, the closest analog, has "no hash linkage between the vendored `.wasm` and the parent repo's `fs-wasm` crate source" [Code-verified, High].
4. **A public, on-page "Honest scar tissue" strip** (Lab Notes) as marketing content confessing partial CommonMark coverage and the maintainer's own stale-deploy incidents. frankensqlite_website has adjacent candor (the comparison table grades itself "Production Maturity: Early") but not a dated scar-tissue strip; frankensqlite_website's own next-step list does not include one.
5. **Privacy architecture as a verifiable page property**: zero external URLs, zero analytics identifiers, self-hosted fonts (88,660 bytes measured vs "87 KB" claimed [Counted, High]) — the no-tracking claim is auditable from the tree. (franken_whisper's scar tissue is in its test suite, not its shipped surface.)
6. **The executed production kill test as an assessment method**: the only packet whose analyst ran the project's own deploy-verifier against its own production and reported a disproof with nonzero exit [Verified, High].

Merely "also does X" (not unique): the sha256 artifact receipt (shared with beads-for-frankentui's chunk manifest and the engine's release `.sha256` sidecars); negative-evidence ledgers as docs (franken_alignment, franken_tts, franken_whisper have NEGATIVE_EVIDENCE.md / discrepancies ledgers); e2e/smoke/stress suites existing (frankensqlite_website, frankentui, franken_tts all have them); a wasm-in-browser demo (franken_tts's frankentts.com, franken_manim's WASM renderer, frankentui's /web demo).
