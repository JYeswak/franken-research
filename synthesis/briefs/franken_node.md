## 1. OWN-PACKET DISTILLATION

**Verdict:** NODUS **Explore** [Inference, Medium]. "Explore-with-a-ceiling": substantive-but-unproven, and un-advanceable past Explore while the license rider stands (priced into feasibility 2/5 and collaboration 1/5 on the NODUS factsheet). **TRL 4** — "Lab-validated components (honesty census re-verified live, 146 fuzz targets, conformance harnesses, criterion benches) with zero production exposure, CI red at the pin, and the project's own close-condition oracle RED — component validation in lab, not system validation" [Inference, Medium].

**Strongest strength:** The honesty and evidence-governance machinery — "the most self-scrutinizing pre-1.0 codebase assessed in this program to date" [Inference, Medium]. Zero `unsafe` under `#![forbid(unsafe_code)]` across all three workspace members (independent comment/string-excluding scan: 4 candidates, all string literals) [Counted, High]; a 22-row threat model with explicit out-of-scope non-goals and per-threat regression anchors [Code-verified, High]; a close-condition oracle with conjunctive L1/L2/release-policy gates [Maintainer claim, High]; and the README volunteering its own RED verdicts — "the most benchmark-honest posture in the program" [Inference, Medium].

**Strongest ceiling:** The named-party license rider is the advancement blocker — it bars OpenAI, Anthropic, affiliates, and anyone acting for them from "use" defined to include "copying, …, **benchmarking, testing, analyzing, indexing**, or incorporating the Software … into any dataset, training corpus, evaluation harness, or pipeline" (quoted verbatim; emphasis in packet), with breach "automatically and immediately terminat[ing]" permissions [Code-verified (license text), High]. "A project whose moat is *evidence* forbidding evidence-gathering is self-negating" [Inference, High]. Operationally it sits atop CI red at the pin (all 8 push runs failed [CI-observed, High]) and an L1 oracle RED at 69.82% vs the charter's ≥95% ship floor — the project's own instruments say not shippable.

**The 3 most important pieces of evidence:**
1. The honesty machinery actually runs: `scripts/check_claims_manifest.py --check-honesty` executed against the pinned tree — 9 checks ok, 0 drifted, with live recounts (3,756 → 4,106 integration tests; 21,621 → 22,421 inline; 146/146 fuzz targets; 437 → 438 validators; 0 unsafe blocks) inside tolerance bands [Verified, High]. (Caveat the packet keeps: the Ed25519 signature was not cryptographically re-verified locally; enforcement rests on the SDK conformance test in CI [Maintainer claim, Medium].)
2. The gates are red and the product is self-blocked: GitHub Actions API filtered to the pin's head SHA showed 8/8 push runs `failure` (README CLI Drift ×2, Quick Example Smoke ×2, connector conformance ×2, Native migration validation, Native product oracle) [CI-observed, High]; `artifacts/13/compatibility_corpus_results.json` recomputes to 391/560 = 69.82% while the README's FAQ answers "Is this a drop-in replacement for Node or Bun?" with "No" [Counted + Maintainer claim, High].
3. The rider is disclosed, not hidden: root `Cargo.toml` uses `license = "LicenseRef-MIT-OpenAI-Anthropic-Rider"` with a comment explaining that declaring bare `license = "MIT"` "would misrepresent those terms" [Code-verified, High] — the non-OSI status (fails OSD §5/§6 [Inference, High]) is self-advertised.

## 3. CI/EVIDENCE BAR

What franken_node demonstrates that no other packet does (each verified as franken_node-only by cross-suite grep for "honesty manifest", "close-condition", "trust card", "verifier sdk", "revocation"):

1. **Machine-checkable, Ed25519-signed honesty manifest with a CI drift gate and an independent verifier SDK.** `docs/honesty_manifest.json` (7 headline claims, per-source census, signed corpus digest) + `scripts/check_claims_manifest.py --check-honesty` (run live by the analyst: 9 ok, 0 drift [Verified, High]) + `sdk/verifier` with `honesty_manifest_recompute.rs` enforced in CI. Cousins exist but are weaker on every axis: franken_engine has a 28-claim JSON claim-to-proof matrix that "fails closed when a sentence's wording outruns its evidence" [Code-verified, High] — but its own packet flags it as "self-graded and self-executing… A gate the author holds the only key to is an honesty *signal*, not independent validation" [Inference, High]; franken_lean has the B8 claim matrix with docs-CI rejecting wording stronger than the matrix permits — but its own next-step proposes exporting that apparatus to a *second* repo, i.e. it is not yet a standard [Inference, Medium]; franken_markdown has `claims.tsv` + `check-claim-discipline.sh` wiring claims to `capabilities --json` ("the most rigorous marketing-hygiene mechanism observed in this program" [Inference, Medium] per its packet). None of the 43 signs the census, ships an independent recompute SDK, or was re-verified live by the analyst.
2. **A conjunctive close-condition dual oracle with a stated numeric floor — and the discipline to publish its own RED verdict.** The L1/L2/release-policy conjunctive gate "currently reads RED on its own corpus numbers" (69.82% vs the charter's ≥95% floor) [Maintainer claim, High]; the README FAQ disclaims drop-in status. No other packet has a formalized merge-vs-ship oracle that blocks itself; franken_engine's closest equivalent (its claim-to-proof matrix's 13 OBSERVED rows) "have never been executed by a second party."
3. **A mutation-adequacy floor enforced in CI** (`mutants-gate.yml` enforces `MUTATION_SCORE_FLOOR_BP`) [Code-verified, High] — 14 packets mention "mutation" (franken_alignment's planted-mutation testing, franken_lean's Tribunal, franken_engine's shadow daemon), but none enforces a mutation-score floor as a CI gate.
4. **A 22-row threat model with explicit out-of-scope non-goals and per-threat regression anchors** [Code-verified, High] — the combination of the table, the non-goals list (network DoS, MAC, hardware attestation, app-source provenance), and the anchored regressions is unmatched in the 43.
5. **A documented signing economy: deliberately-unsigned artifacts with stated rationale.** Rollback plans (`--emit-rollback`), `bench run` reports (SHA256 `provenance_hash`, "explicitly not Ed25519-signed," the README says so twice), safe-mode state — unsigned by documented design decision, with the README giving the reason each time [Maintainer claim, High]. ## 6. CROSS-POLLINATION IN

1. **CI-blocking statistical baseline gate → from asupersync → why it fits → ratchet the hot-path budgets.** asupersync's baseline gate is "the strongest *process* in the program": `artifacts/baseline.json`, 105 rows, CI-blocking, "fail above max(5%, ci95 envelope, +0.6ns), no skip-ci waiver" [Maintainer claim, High]. franken_node already has hot-path perf budgets as conformance assertions (`tests/hot_path_perf_budget_contract.rs`) [Maintainer claim, Medium] and a `perf_wins` regression suite — but its benches measure its own primitives against its own budgets with "no external incumbent number, and the maintainer claims none." Port the baseline-gate pattern (committed baseline artifact + statistical fail band + no-waiver policy) onto franken_node's hot-path budget contracts. Payoff: the perf budgets graduate from assertions to an enforced statistical ratchet, and the baseline artifact becomes maintainer-independent evidence a second party can re-run.
2. **Upstream-anchored spec (`anchor:`/`expect=`) with drift-failing CI → from franken_lean → why it fits → handcuff the compat corpus to Node's moving source.** franken_lean's `KERNEL_CONTRACT.md` gives every kernel rule an `anchor:` line naming "the exact upstream file and line at the pin — e.g. `anchor: vendor/lean4-src/src/kernel/type_checker.cpp:289 (infer_type_core) expect="infer_type_core"` — and a conformance test fails CI if the token on that line ever changes" [Code-verified, High]. franken_node's L1 oracle *defines* Node as the compatibility spec; its Wardley analysis notes "every new API is a new corpus campaign the lockstep harness must absorb before the L1 oracle can go GREEN" [Inference, Medium]. Port the anchor mechanism to bind corpus tests to the exact Node source lines they probe. Payoff: spec drift becomes machine-detected before corpus numbers silently rot, directly attacking the 25-point L1 gap.
3. **Registry-invariant test pattern + fixture-wired conformance validators → from franken_agent_detection → why it fits → harden the census against count-rot.** `registry_tables_agree_exactly` "fails the build if the connector registry, tilde-expansion table, canonical-slug map, and factory registry disagree by even one slug" [Code-verified, High] — "the crate's mechanical answer to the drift its own README exhibits." franken_node's honesty census optimizes *countable* things and its own packet warns it is Goodhart-bait (§4.7.9); the validator census already drifted 437→438 "without remark." Add a registry-invariant across the census sources (test attributes ↔ fuzz registry ↔ validator scripts ↔ manifest census) plus fixture-wired validators as an upstream-drift canary for Node version bumps. Payoff: the census detects claim-count rot mechanically instead of relying on the drift gate's tolerance bands alone.
4. **Content-hashed input closure + sidecar manifest → from franken_manim → why it fits → make `.fnbundle` incident bundles portable.** franken_manim's input closure (sources, engine and suite commits, toolchain, config bytes, seeds, font hashes, backend identities, locale) "is the closest thing in this research program to portable, verifiable provenance for a generated artifact — the render-pipeline equivalent of a reproducible build" [Maintainer claim, Medium]. franken_node's incident bundles are signed and integrity-verified but only replay the *recorded* decision sequence; the packet's own next-step 4 proposes binding receipt evidence refs to content hashes. Extend that discipline to the bundle: emit a content-hashed input closure (policy version, trust-state version, corpus/toolchain digests) as a sidecar manifest. Payoff: a bundle becomes independently reproducible forensics, not just verifiable-but-recorded forensics — the verifier SDK gets something it can actually recompute.
5. **`claims.tsv` + claim-discipline script → from franken_markdown → why it fits → stop README-vs-machine drift in a 3,401-line README.** franken_markdown wires "each README claim to a `capabilities --json` key and a proof script — marketing hygiene as CI, a discipline no incumbent practices" (its packet: "the most rigorous marketing-hygiene mechanism observed in this program" [Inference, Medium]). franken_node already has two README-scoped CI gates (the README CLI drift gate is currently *red* at the pin). Port the claims.tsv pattern to bind the README's headline claims (test counts, fuzz counts, unsafe-free, corpus numbers) directly to the honesty-manifest census and CLI JSON outputs. Payoff: the red README-drift gate's failure mode is prevented structurally — marketing can no longer outrun the census, and the gate becomes a wording check rather than a perpetual fire.

## 7. CROSS-POLLINATION OUT

1. **Honesty manifest + live census + drift gate → franken_engine, franken_lean, franken_manim.** Why: franken_engine's 28-claim claim-to-proof matrix is "self-graded and self-executing… a gate the author holds the only key to" [Inference, High] — franken_node's signed census + independent verifier-SDK recompute is exactly the externalization its packet's weakness 6 calls for. franken_lean's own next-step #1 proposes "Port the B8 apparatus … to a second FrankenSuite repo" [Inference, Medium] — franken_node's machinery is the ready-made import, down to the analyst-executable `--check-honesty` pattern. franken_manim already has the parity ledger (2,483 rows) and bit-locked goldens; the manifest would bind the ledger's *census* to a signed attestation. Payoff: the suite's best claim-governance becomes its standard instead of its singleton.
2. **Close-condition dual oracle → franken_manim, franken_pandas/franken_numpy/frankenscipy, franken_engine.** Why: franken_manim's convergence gates G2/G3/G4a/G4b/G5 "remain open" [Maintainer claim, High] with no formalized merge-vs-ship separation; franken_markdown already maintains a ratcheted CommonMark floor (578/652, "floor file matches README — consistent" [Verified, High]) that is the L1-oracle's conceptual cousin but has no release gate on it; franken_engine's production checklist "scores 0 of 9 fully met at the pin" with no gate formalizing what shipping requires. Port the conjunctive L1/L2/release-policy gate pattern with stated numeric floors. Payoff: "shippable" becomes a computed verdict rather than a maintainer judgment, and RED-by-default blocks premature claims.
3. **Mutation-adequacy floor (`MUTATION_SCORE_FLOOR_BP`) in CI → franken_lean, frankenredis, franken_manim.** Why: franken_lean has 7,140 `#[test]` annotations "a declared inventory, not an executed result" with no adequacy measure; frankenredis, the suite's exemplar loop, passed 5 grade-revise rounds on QA — it deserves the hardest test-adequacy bar in the program; franken_manim has 3,312 test occurrences across unit and integration suites [Counted, High]. None enforces an adequacy metric. Payoff: test-count Goodharting (the trap franken_node's own README warns about) becomes detectable across the suite's largest suites.
4. **22-row threat model + regression anchors + explicit out-of-scope non-goals → franken_surveillance_system, franken_engine, franken_remote, franken_drone_geometry_reconstruction.** Why: these are the suite's adversarial-exposure projects — franken_surveillance_system (threat-adjacent domain), franken_engine (already has red-team scenarios + a 10-scenario v2 campaign, but no row-per-threat governance table linking defenses to regression anchors), franken_remote and franken_drone_geometry_reconstruction (networked/actuated systems whose packets carry TRL 3–4 exposure without a formalized threat table). Payoff: threat coverage becomes auditable — each threat has a named regression, and the non-goals list stops scope-creep claims before they're made.
5. **Signing economy (documented rationale for deliberately-unsigned artifacts) → asupersync, franken_manim, frankenredis.** Why: asupersync's evidence machinery (baseline gates, DSR receipts) never states what is *not* signed or why; franken_manim's release process publishes signed checksums yet its v0.3.0 notes had to *reject* a mislabeled artifact ("The manifest records both run identifiers and the rejection") — a signing-economy note would discipline exactly which artifacts carry signature weight and which get content hashes; frankenredis ships 24 signed assets plus `.minisig` sidecars, the program's heaviest signature surface. Payoff: signatures regain meaning — where everything is signed, nothing is attested; the economy pattern keeps signature weight on load-bearing claims.
