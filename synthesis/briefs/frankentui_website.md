## 3. CI/EVIDENCE BAR: what frankentui_website demonstrates that others lack

Honest framing first: on *enforcement* (CI gates), frankentui_website is behind most Rust packets — frankenscipy has "CI Gates G1–G9 concluding success at the pinned commit" [CI-observed, High]; beads-for-frankentui has "57 deploy runs with 0 failures including the pin's" [CI-observed + External, High]; asupersync has a "benchmark-gate culture with an explicit no-skip-CI waiver" [Maintainer claim, High]. ftw has *zero* of that. What it does demonstrate that other packets — specifically the sibling website packets — lack:

1. **A versioned demo manifest binding the demo payload to an upstream source commit.** `public/web/version.json` pins `frankentui_git_sha`, carries per-file sha256 over 20 files, a 209-line `evidence.jsonl` build receipt, `synced_at`, `source_inputs_sha256`, `runner_lock_sha256` [all Code-verified, High]. No other packet's grep footprint includes `version.json` or `evidence.jsonl`. **Who lacks it:** frankensim_website explicitly — its "'same bytes the native build runs' claim has no hash linkage between the vendored `.wasm` and the parent repo's `fs-wasm` crate source" [Code-verified, High]; franken_markdown_website has stale sha256 artifact receipts (re-derivation fails on the gzip leg, receipts two versions old).
2. **Byte-identity verification of cross-repo-vendored assets.** `fetch_assets.ts` vendors the beads viewer from `Dicklesworthstone/beads-for-frankentui`; the packet verified the vendored `viewer.js` is byte-identical to that repo's HEAD (pushed 2026-09-21) [Code-verified, High]. This is evidence-by-procedure (diff, don't trust) where the sibling sites merely vendor.
3. **Deliberate cache-header design as evidence hygiene.** `next.config.ts` serves the WASM payload immutable-cached (1 year) while the *manifest* is `no-store`, with the rationale written in the config comment — caching the manifest would pin a visitor to a stale hash set [Code-verified, High]. The freshest-demo-surface (synced 2026-09-18, four days before the pin) is the only surface where the packet says the maintainer's hygiene is current, and the cache design is why.
4. **Analyst-level live-verification bar applied to the deployed artifact** (methodological, not a repo practice): both hostnames curled HTTP 200, all 8 live routes 200, the disabled `/war-stories` returning the *designed* 404 [all Verified, High]. No other website packet's TL;DR claims a live-verification pass of every route.

2. **`verify:live` production kill-test → origin: franken_markdown_website → why it fits → payoff.** That site's `verify:live` "run against production reports 8 stale assets with the wasm glue matching no committed tree, exit nonzero" [Verified, High] — a production-side freshness check with a failing exit code. ftw already runs Playwright suites locally (`BASE_URL=… bunx playwright test` [Code-verified, High]) but has no CI and no production check; its decay mode is "silent by construction" (§4.11). A `verify:live` pointed at frankentui.com + frankentuiwebsite.vercel.app — checking demo-pin currency, dataset vintage vs `export_meta`, and hero claims vs kernel APIs — **payoff:** turns the packet's six revisit triggers into a runnable gate; the site can no longer fossilize at 200 OK unnoticed.

4. **Public-retraction discipline → origin: frankentui (kernel) → why it fits → payoff.** The kernel carries "a 152-row claims ledger with a proof grammar and **56 public retractions**" [Verified, High]. ftw's packet already notes the site's "negative-evidence culture" (it admits Safari breakage, bloat, no-backend limits [Code-verified, High]) — the missing move is *retracting* the four dead hero stats publicly on the site rather than silently editing them later. **Payoff:** converts the strongest credibility liability into a demonstrated honesty signal, consistent with the site's own voice.
