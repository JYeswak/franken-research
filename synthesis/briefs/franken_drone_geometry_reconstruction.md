## 1. OWN-PACKET DISTILLATION

- **Verdict (one line):** "the most honest pre-reconstruction codebase in the program — a dependency-closed, unsafe-free evidence substrate that documents exactly what it cannot do, frozen mid-ascent at the hardest seam: the jump from audited bundle problems to actual optimized geometry" [Inference, Medium].

- **NODUS ring:** **Explore** [Inference, Medium] — "Substantive-but-unproven is the textbook Explore case"; not Monitor (57k lines of real reference code), not Pilot (no release artifact, nothing ever executed observably).
- **Strongest strength:** the honesty infrastructure — a five-label maturity vocabulary (source-present → production-admitted) with the rule "no lower label implies a higher one," an ~18-item "does not yet claim" list, README-vs-IMPLEMENTATION_STATUS cross-checks, `#![forbid(unsafe_code)]` in all 88 `.rs` files with zero unsafe blocks re-counted independently [Counted, High], and a dependency universe of literally nothing but `std` (Cargo.lock = 30 packages, all `fdgr-*`) [Counted, High]. The packet rates this "best-in-class for the FrankenSuite among packets assessed so far" [Inference, Medium].
- **Strongest ceiling:** the core thesis is untested because the geometry half does not exist — no feature extractor, no five-point solver, no triangulation, no bundle adjustment, no mesh; `WP-018` ("Pose graph and bundle refinement") is open [Maintainer claim, High]. Compounded by the velocity stop (last push 2026-09-04, 18 days silent [External, High]) and CI that has never run green — the sole CI workflow is self-hosted and all 324 observed runs are cancelled, including the run at the pin [External, High]. "A hypothesis with scaffolding, not a system" [Inference, High].
- **The 3 most important pieces of evidence (with tiers):**
  1. **Dependency closure is total and verified** — `Cargo.lock` names exactly the 30 workspace members, zero externals, zero unsafe blocks, `forbid(unsafe_code)` everywhere [Counted, High]. This is what makes the auditability posture checkable rather than aspirational.
  2. **The adjudicators adjudicate only supplied candidates** — `fdgr-relative-pose`'s header states "does not generate pose candidates"; `verify_epipolar_candidates` takes an exact supplied `Vec<EssentialCandidate>` [Code-verified, High]. The design inversion (verifiers before generators) is real in code, not just docs.
  3. **The maintainer's own bar is observably unmet** — the README states "the current exact head has not yet earned a retained full local receipt," and the Actions run at the pin is cancelled [Maintainer claim + External, High]. The project cannot be accused of overselling because it pre-emptively convicts itself.

## 3. CI/EVIDENCE BAR — what FDGR demonstrates that others lack

FDGR is weak on CI execution (Pattern E above — be clear about that). What it demonstrates that others lack is *evidence-governance machinery*:

1. **The five-label maturity vocabulary** (source-present → reference-implemented → publicly-invokable → locally-qualified → production-admitted) with the "no lower label implies a higher one" rule, enforced in IMPLEMENTATION_STATUS §"Maturity vocabulary" [Code-verified, High]. The string "maturity vocabulary" appears in **no other packet** in the suite. Who lacks it: everyone — but the gap is sharpest where it would bite: franken_numpy's G1 badge would have to be re-labeled `locally-qualified(at-2026-09-03)` rather than implying current qualification; frankentui's phantom v0.9.0 could not be labeled `production-admitted`; franken_networkx's PyPI-lagged 0.2.1 vs. GitHub 0.2.2 split would be forced into distinct labels. (Honest caveat: FDGR's ladder is *docs-level*, not CI-enforced. franken_lean has a CI-enforced claim matrix + documentation CI that "rejects wording stronger than the matrix permits" — FDGR has the stronger vocabulary but the weaker enforcement. Section 6 proposes closing that gap.)

2. **Versioned machine-readable policy registries as normative scaffolding:** `registries/slos.toml` (102 lines, 20 SLOs), `registries/tests.toml` (178 lines, 44 test families), `registries/gates.toml` (127 lines, 25 gates with terminal predicates like "no implementation claim exceeds evidence"), `registries/operation_costs.toml` (97 lines) [Counted, High]. Sibling registries exist but are narrower or unexecuted: frankengit has `registries/claims.tsv` (6 claim rows with SHA-256 artifact bindings — genuinely strong, but claims-only); frankengraphdb has `registries/invariants.toml` (20 IDs); **frankenmermaid declares `.ci/quality-gates.toml` but "no workflow file consumes them"** — the direct negative example of what FDGR at least *populates substantively*. Nobody else publishes SLO + test-family + gate + cost registries as a coherent qualification substrate.

3. **The "has not yet earned" receipt doctrine:** the README states the current head "has not yet earned a retained full local receipt" and `scripts/qualify.sh --mode full` is framed as the "local qualification contract" [Maintainer claim, High]. frankenterm has qualification gates but runs them on private hosts ("no public CI"); franken_tts has real receipts and publishes "his flagship optimizer's two death certificates in-tree"; franken_whisper has a "campaign-win doctrine" and publishes failed campaigns as "no admissible verdict." FDGR's distinct move is making the *unmet bar itself* a first-class README statement — a norm no other packet follows as explicitly.

4. **An 18-clause structured non-claims table** (IMPLEMENTATION_STATUS non-claims table + `WP-018` open boundary) [Maintainer claim, High]. franken_code_browser's total README disavowal and franken_manim's present-tense disclaimer are cousins, but FDGR's is a *tabular, located, claim-by-claim* non-claims list rather than a prose disclaimer.

## 4. SHARED HURDLES

- **Bus factor 1 with no succession path.** FDGR: "bus factor 1 (sole author Jeffrey Emanuel...)... no release artifact to fork from, only the tree" [Inference, High]. Suite-wide (see Pattern B). franken_sympy states the mechanism most crisply: "If the maintainer stops, the project freezes at whatever commit the stop happens on." FDGR's bead graph (347 beads, all `open`, zero closed [Counted, High]) makes the freeze *machine-readable*.
- **The rider as advancement blocker.** FDGR: "For a mission framed around *agents* operating drone-evidence pipelines, excluding the two leading agent builders sabotages the stated mission" [Inference, Medium]. frankenterm states the same mechanism most pointedly: the rider "denies all rights to the two leading AI labs — the precise demographic an agent-orchestration tool needs"; franken_whisper: the license bars "the exact audience an agent-era speech stack needs." FDGR is the most self-sabotaging instance because its stated end-user *is* an agent.
- **Velocity-vs-review-depth tension.** FDGR's entire 57k-line tree was built in five days by one hand, with hand-rolled SHA-256, ISO BMFF parsing, fixed-point geometry, and Hamming matching that have "no independent review" and with fuzzing present only in plan docs, never in executable code [Code-verified, High]. franken_engine's packet names the mechanism: "gates scale where reviewers don't, but only the gates that actually run." FDGR's gates (Pattern E) do not run — so neither mechanism (review nor gates) currently constrains the re-derived crypto/parsing/numerics.
- **The asupersync doctrine gap — a suite-shared aspirational-policy pattern.** FDGR: README and AGENTS.md mandate asupersync as "the sole admitted in-process async runtime"; the tree contains zero references [Code-verified, High]. Partially shared: frankensympy's `registries/dependencies.toml` lists "asupersync admission" (its doctrine is also ahead of its code). asupersync itself is the suite's most mature member (Pilot, TRL 6, release artifacts) — the doctrine points at a real runtime, which makes FDGR's gap a concrete next step rather than vapor.
- **Release discipline.** FDGR: no releases, no tags [External, High]. Shared with most of the suite; the failure *mode* varies (FDGR: none at all; frankentui: phantom release notes; franken_networkx: install-path lag; frankenredis: release pinned to an earlier commit).

## 5. GENUINE UNIQUENESS

Only claims where no other packet does the thing (verified by cross-suite grep):

1. **The only photogrammetry/SfM packet in the suite.** The strings "photogrammetry," "SfM," and "bundle adjustment" appear in exactly one packet — this one. The incumbent analysis (COLMAP, OpenDroneMap, Pix4D, SkyeBrowse) is therefore unique content in the cross-suite context. franken_surveillance_system is drone-*adjacent* (cameras, drones) but is a sensor/NVR fabric with no geometry, so the reconstruction lane is FDGR's alone.
2. **The five-label maturity vocabulary as executable doctrine** (see §3.1) — suite-unique string and mechanism.
3. **The two-generation bundle-admission split**: a structural bundle-problem compiler (`fdgr.bundle_problem/1`) *plus* a separate held-out seed-provenance audit (`fdgr.bundle_admission/1`) whose final positive authority is `audited_relative_bundle_problem` [Maintainer claim, High]. franken_surveillance_system has "property-separated held-out evaluation" and franken_whisper has corpus-leakage audits — held-out *evaluation* exists elsewhere, but the *structural-compile vs. admission-audit two-generation split with versioned TSV schemas* (nodes.tsv, pose-edges.tsv, camera-bindings.tsv, landmark-seeds.tsv, bundle-observations.tsv, camera-domains.tsv, seed-provenance.tsv) [Inference, Medium] is unique.
4. **Typed scale authority as a type-level discipline**: `component_edge_scale_unit_nano` as a real code unit string — "neither meters nor a cross-component world frame" enforced in the type vocabulary — plus the invariant "Estimated scale is not permission to emit meters" [Code-verified, High]. No other packet types epistemic authority this way.
5. **Adjudication-before-generation as an explicit design inversion**: verifiers (`verify_epipolar_candidates`, relative-pose adjudicator, bundle-admission audit) built *before* any generators exist, front-loading acceptance criteria [Inference, Medium]. The mirror weakness is acknowledged in-packet ("generation-before-adjudication is how every verifier in history got its thresholds").
6. **The `.inc`-via-`include!` workspace convention** (96 `.inc` files / 30,098 lines vs. 88 `.rs` files at 27,082 lines [Counted, High]) — ".inc" appears in no other packet. A codegen-friendly organizational quirk, consistently applied, unique in the suite.
7. **Hand-rolled ISO BMFF metadata + sample-table inspection (bounded, metadata-only, no decode) as part of a custody chain** — franken_surveillance_system does native HTTP camera recording with "durable original custody," so *custody* is shared (note this), but the bounded container-metadata inspection coupled to a geometry pipeline's custody chain is FDGR's alone.

Explicitly **not** unique (shared, so do not claim as standalone): zero-unsafe + `forbid(unsafe_code)` posture (§2, Pattern F); bus factor 1 (§2, Pattern B); the rider (§2, Pattern A); bead work-graphs (frankengraphdb, franken_pandas, franken_engine, FSS all have bead journals); an "honesty" positioning (franken_manim, franken_code_browser, franken_tts, franken_whisper, frankenlean, franken_nlp, frankenfs all carry some variant).
