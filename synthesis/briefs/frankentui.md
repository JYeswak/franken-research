## 1. OWN-PACKET DISTILLATION

**Verdict.** "FrankenTUI is a **genuinely large, working terminal-UI kernel in safe Rust** [Inference, High] — not a demo repo" — 20 crates, 1,124,747 lines of first-party Rust across 986 files, a real diff-based render pipeline, RAII terminal teardown, first-class inline mode, 87 widget types, 45 demo screens, in-tree web/WASM backends, an 11-target fuzz suite, and a Bayesian/adaptive intelligence layer. **But:** the CHANGELOG's v0.9.0 release (2026-09-18) is phantom — no git tag, no GitHub Release, no crates.io package; GitHub Actions was disabled 2026-09-06 so all verification runs on maintainer-private DSR infrastructure invisible to outsiders; zero independent validation found; API explicitly unstable pre-1.0; MIT+OpenAI/Anthropic-rider license withholds even benchmarking and analysis from the two leading AI labs. "The methodology may outlive the kernel [Inference, Medium]."

**TRL: 6.** **NODUS ring: Explore** — substantive-but-unproven; Pilot requires a bounded real-workload fit (none evidenced) and Invest requires independent validation plus governance (neither exists).

**Strongest strength:** the honesty apparatus — "the evidence machinery is the best in this program": the claims ledger (152 rows, proof grammar, 56 public retractions), five `make gates` checks, the `doctor_frankentui` verification harness, shadow-run lane proofs, machine-readable SLOs, and perf writeups that publish losses. "This is the rare repo where the honesty has a test suite [Verified, High]."

**Strongest ceiling:** governance — "the CHANGELOG describes a v0.9.0 release (2026-09-18) that exists on no surface GitHub tags, GitHub Releases, or crates.io can see [External, High]; GitHub Actions was disabled 2026-09-06 so all verification runs on maintainer-private DSR infrastructure invisible to outsiders [Verified from AGENTS.md, High]; bus factor 1; and the non-OSI MIT+OpenAI/Anthropic-rider license withholds all rights — including benchmarking and analysis — from the two leading AI labs [Verified, High]."

**The 3 most important pieces of evidence:**

1. **The phantom v0.9.0 (disproven release claim).** Claim 16 of the claim inventory: "v0.9.0 released 2026-09-18; 17 crates published to crates.io at 0.9.0" — status **Disproven**. [External, High] — "no v0.9.0 ref of any kind remotely (no tag, branch, or release), no GitHub Release (latest is v0.8.0, 2026-09-14), crates.io max_stable is 0.7.0." This is the single hardest governance fact in the packet and the reason the honesty culture's one lapse is load-bearing.
2. **Zero `unsafe` across 1.12M lines.** Claim 3: "**Demonstrated** ... zero `unsafe {`/`fn`/`impl`/`trait`/`extern` constructs and zero `#[unsafe(` attributes in 986 files; 8 `unsafe`-word hits are identifiers in safe code (e.g. `unsafe_codes.sort()`, `unsafe_snapshot.disposition`), individually classified" [Verified, High]. Portable SIMD is done in safe `std::simd` (nightly `portable_simd`) with scalar twins for parity testing. (Cross-packet caveat: the frankenmermaid packet also claims "the strongest unsafe posture in this program" for its 258k-line census — see §5 for the superlative conflict.)
3. **The claims ledger + gates (the evidence machinery).** Claim 20: "Claims ledger: 152 rows (37 C + 71 V + 39 S + 5 N) with proof grammar, `make claims` enforcement" — "**Demonstrated**" [Verified, High] — "56 proven / 56 retracted / 34 pending-doc / 6 pending-code." Plus five `make gates` checks (module reachability, claims proofs, env-var docs, close-audits of beads, baseline benches), the 194,840-line `doctor_frankentui` harness (larger than the runtime it verifies, 156,975 lines), `ShadowRun::compare()` for cross-lane determinism, and machine-readable frame budgets in `slo.yaml` [all Verified, High]. The open loop: the budgets are public but measurements against them are not — "loop closure happens inside DSR, invisible to outsiders [Verified, High]."

## 2. SHARED NEGATIVE PATTERNS

Patterns frankentui shares with other packets, with the sharing evidence.

- **Pattern:** named-party discrimination + use restriction (including benchmarking and analysis) making the license NOT OSI open source, positioned as an advancement blocker/ceiling across the suite.
- **Other projects:** all 44 packets mention the rider; the "rider as advancement blocker / Explore-with-a-ceiling" framing appears in franken_code_browser ("The rider is an advancement blocker (Explore-with-a-ceiling), not a ring qualifier"), franken_engine ("the rider blocks the likeliest collaborators"), franken_networkx ("the rider is an advancement blocker"), franken_node, franken_numpy ("unauditable-by-license for the likeliest evaluators"), franken_graphdb, franken_jax, franken_pandas ("rider + no-contributions policy form a double ceiling"), franken_torch ("the software is currently un-advanceable while the rider stands"), frankenscipy, frankensearch, franken_snowflake, frankenterm, frankenredis, and more.

- **Sharpest sibling quote:** frankenlibc on the same strategy — "the current rider reads as strategy written against phantoms at the expense of real counterparties. [Legal interpretation is the assessor's inference, not legal advice.]"

## 3. CI/EVIDENCE BAR — what frankentui demonstrates that others lack

Important context first: the *idea* of the evidence apparatus is shared — 22 packets mention a negative-evidence ledger (frankenfs's 20,556-line ledger, frankenpandas's 44,086-line ledger, frankenlibc's 41,205-line ledger, frankentorch's 42,708-line failure ledger, frankenmermaid's 726-row perf ledger), and retractions appear in franken_overlap, franken_snowflake, franken_tts (NE-006), frankenlibc, frankenpandas, frankentorch. What follows is genuinely not found in any other packet (verified by suite-wide grep).

1. **Proof-grammar claims ledger + `make claims` schema validator.** No other packet describes a claim-governance protocol with a formal proof grammar (`test:`/`path:`/`ident:`/`cmd:`/`count:`/`manual:`) and a machine-enforced schema validator. Frankengit has a "machine-checked claims registry" that "automatically demotes its own verified rows the moment a required artifact's digest no longer matches" (6 verified rows) — the closest relative — but no other packet shows a proof grammar. Frankentui's ledger is the largest formal one: 152 rows, 56 proven / 56 retracted / 34 pending-doc / 6 pending-code [Verified, High].
2. **`make claims` failing README experimental sections without a "Where it runs" line.** No other packet ("Where it runs" matched only frankentui) enforces honesty on *documentation* claims about experimental code via CI: the ledger's first act was a 2026-09-19 audit that retracted eleven README experimental sections because zero crates imported them, then required "Where it runs" lines [Verified, High].
3. **`slo.yaml` — machine-readable frame budgets enforced by gates.** No other packet mentions `slo.yaml` or machine-readable *frame-performance* budgets. ("Machine-readable" in other packets refers to work packets, contracts, or attestations — e.g. franken_alignment's 143 machine-readable work packets, frankensqlite's machine-readable contracts — never perf budgets.) `make gates` includes the baseline-benches check against them [Verified, High]. Open loop noted honestly: budgets are public, measurements are not — "loop closure happens inside DSR, invisible to outsiders."
4. **`scripts/bench_budget.sh` "missing evidence fails" semantics.** No other packet describes budget enforcement where absence of measurement is itself a failure: "exit 0 = every selected budget measured *and* met" [Verified, High]. Other suites have bench gates (franken_networkx's scripts/ benchmark-gate entry points, frankengit 78 CI workflows) but none with the missing-evidence-fails property.
5. **Close-audit gate on issue-tracker closures.** No other packet has one: `make close-audit` "rejects bead closures without 80+ character evidence-bearing reasons" (the beads issue tracker had 188 of 2,900 historical closes with no reason at all) [Verified from AGENTS.md, High].
6. **Shadow-run lane-migration proofs (`ShadowRun::compare()`).** No other packet has cross-lane determinism validation: the runtime has three execution lanes (Legacy/Structured/Asupersync) and `shadow_run.rs` + `rollout_scorecard.rs` + `rollout_runbook.rs` in `ftui-harness` exist to prove rendering determinism across migrations [Verified files exist, High; results not executed].
7. **`doctor_frankentui`: a verification harness larger than the system it verifies.** 194,840 lines — bigger than the runtime (156,975) — with capture, determinism soaks, chaos drills, CEGIS, concolic differential testing [Verified, High]. No other packet describes a standalone verification crate of this scale relative to its target.

**Honest caveat on §3:** several of these are *existence* claims (verified files exist) whose *behavior* the analyst did not execute ("did not compile the workspace, run any test, bench, or binary... all behavioral and performance claims rest on maintainer evidence" — §4.12). And the retraction/honesty *culture* is genuinely shared with the suite's other honesty-exemplars (franken_ocr's "measured parity receipts, published losses"; franken_torch's publicly retracted headline SDPA win; frankenlibc's ledger judged by its own analyst "the strongest measurement discipline observed in the program so far [Inference, High]" — a superlative that conflicts with frankentui's own "the evidence machinery is the best in this program").

## 7. CROSS-POLLINATION OUT — frankentui concepts to export to named other projects

**Concept → target project(s) → why it fits them → expected payoff**

1. **The claims-ledger proof grammar + `make claims` → frankengit, franken_node.** FrankenGit already has a "machine-checked claims registry (6 verified claim rows)" that auto-demotes rows on digest mismatch — the closest relative — but its 589,340-line, 49-crate surface would benefit from frankentui's formal proof grammar (`test:`/`path:`/`ident:`/`cmd:`/`count:`/`manual:`) and retraction statuses; franken_node's packet names "the honesty and evidence-governance machinery" as its methodology exemplar but the packet describes no formal grammar. **Payoff:** both projects' honesty machinery moves from maintained discipline to machine-checked protocol; frankengit's revision-bound reality check gets a proof vocabulary.

2. **"Where it runs" enforced experimental-section honesty → franken_remote, franken_alignment, franken_surveillance_system.** Frankentui's 2026-09-19 audit retracted eleven README experimental sections because zero crates imported them, then gated "Where it runs" lines via `make claims` [Verified, High]. Franken_remote and franken_alignment are plan-stage/substantive projects where READMEs describe experimental modules; the rule gives them a portable mechanism to keep documentation claims checkable. **Payoff:** prevents the exact drift pattern (documented-but-unwired experimental modules) that frankentui's own audit caught — at projects too early to need full claims ledgers.

3. **`bench_budget.sh` "missing evidence fails" semantics → frankenpandas, frankenscipy.** Frankenpandas documents the failure mode: "216 lanes never cleared the certification gate (74 undecidable, 62 dropped on variance) [Code-verified, High]" — measurement gaps are tolerated as documentation.
