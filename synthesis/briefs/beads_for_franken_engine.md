# Cross-Suite Brief: beads_for_franken_engine

Analyst note: this brief is grounded in the pinned-commit assessment packet
(`~/workspace/franken-research/beads_for_franken_engine-assessment.md`, assessed
2026-09-22) and a skim of the other 43 packets (TL;DR, claim inventory, verdict/TRL/
NODUS ring, benchmark/limitation/license sections). Evidence-tier labels below are
the packet's own ([Counted], [Verified], [Code-verified], [Git-observed],
[CI-observed], [External], [Maintainer claim], [Inference] + confidence).

## 1. OWN-PACKET DISTILLATION

- **Verdict:** a faithful, carefully engineered, offline-first static export of
  FrankenEngine's beads issue-tracker journal (generated by `bv --pages`) that is
  now a museum piece — "a 22 MB time capsule (excluding .git) with exactly one
  commit" whose headline calls it a live dashboard while its data says March 2026.
- **TRL:** 7 — "Deployed static system serving on GitHub Pages (both deploy runs
  green at the pin); content frozen 197 days" [Inference, Medium]. Not 8: never
  validated *as a live tracker* (its headline claim), and in-browser hydration
  untested.
- **NODUS ring:** Monitor [Inference, High]. The Rulebook names Monitor for
  "websites, retired artifacts, and plan-stage work" — this is the first two at
  once. "The export *pattern* … is the methodology worth stealing; this instance
  is a museum piece."
- **Strongest strength:** data fidelity of the export. "Every headline count
  reproduces exactly from the shipped sqlite (1,180 / 853 closed / 1,916 deps
  [Counted, High]); the 8 chunks reassemble byte-exact to the committed sqlite
  (sha256 match across all three [Verified, High]); the dependency graph is
  genuinely acyclic (independent DFS over all edges [Counted, High]); the FTS
  index answers queries; the hybrid scorer's self-test passes under node; the
  bundle is offline-first with 5.3 MB of vendored libraries and a COOP/COEP
  service worker for WASM threads."
- **Strongest ceiling:** it is a fossil wearing a live dashboard's headline.
  "One commit, last pushed 2026-03-09; data 197 days stale [Counted, High];
  all 1,180 tracked issues closed in the live journal, which has grown to 4,537
  beads — the dashboard covers 26% of a journal that moved on [Verified, High]."
  Plus: the README's "264 blocked / 63 ready" "reproduces under no definition
  from the shipped DB," there is no LICENSE file, and there is no regeneration
  path (no script, no CI job, no recorded `bv` version).
- **Three most important pieces of evidence:**
  1. All 1,180 snapshot IDs resolve in franken_engine's live `.beads/issues.jsonl`
     (4,537 records, 2026-09-22 sparse clone) and all 1,180 are `closed` —
     the "Did You Know" that kills the live-dashboard thesis [Verified, High].
  2. README 264/63 blocked/ready vs 251/76 (unmet-dependency recomputation) vs
     286/41 (the DB's own `issue_metrics`) — and the identical +13 offset on both
     sides in sibling journal `beads-for-frankentui` (157/47 vs 144/60),
     proving the defect is a *systematic definitional delta in `bv`'s triage
     computation*, not drift [Counted, High on the numbers; Inference, Medium on
     the generator-level reading].
  3. The 2026-09-21 fleet batch commit: three sibling dashboards received an
     identical *formatting-only* commit (verified via API on all three), data
     still March-frozen everywhere; this repo — single March commit, stalest push
     of the 8-repo fleet — missed even the style pass [External, High]. "The
     maintainer maintains the fleet's code, not its data."

## 3. CI/EVIDENCE BAR

What beads_for_franken_engine's packet demonstrates that other packets lack
(or do less of):

- **Independent reproduction of headline counts from the shipped artifact.**
  The analyst ran `SELECT count(*)` against the shipped `beads.sqlite3`
  (1,180 / 853 closed / 1,916 deps / 900 comments), re-ran chunk concatenation
  with sha256 against the manifest, ran an independent Python DFS over all
  1,916 dependency edges (no cycles), and probed the FTS index (`MATCH
  'cranelift'` → 1 row) — all [Counted/Verified, High]. Most engine packets
  verify claims against code or maintainer-run ledgers; beads re-derived the
  artifact's load-bearing numbers from the artifact itself. The sister
  (beads-for-frankentui) did the same class of work (11/11 chunk hashes
  re-verified), so the bar is *shared across the two dashboard packets* — it is
  the engine packets (ledgers, bench tables) that mostly lack in-packet
  independent recomputation.
- **Ground-truthing against an external source.** All 1,180 snapshot IDs were
  intersected against a 2026-09-22 sparse clone of franken_engine's live
  `.beads/issues.jsonl` (4,537 records): all present, all closed [Verified,
  High]. No other packet observed cross-validates its subject's data against a
  live external corpus at ID level.
- **Cross-instance replication to upgrade a finding from drift to systematic.**
  The analyst cloned sibling `beads-for-frankentui` and recomputed its
  README numbers (157/47 vs 144/60) to show the identical +13 offset on both
  sides — "ruling out percentage-based definitions and pointing to a fixed
  reclassified set" — converting a one-repo anomaly into a generator-level
  defect [Counted, High]. No other packet was observed replicating its key
  quantitative finding against a sibling instance.
- **Fleet-level commit analysis via API.** The 2026-09-21 style batch was
  verified commit-by-commit on all three sibling dashboards, plus a sampled
  sibling's `export_meta.generated_at` (2026-03-08) and max `updated_at`
  (2026-03-06), to prove the batch was formatting-only fleet-wide [External +
  Code-verified, High].
- **Executing the shipped self-test rather than citing it.**
  `hybrid_scorer.test.js` was run under node with a `window` shim — "HybridScorer
  tests passed" [Verified, High] — where CI never runs it. (The sister packet's
  analyst did the equivalent for its self-test [Verified, Medium]; engine
  packets generally cite CI or maintainer-run gates instead.)
- **Observable, falsifiable revisit triggers.** Seven triggers ("a second commit
  lands — `git log` count > 1"; "a LICENSE file appears"; "`export_meta`
  generated_at advances past March 2026"; "the README's 264/63 is corrected or
  reproduced") — each naming the exact observation that flips a judgment.
  Several engine packets have revisit triggers, but beads's set is the tightest
  trigger-to-judgment mapping of the Monitor-ring group.

What beads conspicuously does NOT have (the bar it fails): no CI job that
verifies anything, no recorded generator version (`export_meta` has no
`bv_version` key), the live site was "shell renders; full hydration untested" —
the WASM graph init, chunk reassembly in-browser, and time-travel animation are
[Code-verified, High] existence, never executed.

## 4. SHARED HURDLES

Structural issues beads shares with other projects, with evidence:

- **Bus factor 1 / no succession.** One commit, one author
  (Dicklesworthstone <email redacted> [Git-observed, High]); "There is no
  one to page when the Pages deploy breaks." Same across the suite (§2.5 above).
- **License-rider ecosystem friction.** Every engine packet names the MIT +
  OpenAI/Anthropic rider as an advancement blocker ("Explore-with-a-ceiling,"
  franken_engine; "withholds even *benchmarking and analysis* rights,"
  franken_markdown). Beads's variant is worse in one way and neutral in
  another: worse because it ships *no* license while redistributing rider-bound
  code; neutral because nothing in it is benchmark-worthy anyway ("zero
  performance claims … grep-verified [Code-verified, High]").
- **No regeneration path; manual/cadence-less refresh.** "No script, no
  Makefile, no CI job, no recorded `bv` version" [Code-verified, High].
  Shared with the sister dashboard — where `bv --watch-export` "already exists
  in the tool — the missing piece is only someone (or something) running it on
  a schedule" [External, High on the interface] — and
  **franken_markdown_website** ("production lags the pin (manual deploys)").
- **Velocity-vs-refresh asymmetry at fleet scale.** The maintainer is highly
  active in the *tool* (`bv` pushed 2026-09-22, 1,691 stars) and the *upstream
  project* (franken_engine pushed 2026-09-21T01:29Z, hours before the dashboard
  style batch) — while the *artifact* sits at one March commit [External,
  High]. The suite-wide analogue: extreme tool velocity (frankenmermaid
  "~3,282 commits in ~7 months", franken_snowflake/franken_lean velocity)
  coexisting with frozen or drifting *published surfaces* (stale READMEs,
  drifting badges, unrefreshed sites). The hurdle is not low velocity — it is
  velocity pointed at code while the published artifact rots.
- **Lossy export / provenance gaps.** The sqlite drops upstream journal fields
  (`created_by`, `close_reason`, `acceptance_criteria` — "the export is a
  *projection*, not a full dump" [Code-verified, High]); `export_meta` records
  no generator version, no source-journal head hash, no signature over the chunk
  manifest ("portable attestation would require … the manifest already hashes
  every chunk, so signing it is a small step the pipeline never took"
  [Inference, Medium]). The suite-wide analogue is the provenance weakness
  other packets flag (franken_threed: "provenance is opaque to outside
  reviewers"; frankenredis's signed 24-asset release at an *earlier* commit
  than the pin — signatures detached from the assessed artifact).

## 5. GENUINE UNIQUENESS

Only things no other packet does — verified against the full 44-packet read:

1. **The only dashboard instance that still ships the time-travel
   bead-archaeology view.** Beads: `data/history.json` (48 commits with
   `beads_added` lists) + `graph.js` L3236 "TIME-TRAVEL ANIMATION (bv-z38b)"
   [Code-verified, High]. The sister packet (beads-for-frankentui) documents
   the opposite: `data/history.json` "remains absent (removed in second
   deployment)" — a time-travel feature silently dropped, documented
   [Maintainer claim, High]. No other packet ships a commit→issues replay view
   at all.
2. **The only 100%-closed journal snapshot in the suite — a complete labeled
   dataset.** "All 1,180 issues on this 'Live Dashboard' are closed in
   FrankenEngine's live journal today — and the journal has grown to 4,537
   beads since the export" [Verified, High]. Every other dashboard/journal
   packet tracks live or partially open work (frankentui's 2,590-issue journal
   is still shipping; franken_engine's journal has 626 open). This makes beads
   the *only* packet proposing a true backtest: "Compute the rank correlation
   between the March triage scores (`triage_recommendations.score`) and the
   actual close order" with all outcomes known (next-step 1), and the
   bottleneck-precision study (next-step 5). The "labeled backtesting dataset"
   concept appears in no other packet's next steps.
3. **The only cross-instance definitional replication.** The +13 systematic
   offset proof (README 264/63 vs recomputed 251/76 vs 286/41, replicated as
   157/47 vs 144/60 in the sibling journal, both sides) [Counted, High] is the
   only packet that re-ran its key quantitative finding against a *sibling
   instance* to distinguish generator defect from drift. Engine packets
   replicate against incumbents (whisper.cpp, Redis 7.2.4 oracle); none
   replicate a headline-number failure against a sibling output of the same
   generator.
4. **Benchmark honesty by absence.** "The repo makes **zero** performance claims
   — a grep over all non-vendor text finds only a 'faster settling'
   layout-animation comment [Code-verified, High]. There is no benchmark table
   to audit." In a suite where every engine packet maintains a bench/perf
   ledger and most carry disputed headline numbers, beads is the only packet
   whose strongest quantitative statement is a verified null — and whose
   numbers-that-hold are counts and hashes rather than speedups.
5. **The only packet whose kill test has already run.** "The single experiment
   that falsifies the core thesis — 'a static export is a useful live project
   dashboard' — has already run: compare the export against the live journal…
   The thesis is falsified by the artifact's own data, not by a critic
   [Verified, High]." Other packets hypothesize kill tests; beads's ran
   itself, leaving a clean surviving thesis ("a static export is a useful
   *frozen* dataset") with its own stated kill test (regenerate with current
   `bv`; if triage numbers still don't recompute, the generator's analytics
   are unsound).
6. **Fleet-canary position.** The oldest push of the 8-repo dashboard fleet and
   "one of three members still on a single commit" — and the only member
   skipped by the 2026-09-21 style batch despite the maintainer being active in
   franken_engine that same morning [External, High]. The sister packets were
   *touched*; this one is the fleet's neglected tail, which is what makes the
   "maintains the fleet's code, not its data" finding load-bearing rather than
   anecdotal.

Shared, so NOT claimed as unique: the hash-manifested chunked-sqlite export
bundle (identical in beads-for-frankentui: "eleven 1 MB binary chunks …
SHA-256 integrity checks … hashes the analyst re-verified 11/11"), the
offline-first vendored stack, the COOP/COEP service worker, and the Monitor
ring itself (shared with all five website packets: frankentui_website,
frankensqlite_website, frankensim_website, franken_markdown_website,
beads-for-frankentui).

## 6. CROSS-POLLINATION IN

Concepts from other packets that should be applied to beads_for_franken_engine:

1. **Claim-discipline gate (`claims.tsv` + `check-claim-discipline.sh`)** →
   origin: **franken_markdown** ("`claims.tsv` + `check-claim-discipline.sh`
   wire each README claim to a `capabilities --json` key and a proof script —
   marketing hygiene as CI, a discipline no incumbent practices" [Verified,
   High]). Why it fits: beads's sharpest finding is exactly a claim without a
   proof — the README's 264/63 "reproduces under no definition from the shipped
   DB" [Counted, High]. Expected payoff: wire each README headline number to a
   committed SQL query as its proof script; the gate fails when the triage
   definition drifts again. This is the packet's own next-step 4 ("a SQL query
   in the repo reproduces the headline numbers byte-for-byte"), upgraded from
   a manual query to CI-enforced discipline.
2. **Claim-coverage audit** → origin: **frankenmermaid** ("a claim-coverage audit
   admitting 96.4% of its own performance claims carry no same-invocation
   incumbent ratio"; "225 KEEP claims, 8 with a live incumbent ratio")
   [Counted, High]; also **franken_networkx** ("CLAIM_COVERAGE_AUDIT … 579 of
   591 KEEP rows carry no vs-incumbent ratio"). Why it fits: beads's triage
   scores are "demonstrated (as generated values)" but "the *meaning* of the
   scores is unvalidated — no ground truth exists in-repo" [Counted, High].
   Expected payoff: a coverage audit over the 10 `triage_recommendations` rows
   and the impact scores (validated vs heuristic vs decorative) converts the
   "Top Priorities" panel from decoration to an audited heuristic — and feeds
   directly into the backtest (next-step 1).
3. **`verify:live` deploy verification** → origin: **franken_markdown_website**
   ("a `verify:live` script that sha256-compares every production asset"
   [Code-verified, High]; the packet's methodology-fit names it "directly
   importable"). Why it fits: beads's live site was "shell renders; full
   hydration untested," with a CDN fallback the "fully self-contained" framing
   doesn't admit [Code-verified, High]; and any scheduled regeneration (next-
   step 2) needs proof the deploy actually refreshed the data. Expected payoff:
   a post-deploy check that the served chunks match the committed manifest —
   and that `export_meta.generated_at` advanced — closes both the hydration
   gap and the fossil-serving failure mode with one script.
4. **Negative-evidence ledger for the backtest** → origin: **franken_whisper**
   ("a 26,846-line negative-evidence ledger … a maintainer who records his
   losses (the failed A/A-null campaign is published as 'no admissible
   verdict,' not buried)"); **frankengit** ("a machine-checked claims registry …
   that automatically demotes its own verified rows the moment a required
   artifact's digest no longer matches"). Why it fits: beads's next-step 1
   backtest is *falsifiable by design* ("the scores show no correlation with
   close order, which converts the 'Top Priorities' panel from analytics to
   decoration"). Expected payoff: recording the backtest outcome —
   *including* a no-signal result — as ledger rows (whisper style) or
   auto-demoting triage rows (frankengit style) gives the fossil's analytics
   panels a documented verdict instead of silent decoration.
5. **Honest-status / historical labeling** → origin: **asupersync**
   ("honest-status tables" as exportable methodology [Maintainer claim, High]);
   **frankentui_website** ("labeled as historical on the site [Verified,
   High]" — old claims explicitly marked); **franken_native_capsule**
   ("bring-up disavowal convention … directly importable"). Why it fits:
   beads's [FATAL] finding is literally "Live Dashboard is false advertising
   the data itself refutes" [Verified, High]. Expected payoff: replace the
   "Live Dashboard" headline with an honest-status strip ("snapshot of March
   2026; all 1,180 issues now closed; upstream journal at 4,537 beads") —
   one edit that retires the packet's single fatal weakness without touching
   the artifact.

## 7. CROSS-POLLINATION OUT

Concepts from beads_for_franken_engine that should be exported to named other
projects:

1. **The export bundle format (sqlite + `export_meta` provenance + hash-
   manifested 1 MB chunks + sql-wasm loader) as a portable evidence artifact**
   → targets: **frankenredis** (its "499 MB / 127,571-file benchmark evidence
   pack" and "26,485-line negative-evidence log" are currently loose files),
   **franken_whisper** (5,567-line performance ledger + 26,846-line negative-
   evidence ledger as giant markdown), **frankenmermaid** / **franken_networkx**
   (claim-coverage audits), **frankentorch** ("provenance-complete evidence").
   Why it fits them: every one of these packets maintains its evidence as
   text files that are greppable but not *queryable*; beads demonstrates the
   recipe for publishing a dataset as an offline-first, zero-backend,
   hash-verified sqlite anyone can download, diff, and query without repo
   access [Inference, Medium — the packet's own §4.9 methodology-fit:
   "the export bundle format … is a directly importable template for
   publishing any repo's evidence as a portable, checkable artifact"].
   Expected payoff: ledgers become downloadable evidence databases with
   integrity manifests instead of 26,000-line markdown files.
2. **The triage-backtest design (closed journal = labeled dataset; rank-
   correlation of triage scores vs actual close order; bottleneck precision)**
   → targets: **franken_engine** (its 4,537-bead journal, 3,911 closed / 626
   open [Counted, High] — a 3.8× larger labeled corpus for validating `bv`'s
   impact heuristic), **beads-for-frankentui** (2,590-issue journal via the
   sibling dashboard). Why it fits: the backtest machinery only needs
   `triage_recommendations.score` + `closed_at` timestamps, which every
   `bv --pages` export ships. Expected payoff: the first empirical validation
   (or refutation) of `bv`'s triage analytics across three independent
   journals — the "no ground truth" gap the packet flags becomes a solved
   problem suite-wide.
3. **`hybrid_scorer.js` as a drop-in graph-aware ranking function** → targets:
   **frankengraphdb** (graph database with no demonstrated ranking consumer),
   **franken_networkx** (the graph library whose KEEP rows lack incumbent
   ratios — ranking is its native lane), **franken_code_browser** (code search
   over 10-day-old repo; ranking by PageRank+recency is directly applicable).
   Why it fits: "88 lines, self-tested, no dependencies beyond `window`"
   [Code-verified, High], with documented normalization weights (text 0.40,
   pagerank 0.20, status 0.15, impact 0.10, priority 0.10, recency 0.05) and a
   passing self-test the analyst executed [Verified, High]. Expected payoff:
   a zero-integration-cost graph-aware ranker for any issue/code list in the
   suite — the packet's own "cheapest embeddable unit" (§4.12 deepening Q2).
4. **Time-travel bead-archaeology view (commit→beads animation over
   `data/history.json`)** → targets: **beads-for-frankentui** (explicitly
   dropped it: "`data/history.json` 'remains absent (removed in second
   deployment)'" — the packet documents the removal as a regression),
   **franken_engine** / **frankentui** (live journals whose history would make
   the replay view genuinely useful rather than fossil-bound). Why it fits:
   beads is the only fleet member that kept the feature working
   [Code-verified, High], so the implementation reference exists in-tree.
   Expected payoff: restores the one analytics view no incumbent offers
   ("GitHub has no 'replay the project's March' view" [Inference, Medium]) to
   the sibling that lost it.
5. **Fleet-as-a-unit maintenance discipline (batch commits + fleet-wide
   freshness checks)** → targets: the program itself and the other Monitor-ring
   websites (**frankensqlite_website**, **frankensim_website**,
   **franken_markdown_website**, **frankentui_website**). Why it fits: beads's
   packet proves the maintainer "operates these dashboards as a fleet — code,
   not data" [External, High], and the frankentui packet shows `bv
   --watch-export` "already exists in the tool — the missing piece is only
   someone (or something) running it on a schedule." Expected payoff: one
   scheduled fleet-wide re-export job (the packet's next-step 2, generalized)
   retires the defining weakness of the entire dashboard/website cohort at
   once — stale published surfaces — instead of fixing them one fossil at a
   time.
