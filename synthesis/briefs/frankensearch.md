## 1. OWN-PACKET DISTILLATION

- **Verdict (one paragraph, §4.12):** frankensearch is an 883k-line bet that search infrastructure should be progressive (answer in milliseconds, refine within budget), receipted (every number bound to a git revision, a host, and a load average), and adversarially honest (a gauntlet that grades its own engine against the incumbent it replaced, a ledger of reverted experiments, a public correction when it oversold its own hash embedder). On instrumentation it is the best in the FrankenSuite. But the product case is half-built at the pin: ranking quality is unmeasured by the maintainer's own admission, `main` was reported uncompilable a day before this assessment and couldn't be re-verified, one human is the entire bus factor, and the license forbids the AI labs whose agents are the likeliest users of its agent-friendly CLI. **Explore the methodology; the software stays behind the rider's ceiling.** [Inference, Medium]
- **TRL:** 5–6 [Inference, Medium] — receipted latency on real models and hardware, multi-platform release binaries, 13-member crates.io family, but relevance quality unmeasured and compile state unverified.
- **NODUS ring:** **Explore** [Inference, Medium] — "Explore-with-a-ceiling": substantive-but-unproven, currently un-advanceable past Explore while the rider stands and no relevance receipt exists. The rider is instrumented as the advancement blocker (feasibility 3/5, collaboration 1/5, wired to revisit trigger 3).
- **Strongest strength:** the receipt machinery — "the best benchmark-instrumentation culture in the program" [Verified, High] (§4.7 S1): machine-readable JSON binding git revision, hostname, load average, model identities, corpus description, and percentiles, corroborated against the README table to the decimal, plus the SELF-SPEEDUP/INCUMBENT comparison-class policy enforced in the 19,201-line negative-evidence ledger [Counted + Code-verified, High].
- **Strongest ceiling:** the rider as advancement blocker — "the rider doesn't just shrink the contributor pool — it names the target user as forbidden" [Inference, Medium] (§4.8) — compounded by the unmeasured relevance gap: "even with the rider gone, a search engine with unmeasured relevance is un-adoptable" (§4.11).
- **The 3 most important pieces of evidence:**
  1. Committed latency receipt `library-two-tier-latency-20260903-thinkstation1.json`: initial p50 0.395 ms, phase-2 p50 5.11 ms, with revision + host + loadavg recorded, corroborating the README to the decimal [Verified, High] (claim 1, §4.3).
  2. `docs/NEGATIVE_EVIDENCE.md` — 19,201 lines with the explicit policy that in-repo before/after numbers are `SELF-SPEEDUP` (maintenance, not wins) and only a named live incumbent run side-by-side in the same invocation is an `INCUMBENT` comparison [Counted + Code-verified, High] (claim in §4.5 item 3).
  3. `docs/SEARCH_QUALITY_FINDINGS.md` standing disavowal: "These Python results do not certify Quill quality"; "real-model phase delivery is necessary but does not establish a relevance improvement" [Maintainer claim, High] (claim 14, §4.3) — simultaneously the strongest honesty evidence and the load-bearing product gap.
  - Honorable mention: v1.6.0 changelog, verbatim — "Hash control no longer presented as semantic search" [Maintainer claim, High] (claim 13).

## 3. CI/EVIDENCE BAR: what frankensearch demonstrates that others lack

Honest framing first: almost every individual mechanism has a peer. What frankensearch does that has **no observed peer**:

- **Per-row evidence-basis labeling of every performance number.** The README's "Baseline Performance Envelope" labels every row's basis — *ledger*, *receipt*, *product receipt*, *target* — and says explicitly that rows marked *target* "have no committed measurement" [Maintainer claim, High] (§4.5 item 2). No other packet describes this discipline; the closest peers are structural cousins, not equivalents: franken_engine's 28-claim JSON ledger gating README wording in CI [Code-verified, High] is stronger on enforcement but operates at claim granularity, not per-benchmark-row; franken_whisper's result-class doctrine (maintenance vs INCUMBENT-WIN) classifies *campaigns*, not individual table rows.
- **The most complete *performance* receipt schema observed.** One JSON binds git revision, hostname, load average, model identities, corpus description, and percentiles — and the analyst corroborated the README against it to the decimal [Verified, High] (claim 1). Peers cover subsets: franken_markdown's `perf-gauntlet.sh` is "measurement-first (release-perf profile with frame pointers, host/build fingerprint, in-process library scenarios, hyperfine CLI baselines, optional Linux perf counters, golden checksums, a hypothesis ledger)" but binds build/host, not model identities + loadavg + percentiles per receipt; franken_whisper's PERF_LEDGER rows carry "SHA-256 identities for both ELFs, A/A nulls in [0.98, 1.02], full host provenance… and WER-gated transcript equivalence" but in ledger rows, not revision+loadavg+model-bound receipt JSON; franken_snowflake's receipts are "BLAKE3 content-addressed receipts with an append-only audit log" [Verified in code, High] — execution receipts, not benchmark receipts. frankensearch is the only packet where the performance receipt is the *unit of account* for the whole performance story.
- **Content-addressed differential-conformance certificates for a replaced incumbent** (`frankensearch/quill-gauntlet/cutoff-certificate/v1`, SHA-256 domain-separated) [Code-verified, High] (§5.1). Closest peers: franken_ocr's "Phase −1 'truth pack' pinning the exact model source commit and fixture hashes" [Verified, High], and franken_networkx's "ELF-hash pinning" plus "byte-identity-before-timing" [Maintainer claim, High]. Neither binds a *same-snapshot cutoff* between a replacement engine and its oracle as a checkable certificate format.

What frankensearch does at **top-tier level but not alone**: the negative-evidence ledger (19,201 lines — mid-range; franken_torch has 42,708 [Counted + Maintainer claim, High], franken_networkx 37,116 [Counted, High], franken_numpy a 67k-line ledger of its own failures, franken_whisper 26,846); the SELF-SPEEDUP/INCUMBENT comparison classes (shared with franken_networkx's "enforced INCUMBENT-vs-SELF-SPEEDUP verdict contract" [Counted, High] and franken_whisper's campaign-win doctrine); one-command receipt regeneration (`QUALITY_GATE_STAGES=perf scripts/quality-gate.sh` regenerates receipts — peer: franken_markdown's `perf-gauntlet.sh` + `perf-compare.sh`).

## 5. GENUINE UNIQUENESS

Only claims where no other packet does the thing. Each carries the peer caveats so it is falsifiable.

- **U1. Two-tier progressive search as a first-class iterator contract.** `SearchPhase::Initial/Refined/RefinementFailed`, `SyncSearchIterator: Iterator`, sub-15 ms `Initial` then ~150 ms-budget `Refined` — a latency-budgeted "answer now, refine within budget" API [Code-verified + Counted, High] (claim 10). The string `SearchPhase` appears in no other packet. Peer checks done: frankenterm has "FTS5 (SQLite full-text search) + Tantivy + semantic fastembed + RRF hybrid" [Verified, High] — hybrid but not progressive two-tier; franken_alignment's "progressive refinement ladder" is activation-level oversight, not delivery; franken_whisper has NDJSON robot streaming + speculation, not answer-then-refine. **Genuinely standalone.**
- **U2. The shipped-default → pinned-oracle demotion arc.** Tantivy shipped as the default lexical backend and was demoted by owner ruling (2026-09-01) to a pinned (`tantivy = "=0.26.2"`), content-addressed conformance-oracle lane (`shadow-oracle` default-off), graded by the `quill-gauntlet` against the homegrown Quill default [Code-verified + Counted, High] (claim 5). Peer checks: franken_whisper also "replaced the backends it wraps" with a native engine shipping as default (`NativeEngineRolloutStage::Sole`, verified in code) — but keeps the incumbents as bridges/campaign comparators, not as a pinned in-tree oracle crate with cutoff certificates; frankengit keeps "upstream Git executables only as pinned, sandboxed conformance oracles" by constitution — but Git never shipped as its backend; franken_numpy still *depends* on its incumbent ("the wheel requires `numpy>=2.3`"). The mid-project demotion of a shipped default to a certified oracle lane is unmatched.
- **U3. Frozen producer identities with fail-closed embedding-space mixing, in the index format.** `producer_fingerprint: [u8; SHA256_BYTES]`, `identity.freeze()`, "Identity checks fail closed if vectors from the two spaces are combined", `embedder_revision` in FSVI, adapter-fingerprint-gated rebuilds [Code-verified + Maintainer claim, High] (claim 12). Closest peer is franken_ocr's truth-pack (doc-level pinning of model source commits + fixture hashes [Verified, High]) — a manifest, not an in-format refusal mechanism. No other packet has per-generation embedding provenance with refusal semantics. **Genuinely standalone** (within the evidence scanned).
- **U4. The `fsfs` agent-search product shape.** A search CLI built as an agent tool: progressive iterator + query daemon over a Unix socket + `--stream` JSONL/toon + `explain` surfaces + watch mode, with a checksum-verifying installer (full/lite/embedded profiles) that "never substitutes hash control embeddings for semantic results" [Maintainer claim, High] (§4.4, §4.5). Peers have pieces — frankenterm's Robot Mode JSON/TOON API, franken_whisper's sequenced NDJSON robot events, franken_ocr's installer + Homebrew tap — but none has a progressive-iterator-backed search daemon for agent tool-call budgets.

**Explicitly NOT unique** (do not cite as standalone): the negative-evidence ledger (peers are larger: torch 42,708, networkx 37,116, numpy 67k, whisper 26,846); the SELF-SPEEDUP/INCUMBENT classes (networkx enforces them; whisper's doctrine equivalent); RaptorQ FEC sidecars (frankenjax has "RaptorQ-branded durability sidecars"; frankengit has "ATP-Git / RaptorQ permeation"); the asupersync/tokio-forbidden posture (franken_snowflake enforces no-Tokio over a 589-package graph with a build-failing admissibility gate — stronger); multi-platform binary releases (franken_ocr ships six platforms with SHA256 sidecars; franken_whisper ships v0.9.3 installables + Homebrew tap); the nightly pin (26 packets share it); the 883k-line scale (frankenterm, franken_engine, frankentui are all larger).

## 6. CROSS-POLLINATION IN (apply to frankensearch)
