## 3. CI/EVIDENCE BAR — what franken_code_browser demonstrates that others lack

1. **The anti-fabrication defect taxonomy wired into a coordinator workflow.** AGENTS.md names six defects — demo hardcoding, proof laundering, refusal farming, commit pumping, gate self-weakening, follow-up laundering — as *coordinator-reopened defects*: the coordinator reopens work that exhibits them [Code-verified, High]. The packet's Wardley placement calls this "genesis, and the most exportable artifact" [Inference, Medium]; the bear-case steelman notes the taxonomy's own forbidden list "reads like a confession of what the swarm is tempted to do." Who lacks it: everyone has AGENTS.md doctrine, but no other packet documents a defect taxonomy *operated as a reopening workflow* by a named coordinator (BlackCedar) over named agent personas. Caveat: frankenlibc's AGENTS.md lists *twelve* named reward-hacking patterns as forbidden ("gate self-weakening, proof-class inflation, bench-path hardcoding, conformance metastasis among them") — "gate self-weakening" is shared verbatim, and the franken_whisper packet mentions "gate self-weakening" once. The fabrication-specific five (demo hardcoding, proof laundering, refusal farming, commit pumping, follow-up laundering) and the coordinator-reopen mechanism are FCB's own.
2. **The inverted claim inventory.** When the README disavows everything, the inventory's function flips: it documents the code *outrunning* the disavowal (CLI exists, desks exist, paged-postings search exists — all disavowed as "remain unimplemented"). Proposed as a Rulebook amendment and recorded in the program's status matrix: "declare the inventory's direction." The contrast case is FrankenRedis's *buried* disavowal; the adjacent cases (franken_surveillance_system's gate-000 box, franken_overlap's empty benchmark table) disavow without the inversion. No other packet formalizes disavowal-vs-tree divergence as an inventory method.
3. **Executable closure-audit probes.** `fcb-conformance` ships Python closure probes (`tests/test_closure_probe*.py`, `test_extension_ledger.py`) — "an executable dependency-audit tool with no second repo audited" [Code-verified, High on existence]. This is the enforcement arm of the zero-third-party-dependency constitution (`Cargo.lock`: 18 packages, all first-party; "no tokio, no serde, no regex, no tree-sitter" [Counted, High]). Who lacks it: no other packet has closure probes. Closest relatives: franken_snowflake's cargo-tree admissibility gate (exact-pinned `=0.3.5` asupersync with a lockfile census), franken_surveillance_system's dependency constitution (class F1 admission gate), frankengit's 234-external-package tree with no equivalent probe. Portability test the packet sets: run the probes against a second repo.
4. **The paged-postings trust boundary, stated as a contract.** `fcb-search`'s `SnapshotPostings` index carries an explicit rule: "a disk checksum proves internal consistency, *not* completeness — `decode_pinned` requires a separately supplied digest of a trusted-host-built artifact, and an untrusted index must be rebuilt from its independently validated snapshot" [Code-verified, High]. Relatives with adjacent machinery: frankensim's content-addressed evidence packages v9 with Merkle roots and a solver-free checker; frankenterm's sigstore-signed attestation bundles; franken_numpy's RaptorQ artifact sidecars. None states the checksum-≠-completeness split as a source-browser index contract — the formulation is FCB's.
5. **The "inert by construction" embeddability contract.** "One library (`fcb`), one app; default construction inert (no thread, window, scan, or global handler); hosts own event loop/device; two embedded instances must not interfere" [Maintainer claim, Medium — with the packet's own caveat that "one library" is really a feature-gated monolith]. Wardley: genesis, "no occupant in the code-browser lane" [Inference, Medium]. No other packet has an inert-construction contract; the nearest concept is franken_node's "impossible-by-default capabilities" (trust-native, not embeddability).
6. **Self-naming the exact stale sentences.** Claim 4's staleness finding quotes the precise README sentences that went stale (the "first foundation crates" inventory; the "no standalone executable" status) rather than gesturing at drift. This is evidence-bar behavior most packets approximate (franken_networkx's false-drift correction saga is the cautionary tale — it produced a Rulebook amendment requiring two counting methods before any drift accusation).

## 5. GENUINE UNIQUENESS

Verified by keyword sweep across all 44 packets: only franken_code_browser's packet contains "repository atlas," "code browser," "source browser," "paged postings," "inert by construction," or "two-instance."

1. **The spatial, read-only, Metal-native repository atlas as a product concept.** "Stable 2D places for directories/files; zoom from structure to readable source" [Maintainer claim, Medium]; `fcb-map`'s deterministic retained partition tree with "frozen raw-path child order (deliberately *not* size-sorted squarify)" and local repair explicitly not implemented [Code-verified, High]. Entirely standalone in the program. "Also does X" caveats, all different: franken_whisper's "Metal" is GPU inference kernels (`ft-kernel-metal`, target-gated on macOS); frankentorch's "metal" is a tensor backend; frankenterm has a native GUI terminal, not an atlas; the §4.6 web search found "no direct Rust-native spatial code browser" [External, Medium within recall caveats].
2. **The source-browser-specific paged-postings trust boundary** (§3 item 4): checksum proves internal consistency, completeness requires a separately trusted artifact digest; `decode_pinned` refuses untrusted indexes [Code-verified, High]. No other packet formulates this split for a search index.
3. **The "inert by construction" embeddable facade contract** (§3 item 5): empty default features, no process-global effects on construction, two-instance non-interference target. Competitor analysis: "a memory-safe, read-only, embeddable source-browsing *library* with audited byte-exactness contracts and an inert-construction guarantee has no direct occupant — editors are apps, not libraries, and Sourcegraph is a service" [Inference, Medium].
4. **The anti-fabrication verification process as an operated workflow** (§3 item 1): code-first → batch-verification-pending → independent receipt closure, with the six-defect taxonomy and coordinator reopening. Caveat, stated plainly: the *practice* of named forbidden patterns in AGENTS.md is shared with frankenlibc (twelve patterns, "gate self-weakening" shared verbatim); what is FCB's is the fabrication-specific vocabulary (proof laundering, refusal farming, commit pumping, follow-up laundering, demo hardcoding) and the coordinator-reopen operation. Wardley: genesis, "the most exportable artifact" [Inference, Medium].
5. **Persistent reading desks as a product surface.** `fcb-app/src/desk/`: "explicit persistent stdio reading sessions — repository/document/comparison/saved/code/reading command groups over bounded TAB-separated UTF-8 frames; checkpoint files only on explicit save" [Code-verified, High]. "Also does X" check: frankenscipy's and frankensim's "evidence packs" are RaptorQ/content-addressed artifact packages — different concept, different layer.
6. **The agent-shaped reading-trail export (plan-stage).** "Assemble an evidence pack of exact captured bytes with omissions declared" — "an agent-shaped primitive that ripgrep and VS Code do not offer as a library" [Inference, Medium]. No other packet has this primitive even as a plan; the nearest relatives are frankenterm's flight-recorder forensics and franken_node's evidence receipts, both execution-oriented rather than reading-oriented. Caveat: plan-stage only — "the trail export must exist beyond the plan" [Code-verified, High on the absence].

**"Also does X" — explicitly not unique:** the `.beads` issue tracker and receipt-bearing closures (program-wide culture; two whole product repos — beads-for-frankentui, beads_for_franken_engine — exist to export it); the unsafe-posture claim (shared; FCB's *violation* of it is the distinctive part); the rider license; bus factor 1; zero CI; benchmark disavowal (shared with franken_overlap, franken_surveillance_system, franken_remote, franken_nlp, franken_alignment, franken_native_capsule, franken_drone_geometry_reconstruction); the "30 ms p95 warm-path search" objective is unmeasured like every other suite objective.

1. **The anti-fabrication defect taxonomy + coordinator-reopen workflow** → **frankenlibc** (its twelve patterns are gate/benchmark-flavored; FCB's five fabrication-specific defects cover the swarm-process failure modes its taxonomy doesn't name), **franken_whisper** (the packet documents a "marketing-vs-ledger tension" — README headline vs ledger WER; a refusal-farming/proof-laundering lens names the failure), **frankenmermaid** (README chronically stale across every hand-written table — commit-pumping/demo-hardcoding-shaped drift), **franken_overlap** and **franken_nlp** (early-stage repos where fabrication risk is highest and process is thinnest). The operation that travels is not the vocabulary but the *coordinator-reopens-defects* loop.
2. **Executable closure-audit probes** → **franken_snowflake** (cargo-tree admissibility gate — probes make it executable rather than declarative), **franken_surveillance_system** (dependency constitution, class F1 admission gate — same constitutional shape, no enforcement tool), **frankenmermaid**, **franken_ocr**, **franken_agent_detection** (plain-MIT, the suite's most downstream-integrated crate — a closure probe is its supply-chain story). FCB's constitution ("no tokio, no serde, no regex, no tree-sitter") is the strictest in the program; its probes are the enforcement reference implementation.
3. **The inert-by-construction embeddability contract** → **frankentui** (embeddable TUI library ambitions), **franken_markdown** ("agent-first CLI" courting agents as evaluators), **franken_agent_detection** (a library with real downstream use — inert construction is its adoption contract), **franken_native_capsule**. The shippable unit: "empty default features, no process-global side effects on construction, two-instance isolation" as a conformance test, not a README sentence.
4. **The trusted-host digest boundary for cached indexes** → **frankensearch** (daemon rerank/index caching with load-sensitive p50s — its cached artifacts need exactly this contract), **frankengraphdb** (registry-check tooling over large generated surfaces), **frankenmermaid** (golden fixtures), **frankensqlite** (RaptorQ sidecars are the durability half; the digest boundary is the trust half).
5. **The inverted-inventory convention** → the program itself (Rulebook amendment proposed, recorded in the status matrix): applies immediately to **franken_surveillance_system** (gate-000 box vs moved code), **franken_overlap** (empty benchmark table), **franken_remote** (existence-claims posture) — any repo whose docs disavow more than the tree delivers. Plus the companion proposal: a "brief corrections" element when the assigning brief's technical anchors are falsified by the tree.
6. **The reading-trail export primitive** (plan-stage, offered as a design not code) → **franken_node** (migration evidence packs), **frankenterm** (mission forensics / flight recorder — a reading trail is the read-side dual of its execution trail), **franken_agent_detection** (provenance types for connectors). "Assemble an evidence pack of exact captured bytes with omissions declared" is the agent-shaped primitive none of them has.
7. **Persistent reading desks as a session model** → **frankenterm** (pane sessions over agent fleets), **franken_markdown_website** (lab-notebook-style reading flows). Bounded, checkpoint-on-explicit-save, TAB-separated UTF-8 frames over stdio is a session protocol any of them could adopt without the atlas.

**What should NOT be exported:** the "strict remote" verification story (unobservable by construction — deepening question 4 is still open); the `fcb-bridge` pattern (it violates the project's own constitution — export the contract, not the waiver); the sibling-repo delivery pattern (docs-only bead commits over remote-less code is the anti-pattern the packet's weakness 6 names).
