## 1. OWN-PACKET DISTILLATION

- **Verdict:** "franken_manim is a substantial, pre-1.0 clean-room reimplementation of 3b1b's manim" [Inference, High] — **TRL 5. NODUS ring: Explore.**
- **Strongest strength:** "the evidence discipline — a README that disclaims itself, a reality-check status audit, bit-locked self-goldens as merge blockers, a 642-record issue tracker, and release notes that reject their own bad artifacts" [Verified, High].
- **Strongest ceiling:** "the manimlib compatibility long-tail (93 placeholders), zero qualified performance evidence, bus factor 1 with outside contributions explicitly refused, and a non-OSI MIT+OpenAI/Anthropic-rider license that withholds even benchmarking rights from the two leading AI labs."
- **Scale:** 24 workspace crates + 2 G0 spikes; 325,255 Rust lines / 460 files; 3,312 `#[test]` occurrences; four prereleases (v0.1.0–v0.4.0); 9 stars / 2 forks [all Verified/API, High].
- **Revisit triggers:** first stable release; G4a/G4b closure; a pinned-host performance measurement; a cross-platform bit-identity measurement; a contributions policy or second maintainer; any independent benchmark; any change to the rider; fmd-math adoption outside the suite.

**The 3 most important pieces of evidence (with tiers):**

1. **The unsafe posture** [Verified, High]: "23 of 24 authoritative crate roots carry `#![forbid(unsafe_code)]`; the sole exception is `fmn-python`, whose `unsafe` is confined to the PyO3/CPython buffer and method-cache boundary (FFI by necessity, not by choice). Every other `unsafe`-word occurrence in the tree is prose or string literals." ADR-0016 routes SIMD through `std::simd` in crate-wide build tiers rather than per-call unsafe dispatch.
2. **The Parity Ledger + runtime truth gate** [Verified counts/mechanism, High]: "2,483 machine rows (2,071 same / 171 improved / 99 tiered / 142 excluded)" with a 103-site fail-closed refusal inventory, and `fmn-python --audit-parity` as "the runtime truth gate (`fmn-python --audit-parity`), which self-audits the wheel's embedded overlay bytes — exit 0 only if every reviewed row resolves to a real non-placeholder runtime value." Against it: the repo's own 2026-09-09 status audit found "93 placeholder symbols among 2,036 reviewed API rows" [Verified in the repo's own status doc, High].
3. **The asupersync disproof** [Verified, High]: "asupersync is a pinned workspace dep, but per-crate manifests show: `fmn-cli` optional behind the `batch` feature, `fmn-platform` optional (non-wasm), `fmn-runtime` dev-dependency only ('asupersync never enters the frame loop'; production uses std scoped threads)." This is the notable suite-wide finding of this packet: the question every sibling packet asks resolves here to *peripheral* — a batch-farm/scheduler tool, never the frame loop.

Supporting evidence: thread-invariance smoke — "circle scene 160×90 @8fps, PNG bytes + artifact digest + closure digest match at 1/4/16 threads, one Linux build" [Maintainer claim, Medium; the status doc's own caveat: "This is one scene on one Linux build, not full cross-platform or high-core certification"]; and the v0.3.0 release notes "incorrectly summarized a stale 0.2.0 Windows binary as successful. That artifact was rejected and is not attached. The manifest records both run identifiers and the rejection" [Verified on the releases page, High].

5. **Release tooling that publishes its rejected artifact with run identifiers in the release notes** — 1/44.
