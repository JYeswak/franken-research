## 1. OWN-PACKET DISTILLATION

**Verdict (one line, FSS packet's own):** "the most elaborately self-documenting pre-product codebase in the FrankenSuite — a 437k-line, zero-dependency, unsafe-free reference implementation of a surveillance philosophy, with the epistemic honesty to disclaim its own verification status commit by commit, and no demonstrated end-to-end run on real hardware." [Inference, Medium]

**TRL:** 3. Analytical/experimental: large deterministic reference exists, but "no operational-environment (real camera, qualified run) demonstration at the pin" [Inference, Medium]. The loopback/filesystem contracts argued TRL 4, but "they were never executed… unexecuted lab work does not clear the lab-validation bar."

**NODUS ring:** Explore [Inference, Medium]. "Substantive-but-unproven is the textbook Explore case… The rider is an advancement blocker, not a ring qualifier."

**Strongest strength:** The honesty infrastructure — the README IMPORTANT box disclaims the product "does not yet exist as a product"; `docs/PERF_LEDGER.md` states verbatim "No runtime exists yet, so this ledger contains no performance wins"; the pin commit message itself records "Rust compilation, tests, rustfmt, Clippy and native qualification NOT RUN: no Rust toolchain available"; GitHub CI is explicitly demoted to "portable supplementary specification" [all Maintainer claim, High — the honesty is the maintainer's; the code facts are Counted/Code-verified, High]. The packet's aggregate judgment: "claims about *discipline*… verify at High confidence; claims about *capability* are either stale documents, aspirational target-state, or explicitly disclaimed by the maintainer's own commit messages."

**Strongest ceiling:** A governance compound, not a single flaw: nothing at the pin has been shown to run end-to-end on real hardware (no release artifact, zero GitHub Releases), the current CI workflow has zero successes across all 622 recorded runs, the declared sole async runtime is absent from the build graph, the MIT license carries the OpenAI/Anthropic rider barring even *analysis* [Code-verified, High], and there is one human author with no succession plan [Inference, Medium]. The rider is classified "Explore-with-a-ceiling" — "even a fully qualified FSS could not advance while the named-party exclusion stands."

**The 3 most important pieces of evidence (with tiers):**

1. **Discipline claims verify; capability claims don't.** 13 workspace crates, 833 `.rs` files, ~437,249 first-party lines, zero unsafe constructs (695 files carry `#![forbid(unsafe_code)]`, 138 scanned clean), zero third-party dependencies (`Cargo.lock` = exactly 13 packages, the workspace itself), 5,379 `#[test]` attributes — all [Counted/Code-verified, High]. Against that: test greenness unestablished, no qualified decode, no camera acquisition at a qualified run.
2. **The qualification vacuum, quantified.** CI history: 622 runs — 570 `cancelled`, 47 `failure`, 4 `success`, 1 `queued`; the 4 successes belong to retired workflows absent from the pin's tree; the current "portable qualification specification" workflow has **zero successes**; the pin's run sits `queued` behind `runs-on: [self-hosted, fss-linux-amd64]` [CI-observed, High]. 25 of the last 40 commits (~63%) carry "NOT RUN" disclaimers [Git-observed, High].
3. **The runtime is doctrinal, not built.** Asupersync — badged "runtime-Asupersync," constitutionally mandated (Class F1, gate `INT-AS-001`), ledgered as "direct dependency" — is absent from every manifest and `Cargo.lock`, and the tree contains zero `async fn` [Code-verified, High]. The LICENSE reads "MIT License (with OpenAI/Anthropic Rider)" barring Restricted Parties from "use" including "benchmarking, testing, analyzing, indexing" with automatic termination [Code-verified (license text), High].

## 3. CI/EVIDENCE BAR: WHAT FSS DEMONSTRATES THAT OTHERS LACK

Genuine firsts in the 44-packet corpus (verified by grep: no other packet mentions these mechanisms):

1. **Per-commit "NOT RUN" qualification receipts.** 25 of the last 40 commits carry machine-greppable honesty trailers; the pin commit itself records "Rust compilation, tests, rustfmt, Clippy and native qualification NOT RUN: no Rust toolchain available" [Git-observed, High]. ## 6. CROSS-POLLINATION IN

Specific concepts from other packets that should be applied to FSS (concept → origin → fit → payoff):

1. **Admit asupersync as a real dependency** → **asupersync packet.** The runtime is a real, registry-published crate (0.5.0; 318,241 total downloads, 166,388 in trailing 90 days [External, High]; 20 GitHub releases with signed multi-platform builds [External, High]). Siblings already do the real thing: franken_remote consumes "asupersync 0.5.0 as a *published* crates.io release, not a mutable sibling checkout" [Code-verified, High]; frankensqlite "runs its storage I/O on asupersync 0.5.0, a real registry-published async runtime dependency, not a hand-rolled loop" [Verified in Cargo.lock, High]; frankensearch "mandates it and forbids tokio". *Why it fits FSS:* FSS's own DEPENDENCY_CONSTITUTION.md already mandates it as Class F1 "sole_async_runtime" — the admission gate `INT-AS-001` is the blocker, not the doctrine. *Expected payoff:* closes the single largest README-vs-code gap in the repo (FSS §4.7.2 — badged "runtime-Asupersync" vs. zero `async fn` [Code-verified, High]) and converts the structured-concurrency/cancellation story from aspirational ledger rows into build-graph fact.
