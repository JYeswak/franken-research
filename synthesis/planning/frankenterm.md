## 2. Execution-readiness gates

[Verified] Gates are layered and machine-enforced; the strongest are the evidence/receipt gates, not paper sign-offs:

- **Attestation closure gate** (`docs/release/attestation-checklist.md`): *"Every bead that produces or updates an attestation artifact MUST close with the same manifest wiring discipline the release gate later enforces."* Build script "fails loudly" on any required-category slot with `path: null`, missing artifact, hash mismatch, or undeclared proof category. *"If the build fails, do NOT manually patch the manifest — fix the producing bead's artifact instead. Manual edits silently drift the schema."* [Verified]
- **Release publication gate** (`docs/release/attestation-checklist.md`): *"In both cases, incomplete producer evidence MUST block publication."* *"Missing, skipped, failed, or deferred evidence cannot qualify that slot."* Release path is DSR-exclusive: *"GitHub Actions identities and workflow refs are forbidden"*; *"Do NOT treat an Actions result, artifact, log, badge, queue state, or lack of runner assignment as evidence for any FrankenTerm claim."* (AGENTS.md RULE 0.1) [Verified]
- **Cross-cutting bead inheritance rules** (`docs/reality-check-bridge-plan-2026-09-01.md`, §4b): (1) *"Generation binding. Every receipt records `commit`, `cli_version`, `mux_version`/`app_version`, `codec_version`, `host`, and the worker for remote lanes. A receipt from a different generation than the release under test is not evidence for that release."* (2) *"No silent pass. A skipped or informational assertion can never produce `status: pass`."* (3) *"Proof lanes. Remote, fail-closed (`RCH_REQUIRE_REMOTE=1 RCH_NO_SELF_HEALING=1`), `TMPDIR=/tmp`, no worker pins, one core-class lane at a time, the log retained and cited by hash in the bead comment."* (4) *"Degradation. Every operator surface added must say what it could not determine and why, never guess."* (5) *"Docs follow code in the same commit when a claim changes."* (6) *"Removal needs authorization (AGENTS.md Rule 1)."* [Verified]
- **Acceptance shape per gap** (`docs/reality-check-bridge-plan-2026-09-01.md`): *"Every section has the same shape so it can be carried verbatim into its beads: **Status now** … **Acceptance** (positive observable, planted negative, no-claim line)…"* [Verified]
- **Robot-Suggest Hygiene Checkpoint** (AGENTS.md): *"A high-confidence suggestion is not enough evidence to mutate the graph."* Mutation requires description/acceptance-criteria/comments/artifact-flow proof; closeout carries a proof footer with `data_hash`, cycle count, and sync error rate. [Verified]
- **Session-completion gate** (AGENTS.md "Landing the Plane"): *"When ending a work session, you MUST complete ALL steps"* — file issues for remaining work → quality gates → update status → `br sync --flush-only` → hand off. [Verified]
- **Historical baseline** (`docs/planning/PLAN.md` §23 Definition of Done, now explicitly superseded): *"`ft` is 'meaningfully real' when:"* seven unchecked boxes ending *"**Shipping Milestone**: All checkboxes above = v0.1.0 release candidate."* Kept as history, not current obligation. [Verified]

## 3. Honesty guardrails

[Verified] The honesty machinery is the most developed in any repo examined in this program; it is a full receipt-bound evidence architecture, not a document:

- **Proof taxonomy** (`docs/proof-taxonomy.json`): 11 proof categories with `example_path` and `accepted_shapes`, plus 4 explicit non-proof classifications (substrate/process/infrastructure/coordination). Every `ft-tf6g3` bead requires a `proof_category:` line. [Verified]
- **Fail-closed remote proof (RCH)** (`docs/rch-admission-contract.md`): *"The output is advisory. It can say a command appears runnable or blocked, but it is never proof that Cargo, tests, clippy, benches, fuzzers, or release gates passed. A dry-run, queue snapshot, worker-health report, or schema-valid diagnostic must not be cited as compiled proof."* Eight forbidden actions include `run_local_cargo_as_proof` (*"Do not cite local Cargo as proof for a FrankenTerm Cargo lane"*) and `treat_dry_run_as_compile_proof`. [Verified] Bead `ft-00gvk` demonstrates the posture in practice: *"RCH failed closed before Cargo with [RCH] local (no admissible workers: insufficient_slots=4,hard_preflight=2,active_project_exclusion=3); remote required; refusing local fallback (no worker assigned). No local Cargo proof was run or claimed."* [Verified, from `.beads/issues.jsonl` notes]
- **Negative-evidence ledgers** (`docs/perf-ledger/`): nine rounds of negative results; round 9: *"Negative evidence is a win — it hardens the moat for any round-10"*; every rejected/deferred entry closed with a grep-able retry-condition predicate; keep-gate rules and forbidden anti-vocabulary defined once in round 4 and carried over. [Verified]
- **Killed-ideas register with reopen rule** (`docs/proposals/ft-7h5da-12-6-killed-ideas-register.md`): *"Do not reopen an entry because the name sounds useful. A reopening bead must include: the new evidence; the old failure mode from this register; the narrowed scope that avoids that failure; a proof plan that checks the avoided failure does not return."* [Verified]
- **No-claim lines and hedge alignment**: acceptance sections carry a "no-claim line"; attestation bead closing must run `readme_hedge_alignment` when claim wording changes, and the closing comment must *"preserve `blocked`, `missing_evidence`, `degraded`, `skipped`, and `fixture_only` states, and do not turn `score_percent` into a release claim."* [Verified]
- **Auto-demotion**: [Partially verified] — documented as *executed* operator action rather than an automated rule. The 2026-09-01 reality check demoted whole epics to P2 (*"606 P0/P1 children demoted to P2 (open P0 = 25)"*) and released 71 stale `in_progress` claims; remaining open items are *"weekly audit in `reality-check-status.sh`"* and *"epic must have a `first_vertical_slice:` line"*. So: demotion is real, periodic, script-assisted, but the *rule* itself is ad-hoc cadence, not a codified auto-demotion policy. [Verified as executed; auto-rule Absent]
- **Lifecycle timing**: the proof-taxonomy/RCH/reality-check layering is a 2026-06→2026-09 accretion (taxonomy born under epic `ft-tf6g3` in the summer reality-check campaign; admission contract under `ft-69gwh`; attestation closure under `ft-187kv`/`ft-e87u6`), i.e. honesty infrastructure was installed as a *corrective* after the 2026-04 Modes-of-Reasoning report and the false-green history (G52: *"Core loop never proven on live agents; prior proofs were false-green"*). [Inference, anchored in the gap register]
- **No claim matrix as a standalone artifact** [Absent as such] — claim discipline is enforced via the taxonomy line, the hedge test, and the attestation manifest rather than a single matrix doc.

## 6. Anti-satisficing

[Verified] Multiple mechanisms beyond the dialectical reviews:

- **Planted negatives in acceptance**: every reality-check gap closure section must state a negative the acceptance test deliberately provokes, e.g. G50: *"planted negative: a tampered byte in the tarball must fail with the verification error and leave no `current` selector."* [Verified]
- **Mock-finder sweeps**: `docs/review/round-2-mock-finder.md` — repeat sweeps with fixed rg patterns, *"Verdict: SATURATED — zero new genuine WIP. Counts toward the 3-saturated-rounds stop-condition."* [Verified]
- **Reality-check sweeps**: README/AGENTS claims verified against HEAD numeric reality (`docs/review/round-2-reality-check.md` — claim-by-claim table with ✓/mismatch); earlier rounds filed beads for every drift. [Verified]
- **Tamper-detection smoke test**: `tests/attestation/smoke-test.sh` runs both directions: *"A green smoke test means the attestation pipeline catches a deliberate tampering. A red smoke test means the verifier is broken — block the release until repaired."* [Verified]
- **False-green accounting**: gap register explicitly tags prior false greens (G52 *"prior proofs were false-green"*; round-9 perf ledger caught a *"FALSE-OPEN CAUGHT"* with a decisive revert experiment). [Verified]
- **Reality check harness is adversarial against its own devs**: the RCH admission contract exists precisely because agents claimed unverified evidence; the contract pins the forbidden vocabulary and golden fixtures that retain no-service-action cases. [Inference]

## 8. Maturity verdict

**MATURE** — the most developed planning apparatus in the program. FrankenTerm is where Emanuel's plan-first method visibly *evolved into machinery*: the historical paper plans (PLAN.md, PLAN_CODEX.md) are preserved but explicitly demoted to "design history"; live planning now runs through a dependency-aware bead graph (5.5k issues), machine-checked evidence gates (proof taxonomy with mandatory bead lines, fail-closed remote proof lanes, signed attestation bundles with CI-breaking completeness tests), adversarial planning rituals (dueling-model idea contests with steelmen and tombstone registers, 10-lens project audits with published disputes and assumptions ledgers), and anti-satisficing fixtures (planted negatives, mock-finder saturation rounds, tamper-detection smoke tests). Distinctive feature vs. the suite pattern: honesty guardrails here are *executable* — receipts carry commit/version/host provenance and generation binding, local-Cargo-as-proof is a named forbidden action, and the verifier, not the document, is the authority. The system openly records its own failures (false-green history, 3 crate deletions, the orphan-module accretion the Modes-of-Reasoning report quantified at 57% unreferenced modules) and routes corrections through the same bead machinery that caused them.
