## 2. Execution-readiness gates

Emanuel's planning answer to "when may agents start writing code?" is **Gate G0 — Constitutional Contracts** (root plan §19). Verbatim:

> "**Gate G0 — Constitutional Contracts:** before Genesis code, land the threat/trust model; six-bet vocabulary; exact twenty-invariant spine; `invariants.toml`, `evidence.toml`, and `slo.toml`; the four disjoint identity registries … plus exhaustive `durable_fields.toml`, `command_contracts.toml`, `command_type_classification.toml`, and `state_payload_fields.toml`, registered BodyDigest/transcript recipes, acyclic construction/reference checks, and every reserved W12 kind … **No workstream may invent a missing semantic choice locally.**" [Verified, root plan §19]

> "**Hard rule: no subsystem ships against an unenforced invariant.** A workstream exit gate (G1–G4, §19) cannot pass while any invariant it depends on lacks a live checker in `invariants.toml`. Promote a design assumption to enforced only after the checker exists." [Verified, AGENTS.md]

The §1 constitution's claim-typing (constraint 11) is the meta-gate: "Every load-bearing statement is registered as exactly one of: `invariant` …, `proof` …, `bounded_model` …, `statistical` …, `slo` …, or `benchmark` … A weaker claim class may inform policy but may not enforce or justify a stronger one." [Verified, plan §1 + ADR source block]. Constraint 12 adds the cost constitution: "**Costs are registered claims.** … a latency gate must be ≥ its declared class's ordered-barrier count × the benchmark manifest's pinned measured fsync p50, and a gate that a registry row makes arithmetically impossible is a registry error that fails CI, never an ambitious target." [Verified, plan §1 / ADR].

Integration gates verbatim (root plan §19, one-line essence): G1 "The Engine Lives," G2 "One Version Universe," G3 "Verified & Networked," G4 "Leapfrog, Published" (all activated §17 benchmark manifests green/public; conformance matrices published; "papers match proven scope"), plus post-1.0 Gate W12 "One Universe, Many Shards." [Verified] Notably G4's "papers match proven scope" is itself a gate item — publication honesty is an exit criterion. [Verified]

Execution-readiness is also gated procedurally in AGENTS.md's **"Session Completion ('Landing the Plane')"**: file beads for remaining work; run quality gates if code changed; update issue status; `bash scripts/br_sync.sh <id> …` with the exact bead IDs, then stage the JSONL only after the helper reports that exact set; hand off with what changed, gates run + results, remaining risks/gaps, next steps. [Verified, AGENTS.md]

## 3. Honesty guardrails

This repo's honesty machinery is the most developed I found, installed across the lifecycle (not a late add-on):

- **Negative-evidence ledger, plan-stage requirement.** AGENTS.md declares: "Violating any of them is memorialized in `docs/NEGATIVE_EVIDENCE.md`" [Verified]. The ledger has **45 entries (NE-0001…NE-0045)** keyed not to reverts (the maintainers discovered the repo had 0 doctrine-violation reverts in 705 commits — the doctrine forbids the mechanism its clause requires) but to "a doctrine or enforcement claim that was found to be false." Each entry's load-bearing column is `signature` — the generalized shape of the self-deception class (e.g., NE-0001 "a substring test standing in for structural parsing," NE-0011 "a universally-quantified law that is green because its domain is empty," NE-0012 "a summary line asserting more than the run performed"). The entry schema is machine-parsed by its gate; doctrine must resolve in `registries/constitution.toml`, bead in `.beads/issues.jsonl`, repair in a reachable commit. [Verified, NEGATIVE_EVIDENCE.md]
- **Claim taxonomy as machine law.** `registries/constitution.toml` defines six claim classes (invariant rank 6 > proof > bounded_model > statistical > slo > benchmark) with a strength lattice: "rank(justifier) >= rank(claim) or the build fails." [Verified] This is the repo's answer to a claim matrix — typed claims with enforcement edges, not a spreadsheet.
- **Reward-hacking pattern list.** AGENTS.md Rule 0.5 imports 12 named, all-forbidden reward-hacking patterns from suite-wide `/data/projects/AGENTS.md` (file not in this repo): gate self-weakening, proof-class inflation, golden regeneration reflex, commit-stream pumping, tautological tests, easy-lever cherry-picking, close-pump abuse, scope-splitting, spec-editing as progress, conformance metastasis, dependency smuggling, bench-path hardcoding. Plus: "**reporting a loss is a success** — one line, revert, next lever, no retraction narrative." [Verified, AGENTS.md; the suite-wide file itself is [Absent] from this repo]
- **"No-claim boundary" doctrine.** Repeated in LOCAL_PROOF_BUNDLE.md and AGENT_CONTEXT_CAPSULE.md: each artifact states exactly what it does *not* prove ("The proof captures and attributes one invocation of `scripts/check.sh`… It does not replace raw logs… or turn red/void into pass"; "This is a capsule verdict only. It must never be translated into ALL GATES GREEN"). [Verified]
- **Auto-demotion-like rules (machine, no auto-demotion as such).** There is no literal "auto-demotion" rule [Absent]. The functional equivalents: (a) invariants.toml activation closure — "Every reachable clause must be live; otherwise the corresponding capability is absent" (plan §19, §1); (b) G1–G4 phrasing "Full language breadth is not claimed until its binder/operator rows exist"; "A feature whose command/state/checker row is disabled is absent from the 1.0 capability manifest, not described as partial." [Verified]
- **Local proof bundle (receipt-bound evidence).** Three-valued verdicts (pass / red / void); void covers moving-tree, not just pass/fail; verifier recomputes commit/tree/archive from an independent repository so a checksum-consistent bundle cannot silently attribute logs to a fabricated tree. [Verified, LOCAL_PROOF_BUNDLE.md]
- **Lifecycle timing:** the constitution, claim classes, G0 registries, and G0 negative-evidence gate were designed **before Genesis code** (G0 is pre-code by definition); the negative-evidence ledger file itself was created later (bead `fgdb-negative-evidence-ledger-does-not-exist-m172`, NE-0042/43) and seeded from measured history. [Verified]

## 4. Plan→agent execution

- **Task graph.** 997 beads, dependency-typed (`blocks`, etc.), labels mapping every bead to workstreams W1–W12 and gates G0–G4. Bead descriptions follow a What & scope / Why / Design and boundary / Success Criteria template; `Success Criteria` sections are the per-task exit criteria. `bv` computes PageRank/critical-path over `.beads/` for triage (robot flags only). `br ready` = tasks with no blockers. [Verified]
- **Phases.** Two programs coexist: the FABLE-era 8 workstreams / 4 gates and the final root plan's **12 workstreams (W1–W12) converging through G0 + G1–G4 + post-1.0 W12**, sequenced by dependency. SOL's plan adds a 12-track parallel construction program with a weekly architecture integration council (§38), a 180-day aggressive mobilization plan (§40), and its own Gates 0–8 milestone architecture (§39). The root plan's "Genesis slice" defines the first W1–W5 integration in exact state-machine terms (`Genesis -> CheckpointInstalled -> Operational` proven first, including crashes before/after each checkpoint command). [Verified]
- **Verification loops.** AGENTS.md's mandatory post-change chain: `bash scripts/check.sh` (the whole chain "including the non-Rust gates"), or piecemeal fmt/check/clippy/test + `ubs` on diffs — with the documented trap that cargo steps are no-ops on non-Rust files, closed by `check.sh`'s file-coverage closure and shell-lint steps. The **gate-verdict contract** (`fgdb-udco` in `scripts/lib/gate_verdict.sh`): one stream (stdout), one anchored token (`FAIL `), three states (ran-passed / ran-failed / did-not-run — only the first is green; UNRUN ≠ FAIL). The **verdict-contract closure** gate enumerates gates from the registry at run time so a newly registered gate is in scope immediately. [Verified, AGENTS.md]
- **Dialectical review in execution, not just planning.** This is the single most distinctive finding (see closing paragraph). The same adversarial loop that shaped the plan is institutionalized for artifacts: NEGATIVE_EVIDENCE entries record metamorphic/red-team discovery ("caught_by: metamorphic relation — 'what would this checker do if it were broken?'"; NE-0024 "mutation — substituting a confusable operator and observing green"); the claims-lint and registry gates have mutation-witnessed controls. [Verified]
- **Drift prevention.** Machine registries are master over docs (ADR is regenerated; checker fails on byte drift). `invariants.toml` cross-check: "CI verifies the twenty-ID/table hash, dependency DAG, checker/test existence, and the compiled-plus-negotiated activation closure." Frozen source blocks pinned by FNV-1a hashes. `waiver=forbidden` on every invariant clause. [Verified]
- **Multi-agent coordination.** MCP "Agent Mail" (identities, file reservations with TTLs, threads per bead ID); `cass` session search to avoid re-solving solved problems; remote compilation helper `rch` with an UNRUN-classification for offloader refusals; single-writer graph-structure discipline (JSONL is truth, beads.db disposable). [Verified, AGENTS.md]

## 6. Anti-satisficing

- **Adversarial review of the plan itself, twice over.** Kimi K3's falsification-attempted review → Fable's 3-pass meta-adjudication (12 parallel agents + 7 adversarial verifiers + live fact-check) → Sol Ultra's 15-P0-contradiction audit. The final plan's §1 constraint 12 (costs as registered claims) is the direct scar tissue of F-1/F-2: "the plan has a constitution for correctness claims (§1.11) and no constitution for cost" [Verified, META_ANALYSIS].
- **Mutation-proven gates.** Negative-evidence entries are found by metamorphic relations and mutation (NE-0024, NE-0044 "Mutate the input and watch the verdict move, or the law is unwitnessed"); `local_proof_selftest.sh` proves the proof bundle rejects checksum-invalid, fabricated-history, and malformed bundles. [Verified]
- **No-prototype doctrine.** AGENTS.md Doctrine #7 / plan §1.9: "Early code may implement a *subset* of a final abstraction — **never a substitute for it.** A slice that stubs the transaction model or bypasses the algebra is a prototype, and prototypes are prohibited." [Verified]
- **One-reader-per-fact, two-directional closure, non-emptiness controls.** NE-0005/NE-0008/NE-0011/NE-0013/NE-0015 generalize into design rules: universally-quantified laws need non-emptiness controls; closures must be two-directional; configuration that selects a law's domain is part of the law. [Verified, NEGATIVE_EVIDENCE.md]
- **Reality-check loop.** `docs/REALITY_CHECK_AND_BRIDGE_PLAN.md` is a recurring (not one-shot) audit — the 2026-09-22 delta concludes "The development process that produced most of the growth is the main problem," documents NE-0045 recurring at 4.7× scale, and the project failing every convergence gate. [Verified] That is, the anti-satisficing machinery is firing and reporting failure — which is itself evidence it isn't decorative.
- **Campaign mechanisms.** Fault/fuzz campaigns are specified in the verification ladder (plan §15: DPOR schedule exploration, crash-point matrix, torn-write campaigns, grammar fuzzing); [Inference] their execution status is tracked in the reality-check deltas and beads, not as a standalone campaign artifact.

## 8. Maturity verdict

**Mature — among the most developed planning systems in the FrankenSuite I would need to see to contradict, and possibly the single strongest.** The evidence: (1) a full dialectical pipeline for the plan itself — two rival comprehensive plans (FABLE, SOL), an external adversarial review, a second-order adjudication, and a 15-P0 audit — before Genesis code; (2) execution-readiness gated on machine-checkable artifacts (G0 registries) rather than prose; (3) 997-bead dependency-typed task graph with per-task success criteria and workstream/gate labels; (4) a 45-entry negative-evidence ledger with machine-parsed schema and its own e2e gate, recording real self-deceptions with generalized signatures; (5) claim-typed registries with a strength lattice enforced at build time; (6) receipt-bound local proof bundles with three-valued verdicts; (7) a recurring reality-check audit that currently reports the project failing its own gates.

The caveats are equally documented: the reality-check delta of 2026-09-22 reports 662 toolchain-less unverified commits since 09-08, `br ready` empty, 60% of commits citing no bead, the tracker "no longer steers the work," and zero of G0–G4 passed — the planning machinery is mature while plan→execution coupling has frayed under swarm scale. [Verified, REALITY_CHECK_AND_BRIDGE_PLAN.md] That divergence — mature planning, fraying execution — is itself the honest output of the machinery.
