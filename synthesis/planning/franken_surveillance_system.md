**Repo:** https://github.com/Dicklesworthstone/franken_surveillance_system (clone inspected at HEAD `d5edd0b`, 2026-09-22)
**Analyst role:** reverse-engineer HOW Emanuel plans, not what he built.
**Method:** cloned to `/tmp/plan-franken_surveillance_system`; read `AGENTS.md`, `ROADMAP.md`, `IMPLEMENTATION_STATUS.md`, the full `docs/` corpus (130+ docs incl. 13 ADRs), the 265 KB comprehensive plan (gates, work packages), all of `.beads/` (914 issues), machine registries in `architecture/`, and qualification docs. ## 2. Execution-readiness gates

[Verified] Gates are retained-evidence decisions across 14 gates (GATE-000 … GATE-120). From `COMPREHENSIVE_PLAN_FOR_FRANKEN_SURVEILLANCE_SYSTEM.md` §29:

> "A gate is a retained evidence decision, not 'the code seems done.' Gates may fail, pass narrowly, or pass with exclusions. Later gates do not retroactively widen earlier evidence."

Gate matrix (minimum evidence, §29.1), verbatim: GATE-000 architecture constitution ("Registries/mirrors agree; dependency and claim checks pass; threat/privacy model reviewed"); GATE-010 deterministic walking skeleton ("Virtual source→capsule→event→prepared alert→receipt replay; crash/cancel matrix"); GATE-020/030 real standards-device acquisition; GATE-040 media/archive durability; GATE-050 pure-Rust model runtime; GATE-060 event/alert correctness; GATE-070 calibration/digital twin; GATE-080 threat gauntlet ("Sealed event-level evaluation, fixed operating points, confidence bounds, hard negatives"); GATE-090 proprietary adapters; GATE-100 DJI Flip capture; GATE-110 agent/operator presentation; GATE-115 agent epistemic control and accretion (detailed criteria run to 16 bullet clauses); GATE-120 release candidate ("Security/privacy/DR/soak/perf/provenance proof bundle and honest generated status").

[Verified] A plan must pass **WP-000 constitutional bootstrap** before anything else (plan §28.1): "Purpose: make architecture enforceable before implementation complexity arrives." Its deliverables include the comprehensive plan itself, all registries, the dependency allowlist checker, the claim/evidence policy checker, and the negative-evidence ledger. Exit evidence: "all repository policy checks pass; every public claim is classified; bootstrap CLI schemas are stable; no implementation claim is made from skeleton code."

[Verified] The agent-level "set free" gate is `AGENTS.md` workflow steps 1–4 (mandatory, verbatim): (1) "Restore the mission: inspect the latest AgentSessionCapsule/handoff, current authority, active obligations, work claims, invalidations, and negative evidence. Never rely on remembered chat state." (3) "Establish scope: stable requirement IDs, mission/objective contract, files, authority changes, migrations, budgets, affected planes, and qualification gates." (4) "Preserve alternatives: for uncertain work, create/revise an InvestigationCase with competing hypotheses, evidence, contradictions, predicted observations, falsifiers, shared failure domains, probe costs, and stop rules."

[Verified] Per-work-package exit evidence (§28): each WP has "one owning subsystem, explicit inputs, deliverables, dependencies, and exit evidence. Work may proceed in parallel only where the dependency graph permits." Example WP-010: "same seed/input produces byte-identical canonical outputs; cancellation at every instrumented yield point leaves no unowned obligation; crash cut points recover to a classified state."

[Verified] Definition of done (`AGENTS.md`): "A requirement is done only when its contract, success/failure semantics, migrations, deterministic reference, fault tests, compatibility identity, privacy/security behavior, performance cost, proof bundle, status, and documentation agree. 'Code exists' is not a completion state."

[Verified] Truth hierarchy (`AGENTS.md`): "1. Machine-readable registries and versioned schemas. 2. Normative comprehensive plan and ADRs. 3. Tests and retained proof bundles. 4. Implementation. 5. Explanatory documentation. When these disagree, do not choose the most convenient one. Record the drift, identify the owning contract, and repair the set coherently."

## 3. Honesty guardrails

**Negative evidence — [Verified], lifecycle-installed at plan genesis.** `docs/NEGATIVE_EVIDENCE.md` is the ledger with fixed schema (`NEG-###`, date/commit, hypothesis, setup, result, decision, revival condition). It is required by WP-000's deliverables ("repository status doctrine and negative-evidence ledger"), i.e., installed before implementation complexity arrives. Current content: only NEG-001..003 from architecture research (DJI Flip SDK not an architectural dependency; proprietary app access not a stable standard; no single frontier VLM as the complete stack). Decision vocabulary is explicit: "Reject, retain as oracle, narrow scope, or revisit" plus a revival condition per entry. `docs/DECISION_CARDS_AND_EXPERIMENTS.md` §8 adds the rationale verbatim: "Rejected optimizations and failed policies are retained… This prevents agents from repeatedly rediscovering seductive failures."

**Claim lifecycle — [Verified].** Plan §29.13: claims move `Proposed → MeasuredInLab → ShadowQualified → NarrowlyQualified → Released` with "↘ Rejected / Superseded / Expired". "A claim expires when any load-bearing generation changes: device firmware, adapter, model, preprocessing, policy threshold, calibration method, schema, runtime, platform, or corpus contract." Claim classes with minimum evidence are machine-enforced via `architecture/claims.json` (schema `fss.claims.v1`) mirrored by `registries/CLAIMS.md`. `registries/CLAIMS.md`'s "Forbidden claim promotions" is the literal anti-claim-inflation contract, verbatim examples: "no observed miss → never-miss guarantee", "recommendation score → authority to execute an effect", "fewer tool calls → greater agent efficiency without task quality, safety, and full resource cost".

**Auto-demotion — [Verified, mechanism exists; no standalone doc].** Three channels: (a) claim expiry on generation change (§29.13, "the registry must justify" any delta qualification); (b) `DEC-AGENT-LEARNING-001` — learning proposals are "promote, retain as candidate, demote, retire, or invert" with the trauma guard; (c) GATE-115 criteria: "feedback/learning proposals cannot silently mutate truth, active policy, model, thresholds, or authority and harmful proposals are demoted/retired by the trauma guard." Negative-evidence `Decision` values also encode demotion ("narrow scope" vs "revisit").

**Receipt-bound evidence — [Verified, pervasive].** `AGENTS.md` requires semantic compression receipts, semantic handles, and "Update status honestly: documentation and evidence pointers may not upgrade a claim beyond the proof actually retained." MVCC ledger requires read/write/negative witnesses and commit receipts; effects require receipts at every protocol stage; handoffs require typed capsules. ROADMAP: "A checked box here means the stated reference capability exists; it does not imply production qualification."

**Truth-plane honesty — [Verified].** ADR-0001 + `docs/enforcement/three_semantic_planes_contract.md`: authority/cognition/effect planes are type-distinct; the enforcement contract is proven by doctests attached to the real public items that own the boundary, compiled against the actual API ("A cognition output (model score, recommendation) can never grant effect authority"). Machine-checked by `scripts/qualify.sh` policy lane.

## 4. Plan → agent execution

**Task graphs — [Verified].** Two interlocking graphs: (a) `.beads/` issue DB (914 issues, epics → tasks, `dependencies` field, `acceptance_criteria` field, comments carrying review verdicts); (b) the comprehensive plan's Appendix F "First 250 implementation issues" (the seed catalog, machine-owned by `architecture/seed_requirements.json`). WP-000 deliverable includes "issue/bead epic graph derived from this plan." `fss-x4a.1` is the PROGRAM-GOV bead ("Program governance, source drift, and requirement coverage"). Bead statuses include `open/closed/in_progress/blocked/tombstone`.

**Phases — [Verified].** Plan §28: work packages WP-000 → WP-140+ sequence work; ROADMAP.md Phases 0–6 give the same order operationally. "Phases sequence the work; they do not reduce the target scope." The comprehensive plan itself was written first — ROADMAP's twin-to-handoff critical path closes with: "All new runtime items above are unchecked because adopting a plan is not implementing or qualifying its features."

**Verification loops — [Verified].** `scripts/qualify.sh` is the semantic entrypoint (`AGENTS.md`: "Local release authority: scripts/qualify.sh is the semantic qualification entrypoint. DSR executes it from clean snapshots on controlled native hosts with exact sibling closure. GitHub workflows are portable supplementary specifications only. No agent may weaken a lane because hosted capacity is unavailable."). Qualification lanes include policy, Rust static/unit, deterministic reference, differential, fault, crash, cancellation, migration, security, privacy, performance, end-to-end. GATE-120 release criteria include "workflows contain no unique release logic and GitHub-hosted runner absence is irrelevant; public claims are mechanically derived from retained proof-bundle roots and expiry rules."

**Dialectical review — [Verified in bead evidence].** Bead comments record repeated adversarial review rounds by differently named reviewers (FoggyBass, QuietBear, PinkCoast) with explicit verdicts — e.g., `fss-2h5zq.1`: "Review r1e of ebe683b (round 5, forward on main) = REJECT: CAPLOG is read only from stdout … fail-open"; `fss-2h5zq.11`: "Independent review r11 = REJECT (3541936)"; `fss-2h5zq.32`: "FoggyBass 2026-09-14 11:42: round 3 b33e4b0 REJECT (r32c)…"; `fss-2h5zq.39`: "round 2 f322a11 PARTIAL (r39b)… Round 3 bar: …" Verdicts are REJECT/PARTIAL/PASS with named probes (r32e probe p04, M6a/M6b surviving mutants), and fixes must come with named regression tests before status upgrades. This is the two-models-against-each-other pattern operating at the bead level, with the review trail retained in the issue DB.

**Drift prevention — [Verified], the distinctive mechanism.** When the plan and the repo disagree, `docs/PLAN_ERRATA.md` records canonical resolutions without rewriting history ("It does not silently rewrite the historical comprehensive plan"), and the machine registries win ("The machine allowlist wins" — e.g., DRIFT-008 resolved that §27.3's prose about the Thiserror exception was wrong vs `architecture/dependency_allowlist.toml`). Dedicated DRIFT-### beads (`fss-x4a.1.1` … `fss-x4a.1.34`) track each repair; DRIFT-003 reconciled the "first-240" plan text with the canonical FSS-250 seed via a reviewed catalog version plus retained before/after fixtures. The seed proof checker (`scripts/seed_requirement_checker.py`) produces "retained deterministic positive, negative, and recovery evidence"; "recomputing a digest alone is not authority." ROADMAP's unchecked items and IMPLEMENTATION_STATUS's status doctrine ("No task should be closed solely because a neighboring type, schema, shared helper, or happy-path demo exists") are the standing anti-drift rules.

**Anti-compaction posture — [Inference from workflow rules].** No explicit "never compact" rule was found (grep of AGENTS.md and the comprehensive plan for compact-related session rules returns nothing). The protection is structural instead: `AGENTS.md` mandates "No mission-critical fact, assumption, obligation, lease, indeterminate effect, or next step may exist only in conversational context" and a typed handoff published "before ending work" that persists "current mission, situation roots, cases, findings, plans, obligations, unknowns, invalidations, budgets, authority, continuations, and valid next affordances" — i.e., compaction is survivable because no durable state may live in the session context. [Maintainer claim] (AGENTS.md): "Never rely on remembered chat state."

## 6. Anti-satisficing

**Red-team corpus — [Verified].** Plan §24 "Dataset constitution, red-team corpus, and statistical qualification" (events, not frames, as the unit of evaluation; split discipline forbidding random neighboring-frame splits; hard-negative and scenario taxonomy). GATE-080 requires "Sealed event-level evaluation, fixed operating points, confidence bounds, hard negatives" and forbids "absolute 'never miss' language beyond measured bound and observable scope."

**Falsification machinery — [Verified].** Executable investigations (FSS-213/214/215): competing hypotheses with predictions, falsifiers, discriminating probes, stop rules; "refutation is final and an advanced hypothesis cannot silently return to Live"; conclusion "requires the exact declared stop rule, an assessment digest, acknowledgement of every retained unknown ID, and no Live alternatives" — "Closing an indeterminate case archives uncertainty; it does not establish a conclusive answer."

**Campaign mechanisms — [Verified].** GATE criteria name fault campaigns repeatedly (crash/cancel matrices, packet fault suite, disconnect/cancel/soak, interruption/resume, installer canaries, drift quarantine). `docs/DECISION_CARDS_AND_EXPERIMENTS.md` §5 "Same-binary experiment doctrine": A/A null first, proven reference-candidate equivalence before timing, sealed workload identity, results report "distributions, tails, variation, sample count, and negative outcomes—not only a best number." Shadow-first promotion with protected-slice regression bounds.

**Hazardous-comfort prohibitions — [Verified].** `AGENTS.md` "Prohibited shortcuts" (23 items, e.g., "Calling adapter acceptance 'streaming'", "Treating a missing detection during a coverage gap as evidence of absence", "Treating a green hosted workflow as release authority", "Calling fewer tool calls 'agent efficiency' without measuring task correctness, safety, calibration, full resource cost, and operator burden") — a literal anti-satisficing list for agents.

**Protected-world protection — [Verified].** High-loss possible worlds "cannot disappear through ranking, model reranking, compression, transfer, view changes, or handoff"; every action is classified against the exact WorldEnvelope; uncertainty cannot be "flattened" into null/low confidence/omitted output.

## 8. Maturity verdict

**Mature.** This is the most planning-mature repo in the observed suite along the "constitutionally enforceable planning" axis: the plan is not advice but a machine-checkable normative system. Evidence: (1) a 14-gate release matrix with per-gate detailed criteria and a claim lifecycle with expiry, all machine-registered; (2) a 914-issue task graph with dependency/acceptance-criteria fields and round-based adversarial review retained in comments; (3) the distinctive **drift machinery** — DRIFT-### beads, `PLAN_ERRATA.md`, machine-owned canonical resolutions, seed proof checkers — that keeps the published plan honest after the fact rather than silently editing it; (4) three-layer source-of-truth hygiene (research ledger → source census → verified source citations); (5) negative-evidence, decision-card, and performance ledgers installed with schema *before* there is data to put in them (WP-000's "make architecture enforceable before implementation complexity arrives" is itself the signature planning move). The gap between plan maturity and implementation maturity is explicit and quantified in `IMPLEMENTATION_STATUS.md` ("pre-release deterministic reference implementation; not production-qualified"), which is itself part of the method: planning maturity here is measured by how precisely the repo says what it has *not* yet earned the right to claim.
