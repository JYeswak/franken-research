## 2. Execution-Readiness Gates

What must pass before agents are set free is layered: **plan-level charter gates**, **evidence contracts per change**, and **CI-enforced machine gates**. [Verified] verbatim quotes:

**Charter-level (plan, maintainer prose):**
- "No contract, no merge." — `docs/plans/PLAN_TO_CREATE_FRANKEN_NODE.md` §11 "Evidence And Decision Contracts (Mandatory)", which requires every major subsystem proposal to include: "change summary, compatibility and threat evidence, EV score and tier, expected-loss model, fallback trigger, rollout wedge, rollback command, benchmark and correctness artifacts."
- "Line-by-line translation from Bun/Node implementations is off-charter; legacy runtimes may be used for spec extraction and conformance fixture capture only." — plan §4.
- "Any deviation from these substrate rules requires an explicit, signed waiver artifact with rationale, risk analysis, and expiry." — plan §4 (waivers tracked in `docs/governance/waiver_registry.json`, currently empty — `{"waivers": []}` [Verified]).
- Category-creation test (plan §3.1): "If users can get the same outcomes with a thin wrapper around Node/Bun defaults, the feature is insufficient. If claims cannot be independently verified, the feature is insufficient. If migration cost remains high for real teams, the feature is insufficient."
- Ambition gate (plan CAVEAT): "Contributions that reduce ambition without explicit owner direction are not helpful." — plans must increase disruptive capability; "Framing de-scoping as the default answer" is "Out-of-charter behavior."

**Phase gates (roadmap):** each phase has an exit gate, e.g. Phase 0: "Workspace compiles, lint-clean, and reproducible scaffolding validated."; Phase 2: "Simulated supply-chain attack scenarios are detected and contained without host compromise in harnessed tests."; Phase 5: "Evidence-backed readiness report and release approval checklist complete." [Verified]

**Per-change evidence (roadmap "Required Evidence Artifacts"):** every significant subsystem change ships "baseline benchmark report, profile artifact (flamegraph/equivalent), golden output checksums, isomorphism note, decision contract (loss model + fallback trigger), reproducibility pack (`env.json`, `manifest.json`, `repro.lock`)." [Verified]

**Close discipline (AGENTS.md, mandatory since 2026-05-12):** close_reason must be "A one-paragraph (≥ 80 chars) close_reason that includes at least ONE of: a commit SHA, a PR reference, a file:line citation — AND for `bug`/`feature` types, at least one test name that newly passes." [Maintainer claim] Fabricated-evidence rule: a `verification_evidence.json` citing nonexistent files is "a fake close." CI enforces via `.github/workflows/closer-discipline-gate.yml` (ramped: warn-only 2026-05-12→06-15, strict after).

**Reward-hacking bans (AGENTS.md, binding from suite rules):** 12 named patterns forbidden — "gate self-weakening, proof-class inflation, golden regeneration reflex, commit-stream pumping, tautological tests, easy-lever cherry-picking, close-pump abuse, scope-splitting, spec-editing as progress, conformance metastasis, dependency smuggling, bench-path hardcoding"; the three decisive ones: "a self-speedup is MAINTENANCE, not a win — a win needs the incumbent live in the SAME invocation; never weaken a gate to land a change…; and reporting a loss is a success — one line, revert, next lever, no retraction narrative." [Maintainer claim]

## 3. Honesty Guardrails

**Claim language is deterministic and recomputed.** [Verified] `docs/specs/section_10_14/bd-18ud_contract.md` defines a claim-language matrix ("identical (mode, outcome) inputs always produce identical claim strings"); `.github/workflows/claims-manifest-gate.yml` "Recomputes each headline claim… from the committed tree and fails when it drifts from docs/claims_manifest.json beyond tolerance"; `docs/CLAIMS_REGISTRY.md` explicitly separates pending vs verified claims.

**Negative evidence is structurally required.** [Verified] Plan §16 "Scientific Contribution Targets" mandates "transparent technical reports including failures and corrective actions." [Verified] `docs/policy/verifier_economy.md` includes selective-reporting detection: "Statistical completeness checks flag verifiers who consistently omit unfavorable results" and "Incomplete submissions are rejected." [Verified] MODE_OUTPUT_G1 documents the design choice of "negative receipts over permissive compatibility shortcuts." [Verified] The divergence ledger (plan §10.2 epic) records intentional behavior divergences with "cryptographic signature, explicit rationale, policy gate, and remediation guidance" — divergence-as-receipt, not silent drift. [Maintainer claim]

**Demotion exists as an adversarial gate mechanism, not per-bead auto-demotion.** [Verified] The independent-replication gate (`docs/specs/section_13/bd-whxp_contract.md`) "applies adversarial perturbation (demote one independent pass) and requires verdict to flip to FAIL"; its scenarios include pass, coverage-fail, independence-fail, claim-fail, determinism, and "Adversarial scenario: demoting one independent pass flips verdict." [Verified] **No generic auto-demotion rule for stale/weak beads was found** — demotion appears only in quorum/consensus contexts (`QuarantineAction` promote/demote) and this adversarial perturbation gate. [Absent, as auto-rule]

**Completion-debt as falsification retro-loop.** [Verified] 739 beads are titled `[completion-debt]` (16.9% of the store): each records an audit pass that re-opened work on a closed bead with an audit score (e.g. `bd-03gg4.1`: "Audit score: 650/1000… Acceptance criteria for THIS completion-debt bead") and a link to a scorecard. 250 beads are audit-titled. This is the mechanism by which thin closures are re-surfaced as new tracked work.

## 4. Plan→Agent Execution

**Graph-based task scheduling.** [Verified] `.beads/issues.jsonl` is the plan materialized: 4,352 beads, 92 epics, dependencies typed (e.g. parent-child). Agent session protocol (AGENTS.md): `br ready` picks highest-priority unblocked work → MCP Agent Mail file reservation (`exclusive=true`, 1-hour TTL, reason = bead id) → announce start in thread `[bd-###]` → work → close with evidentiary `close_reason` → `br sync --flush-only` → commit. `bv` (graph-aware triage) computes PageRank/betweenness/critical path/cycles to derive "parallel execution tracks with `unblocks` lists." Single-writer discipline on graph structure: "JSONL is truth and `beads.db` is disposable… single-writer on graph structure."

**Multi-agent coordination.** [Verified] MCP Agent Mail: registered agent identities, inbox/outbox, searchable threads, advisory file reservations ("prevents conflicts… human-auditable artifacts in Git"). `AGENTS.md` "Landing the Plane" contains an unusually blunt anti-paralysis rule born from the swarm reality (dozens of concurrent agents): "those are changes created by the potentially dozen of other agents working on the project at the same time… NEVER, under ANY CIRCUMSTANCE, stash, revert, overwrite, or otherwise disturb in ANY way the work of other agents."

**Verification loops.** [Verified] Three nested loops: (a) method-stack loops per PR (MS-01 baseline→profile→prove→implement→verify→re-profile; MS-04 extract→capture→implement→enforce); (b) CI gates on every PR/push (claim gates, contract gates, roadmap gates); (c) periodic reality-check audits that measure the whole repo against the charter and write the gap table in place.

**Drift prevention.** [Verified] Structural, not exhortative: (1) §10.N Execution Normalization Contract — "If the same capability appears in multiple tracks, exactly one canonical implementation path owns the protocol/code semantics… Duplicate implementation of the same protocol semantics in parallel tracks is explicitly off-charter," with a full canonical-ownership map; (2) RULE 0 — the owner override prerogative: "If I tell you to do something, even if it goes against what follows below, YOU MUST LISTEN TO ME. I AM IN CHARGE, NOT YOU."; (3) RULE 1 — no file deletion without express written permission; (4) 13 numbered constraints with CI enforcement and violation event codes (e.g. `NNC-002:C-09` for line-by-line translation); (5) README/claims drift gates that recompute headline numbers from the live tree.

[Maintainer claim, his own audit]

## 8. Maturity Verdict

**Mature.** [Inference grounded in evidence above] franken_node has the most elaborated planning apparatus seen in the suite to date: a 1,889-line canonical plan with an explicit ambition charter, four mandatory method stacks with per-PR artifact requirements, 13 CI-enforced constraints with violation codes and an expiring-waiver registry, 4,352 dependency-typed beads with 92 epics materializing the plan, graph-aware triage for parallel track extraction, MCP agent-mail coordination with file reservations, ~50 CI gates spanning claims/contracts/roadmap metrics, closer-discipline auditing with 739 completion-debt beads retro-filing thin closures, deterministic claim-language recomputation, and a standing reality-check audit that measures promises against the live tree and names the bead-completion illusion by name. The honest deficits are: no bibliographic research phase (SOTA is behavioral only), the suite-level rules file it defers to is not in the repo, and auto-demotion exists only as an adversarial gate perturbation rather than a standing bead-hygiene rule.
