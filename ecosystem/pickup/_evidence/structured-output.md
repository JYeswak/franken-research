## Process practices worth copying (practice | repos exhibiting it | file pointers)

- **Split tests into core-engine unit tests (C++/Rust) and binding/integration tests (Python).** | xgrammar | `tests/cpp/` (test_fsm.cc, test_grammar_parser?/test_parser.cc, test_regular_grammar_fsm.cc) vs `tests/python/` (33 files); repo root has `.clang-format` + `pyproject.toml` side by side.
- **Per-backend conformance tests: run the same constraint semantics against every engine adapter.** | outlines (`tests/backends/test_xgrammar.py`, `test_llguidance.py`, `test_outlines_core.py`, `test_backends.py`); vLLM (`tests/v1/structured_output/test_backend_guidance.py`, `test_backend_xgrammar_stop_tokens.py`) | dottxt-ai/outlines/tests/backends, vllm-project/vllm/tests/v1/structured_output.
- **Golden-file snapshot tests for schema→grammar conversion.** | llama.cpp | `ggml-org/llama.cpp/tests/test-json-schema-to-grammar.cpp` — asserts byte-exact expected grammar text for given JSON schemas, plus `verify_expectation_parseable()` re-parses the expectation through the grammar parser.
- **Grammar accept/reject integration tests at the sampler level.** | llama.cpp | `tests/test-grammar-integration.cpp`, `tests/test-llama-grammar.cpp`, `tests/test-grammar-parser.cpp`.
- **Differential validation against an independent ground-truth validator.** | xgrammar | `tests/python/test_grammar_matcher_json_schema.py` — builds a Pydantic `MainModel`, serializes with `model_dump_json`, and validates matcher output against the model; helper oracle `xgrammar.testing._is_grammar_accept_string` imported in the same file.
- **Mock-model grammar tests that decouple constraint logic from real inference.** | guidance | `tests/unit/test_grammar.py` — uses `models.Mock()` with byte-prefix assertions (e.g. `assert lm["text"] == "nice man."`); includes a `pytest.mark.xfail` for a known lexer-boundary bug linking the upstream issue.
- **Pressure tests for large grammars, explicitly excluded from CI.** | xgrammar | `tests/python/test_pressure.py` ("Local pressure tests for representative large-grammar workloads") with `pytest.mark.skipif(_running_in_ci(), ...)` and `pytest.mark.hf_token_required` — copy the pattern: heavy conformance runs exist but are gated off the critical path.
- **Scheduled CI benchmark measuring constraint overhead (compile + mask generation), not just correctness.** | xgrammar | `.github/workflows/benchmark.yaml` — nightly cron on self-hosted runner running `examples/benchmark/cibench_grammar_compile_mask_gen.py` (grammar compile + mask-gen timing, warmup iters), results uploaded as artifacts.
- **Serving-level structured-output throughput benchmark with tunable constraint ratio.** | vLLM | `benchmarks/benchmark_serving_structured_output.py` (`--structured-output-ratio`, `--dataset json`, request-rate sweep) + `benchmarks/run_structured_output_benchmark.sh` + `benchmarks/structured_schemas/`.
- **Test tiers: unit / model-integration / credential-gated, with separate CPU+GPU CI entry points.** | guidance | `tests/unit`, `tests/model_integration`, `tests/need_credentials`, `tests/notebooks`; workflows `call_cpu_tests.yml`, `call_gpu_tests.yml`, `ci_credentials.yml`, `ci_linux/macos/windows.yml`.
- **Constraint-DSL unit tests (test the spec language itself, not just the sampler).** | outlines | `tests/types/test_dsl.py`, `tests/types/test_to_regex.py`, `tests/types/test_json_schema_utils.py`.
- **Parser-level correctness suites per constraint type.** | lm-format-enforcer | `tests/test_jsonschemaparser.py`, `tests/test_regexparser.py`, `tests/test_composite_parsers.py`; plus tokenizer-cache perf tests `tests/test_tokenizercaching.py`.
- **Compilation-timeout / worst-case safety tests for constraint compilation.** | vLLM | `tests/v1/structured_output/test_regex_compilation_timeout.py` — guards against pathological regexes DoS-ing the serving loop.
- **Grammar-compilation cache correctness tests.** | outlines (`tests/test_cache.py`); vLLM (`tests/v1/structured_output/test_outlines_cache.py`) | Cache invalidation across schema/tokenizer changes is tested explicitly.
- **Constraint × serving-feature composition tests.** | vLLM (`tests/v1/spec_decode/test_mtp_structured_output.py`, `test_scheduler_speculative_padding.py`); xgrammar (`tests/python/test_speculative_decoding.py`) | Verifies guided decoding composes with speculative/multi-token prediction rather than assuming it.
- **Coverage + pinned-tool CI.** | lm-format-enforcer | `.github/workflows/run_tests.yml` — poetry install, `coverage run -m pytest`, codecov upload on main; `tox.ini` for multi-env. Outlines pins action SHAs in `tests.yml`.
- **Backend/type-adapter matrix across model providers.** | outlines | `tests/models/` (~30 files: test_openai.py, test_anthropic.py, test_transformers.py, test_llamacpp.py, …) — each provider gets adapter + conformance tests so constraints behave identically across APIs.

## Notes / caveats (be honest about thin evidence)

- **Fuzzing: thin.** The closest thing to grammar fuzzing found is xgrammar's `test_pressure.py`, which is workload-based load testing of large grammars, not generative fuzzing of grammar→mask equivalence. No repo in this set runs a documented differential fuzzer (random grammar → compare masks against a reference parser). A clean-room project should add one; the ecosystem doesn't demonstrate it.
- **Decoding-overhead numbers are measured at the serving layer, not published as library SLAs.** xgrammar's nightly benchmark and vLLM's serving benchmark measure overhead empirically but neither repo publishes a committed per-token overhead budget in docs; overhead is tracked as CI artifacts, not assertions.
- **guidance's last push (2026-05-21) is ~4 months stale** relative to the others; it remains the most-starred and is still a vLLM backend, but its grammar core has effectively moved toward the shared-engine (llguidance/xgrammar) model — outlines' `tests/backends/test_llguidance.py` is the tell.
- **jsonformer (2024-02-24) is dead upstream**; cited only as evidence the category has a multi-year arc, not for process practices.
- All repos above were verified via `api.github.com` repo metadata + contents/tree listings on 2026-09-23; file pointers are paths observed live in those trees. Nothing in this file was cited from memory.
