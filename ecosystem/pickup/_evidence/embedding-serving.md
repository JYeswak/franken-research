# Embedding model serving - evidence

Every repo below was verified live via the GitHub API / raw file fetches on 2026-09-23.
Star counts and `pushed_at` are from the repo API at time of check.

### Model-weight pinning, observed (CI vs nightly and pin style)

- **Pinned baseline *score*, floating weights**: vLLM's MTEB gate pulls `intfloat/e5-small` current but asserts against a pinned SentenceTransformers score + 5e-4 tolerance. Quality gate without freezing weights.
- **No revision pins in test configs** (float on Hub): TEI's Gaudi integration test config uses `"model_id": "BAAI/bge-large-en-v1.5"` with no `revision` (`integration_tests/gaudi/test_embed.py`); fastembed's `ModelSource(hf=…, url=…)` likewise carries no revision pin (`fastembed/common/model_description.py`) — both trust the Hub and rely on cached Docker volumes in CI.
- **Docs-only benchmark guidance**: sentence-transformers ships MTEB *usage* docs (`docs/sentence_transformer/usage/mteb_evaluation.md`) but runs no MTEB in CI — quality is library-correctness, not score-regression.

## Notes / caveats (be honest about thin evidence)

- **Nobody found runs MTEB/BEIR as a blocking per-PR CI gate.** The strongest automated practice is vLLM's STS12 parity test (a single MTEB task, run via pytest — its CI scheduling beyond "in the suite" was not verified). TEI's nightly is hardware integration, not score regression. Claim "benchmark gates in CI" would overstate; the real pattern is *parity/consistency tests in CI + benchmark numbers reported per release*.
- **FlagEmbedding has essentially no test CI** (`.github/workflows/` contains only `documentation.yml`). Its value here is the benchmark/reporting discipline and the model zoo, not CI structure.
- **Weight-pinning practice is weak across the board**: none of the serving repos pin HF revisions in-repo; reproducibility is via pinned *toolchains/scores*, not pinned weights. A clean-room project should treat this as a gap to do better than, not copy.
- **Reranker/late-interaction CI specifics are thin**: infinity and TEI both serve rerankers and ColPali-class models, but their public CI shows generic unit/e2e stages, not reranker-specific quality gates. The multi-vector test packages in sentence-transformers (`tests/multi_vector_encoder/`) and vLLM (`tests/entrypoints/pooling/token_embed/`) are the best concrete pointers.
- Late-interaction serving evidence leans on stanford-futuredata/ColBERT (last push 2025-10-14, slower cadence) — the *reference implementation* is less active than the *serving* repos around it; trend strength for ColBERT-class serving comes more from infinity/TEI/fastembed supporting multi-vector models than from ColBERT itself.
- Star counts and push dates are point-in-time (2026-09-23); TEI's 2026-dated CI files and vLLM's 92k stars reflect the simulated "current" date and should be re-verified if quoted later.
