# Browser-use stacks - evidence

Research date: 2026-09-23. Every repo verified via GitHub API (repo metadata endpoint) and raw-file/dir listing fetches. Repos that 404'd (browserbase/sdks, langchain-ai/web-voyager, hyperbrowser-ai/sdk) were dropped.

## Trend (one line per repo: owner/repo | stars | last push | why it evidences the trend)

1. **browser-use/browser-use** | 116,059 | 2026-09-18 | Largest agent-browser OSS project; flagship "agents that use the browser" library; ships its own cloud eval platform triggered per-PR (`.github/workflows/eval-on-pr.yml`).
2. **microsoft/playwright-mcp** | 37,504 | 2026-09-18 | Microsoft's official Playwright MCP server — evidences the trend shifting from libraries to agent-native browser tool servers (accessibility-tree-first observation model).
3. **browserbase/stagehand** | 25,315 | 2026-09-23 | Browserbase's SDK for extract/act/observe/agent on any site; ships a first-class in-repo eval harness (`packages/evals`) with dataset-backed benchmark suites — the trend's most eval-driven project.
4. **Skyvern-AI/skyvern** | 23,057 | 2026-09-23 | VC-scale agent workflow automation with a commercial cloud twin; ships WebVoyager/Odysseys benchmark datasets in-repo (`evaluation/datasets/`).
5. **browserless/browserless** | 13,732 | 2026-09-22 | Headless-browser-as-a-service (Docker/Chrome/Firefox/WebKit matrices); evidences the infra layer of the trend: browser farms purpose-built for agent workloads.
6. **steel-dev/steel-browser** | 7,684 | 2026-09-21 | Open-source "Browser API for AI Agents & Apps" — headless browser sandbox with session model; the Steel-class archetype (sessions, CDP, proxy/stealth, extensions).
7. **tinyfish-io/agentql** | 1,467 | 2026-09-18 | Query-language + Playwright integration for AI web access; evidences the trend's diversification into structured-query interfaces over raw DOM.
8. **web-arena-x/webarena** | 1,613 | 2025-11-26 | Benchmark side: realistic web environments + evaluation harness (`evaluation_harness/evaluators.py`) used to score agents — evidences that the category is benchmarked, not just built.
9. **OSU-NLP-Group/Mind2Web** | 1,029 | 2025-11-05 | The original LLM web-agent benchmark dataset/codebase (`src/action_prediction`, `src/candidate_generation`); still bundled as static eval data inside newer projects (e.g. browser-use `tests/mind2web_data/processed.json`), evidencing benchmark lineage.

## Process practices worth copying (practice | repos exhibiting it | file pointers)

1. **Separate unit vs. real-browser integration suites; never let them mix in one config** | stagehand | `browserbase/stagehand/vitest.config.ts` (comment: "Integration specs launch real Chrome and are owned solely by vitest.integration.config.ts… Without this they would also be swept up by the packages/sdk-ts/tests/** glob… and run as part of the cacheable unit suite"); root has both `vitest.config.ts` and `vitest.integration.config.ts`.
2. **Ship a local deterministic test server instead of hitting the live web in unit tests** | microsoft/playwright-mcp | `microsoft/playwright-mcp/tests/testserver/index.ts`, wired in via `tests/fixtures.ts` (imports `TestServer`); CI matrix runs on ubuntu/macos/windows against it — no external-network dependency for core specs.
3. **Define agent tasks as declarative YAML with judge criteria + LLM-as-judge; community-contributable** | browser-use | `browser-use/browser-use/tests/agent_tasks/README.md` (task format: `name`/`task`/`judge_context`/`max_steps`; "The agent's output will be judged by an LLM using these criteria"), tasks `tests/agent_tasks/*.yaml`, runner `tests/ci/evaluate_tasks.py` (parallel subprocesses, "Each task gets its own Python process, preventing browser session interference").
4. **Trigger agent benchmarks on every PR against the PR commit** | browser-use | `.github/workflows/eval-on-pr.yml` — posts PR commit SHA/branch to an external eval platform (`api/triggerInteractionTasksV6`); browser-use/test.yaml gates test sharding, chromium binary caching by week (`~/.cache/ms-playwright`, weekly cache key), and per-test retries (`nick-fields/retry@v3`, `continue-on-error` on some jobs).
5. **In-repo eval package with auto-discovered task suites, dataset-backed benchmarks, and run logging** | stagehand | `browserbase/stagehand/packages/evals/` — suites `suites/{webvoyager,onlineMind2Web,webtailbench,odysseysbench,hardbenchmark}.ts`, task auto-discovery from `tasks/bench/<category>/`, TUI `evals` binary; runs stream to Braintrust (`BRAINTRUST_API_KEY`) for experiment diffing, else local summary (`packages/evals/README.md` § "Tracing / Observability"); `--preview` flag resolves a plan without spending LLM calls.
6. **Bundle third-party benchmark datasets in-repo and keep provenance** | Skyvern-AI/skyvern | `Skyvern-AI/skyvern/evaluation/datasets/` (`webvoyager_tasks.jsonl`, `odysseys_tasks.json`, `ODYSSEYS_ATTRIBUTION.md`), runner scripts in `evaluation/script/` (`eval_webvoyager_task_v2.py`); BrowserGym ships env bundles instead: `ServiceNow/BrowserGym/browsergym/{webarena,webarena_verified,webarenalite,miniwob,assistantbench,visualwebarena}`.
7. **Gym-style experiment loop + typed benchmark configs** | ServiceNow/BrowserGym | `browsergym/experiments/src/browsergym/experiments/{loop.py,agent.py,benchmark/}`; benchmark metadata/configs at `benchmark/configs.py`, `benchmark/metadata/`; tests mirror the env tree at `ServiceNow/BrowserGym/tests/{core,webarena,miniwob,assistantbench,visualwebarena}`; CI runs `unit_tests.yml`.
8. **Session recording/replay as a first-class tested feature** | browser-use | `browser_use/agent/gif.py` (GIF export), `tests/ci/test_action_record.py` — "The watchdog drives CDP screencast (`Page.startScreencast`/`stopScreencast`)… to produce an MP4. These tests exercise the full stack against a real headless browser"; also `browser_use record` CLI. (Replay-as-evidence for debugging flaky agent runs.)
9. **Change-aware CI: only run expensive browser/eval jobs when relevant paths changed; label-based skip** | stagehand | `.github/workflows/ci.yml` — `dorny/paths-filter` per-package (`packages/evals/**`, `packages/sdk-ts/**`…), `skip-evals` / `skip-regression-evals` PR labels, `cancel-in-progress` concurrency; job split `unit-ts` / `browser-ts` / `integration` / `regression-evals` (90-min timeout).
10. **Cross-OS, cross-browser Docker matrices for the browser farm itself** | browserless | `.github/workflows/docker-{chrome,chromium,edge,firefox,webkit,multi}.yml`, `leak-check.yml` (memory-leak regression for long-lived headless sessions), `pr-checks.yml`; playwright-mcp mirrors the practice with a 3-OS CI matrix (`.github/workflows/ci.yml`: `os: [ubuntu-latest, macos-15, windows-latest]`, `npx playwright install --with-deps`).

## Notes / caveats (be honest about thin evidence)

- **Flakiness practices were thin in what I could verify.** The clearest concrete mechanisms: per-test retry in CI (browser-use `nick-fields/retry@v3` in test.yaml), per-PR agent benchmarks quarantined off the unit path (browser-use eval-on-pr.yml; stagehand's `regression-evals` job separate from `unit-ts`), weekly browser-binary caching (browser-use), and `--preview`/Braintrust run-diffing (stagehand). No repo I checked documents an explicit flake-rate budget or quarantined-flake labeling scheme — that would be a differentiator to design, not copy.
- **Determinism for LLM-driven tests is mostly "replay the benchmark, not the model."** Nobody I verified ships recorded LLM responses (no VCR-cassette-style fixtures found); determinism is achieved via deterministic test servers (playwright-mcp), isolated browser sessions per task (browser-use), and experiment logging for diffing (stagehand/Braintrust).
- **Steel evidence is shallow.** `steel-dev/steel-browser` verified as real/active with a vitest config at `api/vitest.config.ts`, but I did not locate an in-repo test directory or eval suite — cite it for trend, not process.
- **Adopter claims avoided.** Stars + push dates + shipped eval infrastructure are the verified trend evidence; I did not verify "notable adopters" claims (press-release style claims aren't traceable via API).
- **Benchmark repos are slower-moving.** webarena and Mind2Web last pushed Nov 2025 — still current as benchmark standards (vendored into active projects' test data), but not fast-moving codebases.
- **Skyvern's evaluation scripts reference their commercial task store** (`create_webvoyager_task_v2.py` etc. post to Skyvern infra); the in-repo pieces are the datasets + attribution, not a fully self-contained runner.
