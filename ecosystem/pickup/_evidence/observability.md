# Agent observability/tracing - evidence

Research date: 2026-09-23. Every repo below verified live via the GitHub API on that date. Stars and push timestamps are as returned by `api.github.com/repos/<owner>/<repo>`.

- **comet-ml/opik** | 22,207 | 2026-09-23 | Comet's OSS tracing/eval platform for LLM and agent workflows; active same-day development. Proves a major commercial ML platform (Comet) ships its observability layer open-source.

- **Helicone/helicone** | 6,175 | 2026-09-16 | Proxy-based observability (one-line base-URL change → request logs, cost, caching, evals). Proves a second viable capture architecture (proxy vs SDK instrumentation), both open-source.

- **openlit/openlit** | 2,790 | 2026-09-22 | OTel-native auto-instrumentation SDK (Python/TS/Go), self-hosted UI, GPU collector. Evidence of OTel-native + multi-language SDK convergence.

The "closed with open SDK" pattern (LangSmith, Braintrust) is the commercial norm; the OSS alternatives above are the process-evidence base.

## Process practices worth copying (practice | repos exhibiting it | file pointers)

1. **Scheduled ingestion-load benchmarks against a live local stack** | comet-ml/opik | `.github/workflows/load_tests.yml` (weekly cron, larger `ubuntu-latest-m` runner — comment documents OOM history on 7 GB runners), suite at `tests_load/suite/python_sdk/` (`test_ingestion_rate.py`, `test_bursts.py`, `test_heavy_payload.py`, `test_attachments.py`); methodology in `tests_load/README.md` — 100k traces × 1 span, 250k spans, 1 GB heavy payloads, burst + concurrency shapes. Copy: named ingestion shapes, not just unit tests.
2. **Per-provider OTel semantic-convention compliance tests with VCR cassettes** | traceloop/openllmetry | `packages/opentelemetry-instrumentation-openai/tests/traces/` — `test_semconv_compliance.py`, `test_span_context_propagation.py`, plus `cassettes/` for deterministic replay (35+ sibling packages repeat the pattern). Copy: semantic-convention assertions per instrumented provider, not just "spans exist".
3. **Span-lifecycle and streaming-token tests** | openlit/openlit | `sdk/python/tests/` — `test_openai_streaming_span_lifecycle.py`, `test_anthropic_stream_span_lifecycle.py`, `test_groq_stream_span_lifecycle.py`, `test_instrumentor_names.py`, `test_provider_version_hash_coverage.py`. Copy: explicit tests that streaming spans close correctly and carry token-usage attributes.
4. **OTel exporter/span-processor unit tests in the SDK** | langfuse/langfuse-python, lmnr-ai/lmnr-python, langchain-ai/langsmith-sdk | `langfuse/langfuse-python: tests/unit/test_otel.py`, `test_span_processor.py`, `test_propagate_attributes.py`, `test_mask_otel_spans.py`; `lmnr-ai/lmnr-python: tests/test_exporter.py`, `test_batch_processor.py`, `test_otel_initialization.py`, `test_context_propagation.py`, `tests/cassettes/`; `langchain-ai/langsmith-sdk: python/tests/unit_tests/test_otel_exporter.py`, `test_hybrid_tracing.py`, `test_span_utils.py`, `test_run_trees.py`. Copy: test the OTel export path as a first-class unit surface (masking, batching, context propagation, hybrid run-tree/span models).
5. **Split unit / e2e / live-provider test tiers** | langfuse/langfuse-python, comet-ml/opik | `tests/unit/`, `tests/e2e/`, `tests/live_provider/` (langfuse-python); Opik runs `python_sdk_unit_tests.yml`, `python_sdk_e2e_tests.yml`, `end2end_suites_v2.yml`, `python_sdk_compatibility_v1_e2e_tests.yml` as separate workflows, plus `tests_end_to_end/` with `TESTING-TAGS.md`, `coverage/`, `visual-tests/`. Copy: tiered workflows so PR checks stay fast and heavy e2e runs post-merge/scheduled.
6. **Per-integration test matrix** | comet-ml/opik | ~25 `lib-*-tests.yml` workflows (`lib-openai-tests.yml`, `lib-langchain-tests.yml`, `lib-crewai-v1-tests.yml`, `lib-adk-tests.yml`, …) plus `installation_tests.yml`. Copy: each supported framework integration gets its own workflow file — cheap parallelism, clear ownership.
7. **Per-language CI split in a polyglot repo** | openlit/openlit | `ci-python.yml`, `ci-typescript.yml`, `ci-go.yml`, `ci-gpu-collector.yml`, `ci-cli.yml`, `ci-controller.yml` (+ `security-oss-boundary.yml`). Copy: one workflow per SDK language instead of a monolith.
8. **OpenAPI/SDK contract checks in CI** | langfuse/langfuse | `.github/workflows/sdk-api-spec.yml`, `openapi-export-check.yml` (verified in workflow listing). Copy: generate the spec from the server and diff it — client/server drift is the classic ingestion-breakage vector.
9. **Scheduled model-price audit (cost-tracking correctness)** | langfuse/langfuse, comet-ml/opik | `langfuse/langfuse: .github/workflows/model-price-audit.yml` (daily cron, Claude-driven audit of default model prices with a spend cap); `comet-ml/opik: .github/workflows/span_cost_upload_daily.yml`. Copy: cost tracking needs its own scheduled correctness job — prices change under you.
10. **Trace-completeness via e2e coverage + visual tests** | comet-ml/opik | `tests_end_to_end/{coverage,visual-tests}/` and `end2end_suites_v2.yml`; Phoenix runs `playwright.yaml` for UI trace-view verification. Copy: verify end-to-end that ingested spans actually render as complete traces in the UI, not just that the API returned 200.

## Notes / caveats (honest assessment)

- **The category's commercial core is thin on open evidence by design.** LangSmith (the "LangSmith-class" namesake) is closed-source hosted; only its client SDKs (`langchain-ai/langsmith-sdk`) are open. Braintrust and similar players have no OSS backend to study. The process evidence above therefore comes overwhelmingly from the OSS-alternative tier (Opik, Langfuse, OpenLLMetry, OpenLit, Laminar, Phoenix) — good news for a clean-room project, since that's exactly the tier whose code and CI you can copy.
- **"OTel-compatible" is asserted more than proven.** Only OpenLLMetry has explicit semconv-compliance tests (`test_semconv_compliance.py`); most platforms claim OTel ingestion in docs without a visible conformance suite in the repo. Treat ingestion-interop claims as marketing until you see the test file.
- **Load testing is the exception, not the norm.** Opik's `tests_load/` suite is the only ingestion-load benchmark found among these repos; no other repo showed a comparable scheduled load suite. If you build this, you'll be copying the single best example, not a consensus practice.
- **Langtrace is stale** (last push 2025-11-17) — included as a recency filter warning, not a model to copy.
- **Verification method:** all star counts, push timestamps, and file paths above were read from `api.github.com` (repo + contents endpoints) and `raw.githubusercontent.com` on 2026-09-23. GitHub code search (unauthenticated) was unavailable, so per-symbol claims inside test files were not verified — file names and workflow contents were.
