# Realtime voice-agent stacks - evidence

All repos below verified via `https://api.github.com/repos/<owner>/<repo>` and `.../contents/...` (2026-09-23). Star counts and `pushed_at` are from the API that day. vocode-ai/vocode 404s (deleted/renamed — dropped per rules).

## Trend (owner/repo | stars | last push | why it evidences the trend)

- `pipecat-ai/pipecat` | 15,807 | 2026-09-23 | Flagship open-source voice-agent pipeline framework ("Open Source framework for voice agents, multimodal apps, and realtime AI"), maintained by Daily and the community; pushed same-day as verification.
- `livekit/agents` | 14,328 | 2026-09-23 | LiveKit's framework for building realtime voice AI agents; pushed same-day; plugin tree covers ~40 STT/LLM/TTS providers (deepgram, cartesia, elevenlabs, assemblyai, soniox, telnyx...), evidence of ecosystem breadth.
- `TEN-framework/ten-framework` | 11,141 | 2026-09-22 | "Open-source framework for conversational voice AI agents"; heavy multi-OS CI matrix (linux/mac/win × arm64/x64) plus AI-agent-review workflows (`claude_code_review.yml`, `codex_code_review.yml`).
- `openai/openai-agents-js` | 3,852 | 2026-09-23 | OpenAI's own "lightweight, powerful framework for multi-agent workflows and voice agents"; pushed same-day; signal that a first-party vendor ships voice-agent orchestration.
- `openai/openai-realtime-console` | 3,614 | 2025-08-28 | React app for inspecting/building/debugging with the OpenAI Realtime API — vendor tooling for the realtime speech-to-speech path, though less actively pushed than the frameworks above.
- `livekit/livekit` | 21,065 | 2026-09-23 | Underlying realtime media transport (SFU) the agent frameworks ride on; the stack is transport + agent orchestration, both actively maintained.
- `ServiceNow/eva` | 216 | 2026-09-23 | ServiceNow AI research repo: "A New End-to-end Framework for Evaluating Voice Agents" with an arXiv paper, public leaderboard, and HuggingFace dataset — institutional money flowing into voice-agent evaluation.
- `saharmor/voice-lab` | 176 | 2025-06-04 | Independent "Testing and evaluation framework for voice agents" with LLM-as-a-judge metrics, web eval UI, and test-scenario JSON — third-party tooling exists for the category (note: last push 2025-06, less active).

## Process practices worth copying (practice | repos exhibiting it | file pointers)

- **Fake/mock service doubles for every pipeline stage** — livekit/agents: `tests/fake_stt.py`, `tests/fake_llm.py`, `tests/fake_tts.py`, `tests/fake_realtime.py`, `tests/fake_session.py`, `tests/fake_io.py`, `tests/fake_vad.py`, `tests/fake_turn_detector_ws.py`. Tests run deterministic agent sessions without API keys or network.
- **Latency metric classes with their own unit tests** — pipecat: TTFA (time-to-first-audio) detected via RMS speech-onset detector on PCM buffers, `tests/test_ttfa_metrics.py` (uses `pipecat.audio.utils.detect_speech_onset`, `pipecat.metrics.metrics.TTFAMetricsData`); sibling suites `tests/test_ttfat_metrics.py` (time-to-first-audio-token) and `tests/test_ttfb_metrics.py` (time-to-first-byte); runtime observers `tests/test_user_bot_latency_observer.py`, `tests/test_speaking_observer.py`.
- **E2E latency handoff test through the full pipeline** — livekit/agents: `tests/test_e2e_latency_handoff.py`.
- **Dedicated interruption / turn-taking test surface** — livekit/agents: whole `tests/test_interruption/` directory plus `tests/test_false_interruption_resume.py`, `tests/test_interrupt_protected_speech.py`, `tests/test_disallow_interruptions_pause.py`, `tests/test_interruption_hold_window.py`; realtime-model variants in `tests/test_realtime/` (`test_realtime_input_speech_interrupt.py`, `test_realtime_interrupt_cancels_generation.py`, `test_realtime_overlapping_speech.py`, `test_realtime_adaptive_interruption.py`).
- **Virtual time for deterministic timing tests** — livekit/agents: `tests/virtual_time.py` (fake clock so turn-taking/latency assertions don't flake on real-time scheduling).
- **Live-provider integration tests gated on secrets** — livekit/agents: `.github/workflows/test-realtime.yml` runs `pytest --realtime` against OpenAI/Azure realtime APIs using repo secrets, path-triggered only by realtime-code changes, skipped on forks; `tests/test_realtime/` is the live-side suite. (Workflow content viewed via raw.githubusercontent.com.)
- **Separate STT conformance workflow, runnable on demand** — livekit/agents: `.github/workflows/test-stt.yml` (workflow_dispatch + `issue_comment` slash-command trigger, path-scoped to `tests/test_stt.py`).
- **Eval harness with LLM judge run in CI** — livekit/agents: `.github/workflows/evals.yml` (matrix over example apps `frontdesk`, `drive_thru`, runs on push to main and every PR) + `tests/test_evals.py`, `tests/test_judge.py`; pipecat: whole `tests/test_evals_*.py` family (`test_evals_harness_shim.py`, `test_evals_judge.py`, `test_evals_simulation.py`, `test_evals_scenario.py`, `test_evals_suite.py`, `test_evals_session.py`, `test_evals_transport.py`, `test_evals_client_transport.py`).
- **Scenario-based e2e evaluation architecture (bot-to-bot calls)** — ServiceNow/eva: `src/eva/{assistant,backend,user_simulator,orchestrator,metrics,models,role}/`, `src/eva/run_benchmark.py`, `src/eva/cli.py`; 213 enterprise scenarios targeting voice-specific failure modes; perturbation suite (background noise, accents, connection degradation) — copy the pattern of simulating the *caller*, not just unit-testing the pipeline.
- **Interruption/pause metrics as first-class eval dimensions** — saharmor/voice-lab: `speech_testing/metrics/{interruptions.py,interruptions_utils.py,pauses.py}`, `speech_testing/run_tests.py`, `web_test_scenarios.json`, custom JSON-defined LLM-as-a-judge metrics.
- **Test helper libraries co-located with tests** — pipecat: `tests/frame_processor_helpers.py`, `tests/flows_test_helpers.py`, `tests/aic_mocks.py`, `tests/openai_http_helpers.py`, `tests/openclaw_fake_gateway.py`; livekit: `tests/conftest.py`, `tests/fake_*`, `tests/toxic_proxy.py` (toxiproxy fault-injection, `tests/Dockerfile.toxiproxy`), `tests/docker-compose.yml` + `tests/lk_server.py` (spin real LiveKit server in tests).
- **Fault injection / network degradation in tests** — livekit/agents: `tests/toxic_proxy.py` + `Dockerfile.toxiproxy`; ServiceNow/eva: perturbation suite including simulated connection degradation.
- **CI matrix + concurrency hygiene** — pipecat: `.github/workflows/tests.yaml` (uv, py3.12, 30-min timeout, `cancel-in-progress: true`, concurrency group per PR), plus `coverage.yaml`, `python-compatibility.yaml`, `format.yaml`, `license-check.yaml`, `provider-watch.yml` (watches upstream provider SDK changes — relevant for a plugin-heavy stack); TEN-framework: per-OS tman workflows (`tman_full_linux_arm64.yml`, `tman_full_win_x64.yml`, …) plus `manual_test_asr_guarder.yml`.
- **Integration tests per runtime target** — openai/openai-agents-js: `integration-tests/` with per-target suites (`node*.test.ts`, `deno.test.ts`, `bun.test.ts`, `cloudflare.test.ts`, `react-native.test.ts`, `vite-react.test.ts`) plus separate `vitest.integration.config.ts`.

## Notes / caveats

- No repo was cited from memory; everything above came from live API/contents calls on 2026-09-23. vocode-ai/vocode 404s and was dropped — do not cite it.
- **Latency measurement is thinner than the category deserves:** pipecat's TTFA/TTFAT/TTFB metric tests are the best in-repo practice found; livekit measures e2e latency in `test_e2e_latency_handoff.py` and end-of-turn metrics (`tests/test_end_of_turn_metrics.py`) but I did not find a published time-to-first-audio *benchmark dashboard* or regression gate in either repo. Latency is tested, not gated.
- ServiceNow/eva is research-grade (arXiv + leaderboard + HF dataset) but only 216 stars and narrow domain; treat as evaluation-methodology reference, not a framework.
- saharmor/voice-lab's last push is 2025-06-04 — useful for interruption/pause metric *ideas*, stale as a dependency.
- openai-realtime-console is vendor debugging UI, not a pipeline framework; included for trend only.
- For a clean-room project, the highest-value copies are: (1) the fake-doubles harness pattern (livekit `tests/fake_*`), (2) pipecat's TTFA metric classes as test fixtures, (3) interruption test matrices + virtual time, (4) a secrets-gated live-provider workflow separate from unit CI, and (5) eva's bot-to-bot caller-simulation architecture for e2e evals.
