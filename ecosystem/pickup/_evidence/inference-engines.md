# LLM inference engines - evidence

All repos verified via `GET https://api.github.com/repos/<owner>/<repo>` on 2026-09-23 (stars, `pushed_at`, description taken from API; repo-tree listings via the `contents/` API). File pointers are `owner/repo/path` as seen at current main/HEAD.

## Trend (owner/repo | stars | last push | why it evidences the trend)

- `vllm-project/vllm` | 92,527 | 2026-09-23 | Category flagship; API description "A high-throughput and memory-efficient inference and serving engine for LLMs". Its `benchmarks/benchmark_serving.py` is the de-facto throughput benchmark other projects clone.
- `sgl-project/sglang` | 36,377 | 2026-09-23 | LMSYS-lab challenger ("high-performance serving framework for large language models"), fastest-growing vLLM-class alternative; CI volume (~130 workflow files, per-vendor nightly GPU fleets) evidences production-serious maintenance.
- `nvidia/TensorRT-LLM` | 14,703 | 2026-09-23 | NVIDIA's official inference/serving stack; the vendor-tuned reference implementation for this category, still pushing same-day.
- `huggingface/text-generation-inference` | 10,884 | 2026-03-21 | Hugging Face's own serving engine. Verified multi-backend pivot: `backends/{v2,v3,trtllm,llamacpp,gaudi,neuron}` shows the incumbent converging on pluggable vLLM-class backends rather than its Rust core alone.
- `InternLM/lmdeploy` | 8,094 | 2026-09-23 | "Toolkit for compressing, deploying, and serving LLMs"; active daily E2E test matrix pinned to GPU SKUs (see workflows below).
- `ggml-org/llama.cpp` | 129,316 | 2026-09-23 | "LLM inference in C/C++"; the reference engine whose `tools/llama-bench`, `tools/perplexity`, and `tools/server` define the correctness/perf baseline the serving engines measure against.
- `ollama/ollama` | 181,524 | 2026-09-23 | Consumer-facing runner (highest-starred repo in the set) that vendors llama.cpp with pinned versions (`LLAMA_CPP_VERSION`, `MLX_VERSION`, `MLX_C_VERSION`); evidences the distribution/packaging layer of the trend.
- `mlc-ai/mlc-llm` | 23,183 | 2026-08-17 | "Universal LLM Deployment Engine with ML Compilation"; the ML-compilation (TVM-lineage), cross-device branch of the trend (android/, ios/, web/ targets in tree).

## Notes / caveats (be honest)

- **Aphrodite Engine dropped.** Neither `aphrodite-engine/aphrodite-engine` nor `alpinelabs/aphrodite-engine` resolved via the GitHub API; a repository search for it also returned nothing verifiable. Not cited rather than cited from memory.
- **TGI is going stale.** Last push `2026-03-21` — six months behind every other repo here (all pushed within the last ~36h). Evidence of the trend pivoting: HF's maintenance effort is now the multi-backend v3 (`backends/v3/`) that reuses vLLM-class engines.
- **llama.cpp has no enabled benchmark CI.** `ggml-org/llama.cpp/.github/workflows/bench.yml.disabled` exists but is disabled; the field's reference engine currently measures perf in-repo (`tools/llama-bench`, `tools/perplexity`) without an automated perf gate.
- **mlc-llm has the thinnest benchmark evidence.** No `benchmark/` directory at repo root; `.github/workflows/` is only `lint.yml`, `documentation.yaml`, `update-relax.yaml`, `windows-build.yaml` (CI largely lives in `ci/jenkinsfile.groovy`). It evidences the cross-device/compilation branch of the trend, not benchmark practice.
- **Ollama is a distribution layer, not a batching/serving engine.** Its copy-worthy practices are dependency pinning and Go `integration/` tests, not scheduling, KV-cache management, or perf regression gates.
- **Star counts and `pushed_at` above are point-in-time values from the GitHub API on 2026-09-23, not live guarantees.**
