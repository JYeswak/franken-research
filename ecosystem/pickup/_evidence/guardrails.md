## Process practices worth copying (practice | repos exhibiting it | file pointers)

1. **Split attack generation from success detection** — one team's probes, another's judges: `NVIDIA/garak` | `garak/garak/probes/*.py` (attack generators) vs `garak/garak/detectors/*.py` (judges: `judge.py`, `mitigation.py`, `unsafe_content.py`, `knownbadsignatures.py`); tests mirror the split (`garak/tests/probes/`, `garak/tests/detectors/`). A clean-room guardrail should have `attacks/` and `verdicts/` that never share code paths.
2. **Rail-level QA tests gated behind an env flag, run against real example configs** — `NVIDIA-NeMo/Guardrails` | `qa/test_jailbreak_check.py`, `qa/test_moderation_rail.py`, `qa/test_topical_rail.py`, `qa/test_grounding_rail.py`, `qa/test_execution_rails.py` — each subclasses `ExampleConfigChatterTestCase` and is `skipif(not QA_MODE)`. Copy: one test file per rail type, full conversation traces, real-LLM QA tier separated from unit tier.
3. **Dedicated evaluator dirs inside the main test tree** — `NVIDIA-NeMo/Guardrails` | `tests/evaluate/test_evaluate_topical.py`, `tests/eval/test_evaluate_cli_and_data.py`, `tests/evaluate/test_evaluate_runtime_classes.py`. Copy: topical/false-positive rail evals as first-class tests, not docs.
4. **Scanner accuracy + latency benchmark over JSON corpora** — `protectai/llm-guard` | `benchmarks/run.py` (timeit-based, builds each scanner, runs over corpora) + `benchmarks/input_examples.json` + `benchmarks/output_examples.json`. Copy: every scanner ships with a labeled example corpus and a timing harness.
5. **Per-scanner unit-test directories + parametrized pass/fail matrices** — `protectai/llm-guard` | `tests/input_scanners/`, `tests/output_scanners/`, `tests/test_evaluate.py` (parametrized `(prompt, expected_results)` pairs covering valid prompts and blocked prompts). Copy: FP/FN cases live in code as parameters, not in a spreadsheet.
6. **Attack-plugin and evasion-strategy taxonomies as enumerated modules** — `promptfoo/promptfoo` | `src/redteam/plugins/*.ts` (~50 plugins: jailbreak, PII, policy, compliance, hallucination) + `src/redteam/strategies/*.ts` (crescendo, bestOfN, gcg, multilingual, encodings). Copy: enumerate attack families as named modules with per-module metadata; new jailbreak class = new file.
7. **Static jailbreak + seed-prompt datasets versioned in-repo, with scorer-eval sets** — `microsoft/PyRIT` | `pyrit/datasets/jailbreak/`, `pyrit/datasets/seed_datasets/`, `pyrit/datasets/scorer_evals/`, `pyrit/score/`. Copy: keep the attack corpus and the judge-calibration set (`scorer_evals`) as separate, versioned artifacts.
8. **Behavior datasets + classifier validation sets for the LLM judge itself** — `centerforaisafety/HarmBench` | `data/behavior_datasets/`, `data/classifier_val_sets/`, `evaluate_completions.py`, `eval_utils.py`. Copy: the judge that scores refusal gets its own FP/FN calibration set; judge drift is measured, not assumed.
9. **Validators hub + spec-language conformance tests** — `guardrails-ai/guardrails` | `tests/unit_tests/hub/`, `test_spec.rail`, `tests/integration_tests/` (with `mock_llm_outputs.py`, `mock_embeddings.py`, `mock_presidio.py`), plus `server_ci/`. Copy: mock-LLM-output fixtures so rail logic tests don't need live models; keep a machine-readable spec test for the rail language.
10. **Recorded LLM fixtures (VCR-style replay)** — `NVIDIA-NeMo/Guardrails` | `tests/recorded/` + per-integration fixtures (`llama_guard_fixtures.py`, `policyai_fixtures.py`). Copy: record once, replay in CI; rails' LLM calls never hit the network in unit tests.
11. **CI split by tier and concern** — `NVIDIA-NeMo/Guardrails` | `.github/workflows/{pr-tests.yml,full-tests.yml,_coverage.yml,latest-deps-tests.yml,test-docker.yml,lint.yml,codeql.yml}`; `guardrails-ai/guardrails` | `.github/workflows/{ci.yml,premerge.yml,examples_check.yml,dependency-audit.yml,cli-compatibility.yml,server_ci.yml}`. Copy: PR-fast suite, full suite, latest-deps suite, examples-check (docs examples must run), dependency audit — as separate workflows, not one matrix.
12. **Agent-level tool-call gating as a distinct rail family** — `meta-llama/PurpleLlama` | `LlamaFirewall/` (src, tests, examples) and NeMo's execution rails (`qa/test_execution_rails.py`). Copy: guardrails for tool input/output are a separate category from prompt text rails.
