# Agent orchestration frameworks - evidence

All repos verified via GitHub REST API on 2026-09-23 (star counts / pushed_at snapshots from that day).
Rulebook compliance: no repo cited from memory; MetaGPT/MetaGPT 404'd on the API and was dropped.

## Trend (one line per repo: owner/repo | stars | last push | why it evidences the trend)

Pushed same-day = actively maintained.
- **langchain-ai/langchain** | 146,931 | 2026-09-23 | Ecosystem anchor: LangGraph sits inside the LangChain agent-engineering platform; activity on both repos same-day signals the category is healthy.
- **microsoft/autogen** | 61,123 | 2026-04-15 | Major Microsoft framework for multi-agent orchestration (autogen-agentchat/core/ext/studio packages). Last push ~5 months prior to check — still large but visibly slower; one secondary source (https://dev.to/saaro_net/multi-agent-orchestration-2026-langgraph-crewai-and-autogen-compared-34bd) says AutoGen development continued as AG2 / Microsoft Agent Framework, so treat "active" status cautiously.
- **crewAIInc/crewAI** | 58,949 | 2026-09-23 | Role-playing multi-agent orchestration framework; pushed same-day. Monorepo layout (`lib/crewai-core`, `lib/crewai-tools`, `lib/cli`) with per-package `tests/` dirs.
- **agno-agi/agno** | 42,319 | 2026-09-23 | "Build, run, and manage agent platforms" (formerly Phidata); pushed same-day. High star count evidences demand for agent-runtime/orchestration layers beyond the top-3 names.
- **huggingface/smolagents** | 29,462 | 2026-09-23 | HF's barebones "agents that think in code" library (code-agent + tool-calling loops); pushed same-day. Shows the category includes minimal agent-loop implementations, not just heavy frameworks.
- **openai/openai-agents-python** | 29,656 | 2026-09-23 | OpenAI's own "lightweight, powerful framework for multi-agent workflows" (hopper/handoff-style orchestration); pushed same-day. First-party vendor validation of the category.

## Process practices worth copying (practice | repos exhibiting it | file pointers)

1. **Ship scripted/deterministic LLM doubles as a first-class, importable test API** | openai-agents-python | `src/agents/testing/__init__.py` (module docstring: "Deterministic test doubles for Agents SDK workflows"; exports `ScriptedModel`, `ModelStepSpec`, `ModelStep`, `assistant_message`, `function_call` builders, `UnconsumedModelSteps`, `UnexpectedModelCall`), `src/agents/testing/model.py`, `src/agents/testing/sandbox.py` (`ScriptedSandboxSession`). Copy: make the fake model part of the SDK so downstream users can test agents deterministically too.
2. **Hand-rolled fake models returning canned per-scenario LLM output** | smolagents | `tests/test_agents.py` lines ~115–855: ~15 subclasses of `Model` (`FakeToolCallModel`, `FakeCodeModel`, `FakeCodeModelError`, `FakeCodeModelSyntaxError`, `FakeCodeModelImport`, `FakeLLMModel`, …), each producing a canned tool-call/code trajectory so agent-loop behavior is asserted without any network call. Copy: one fake per trajectory scenario, not one generic fake.
3. **Canned message-sequence fake chat model for graph/agent tests** | langgraph | `libs/langgraph/tests/fake_chat.py`: `FakeChatModel(GenericFakeChatModel)` cycles through a scripted `messages` list on each call, supports `bind_tools`, streaming, and reset. Copy: scripted sequence with a pointer index, explicit wrap-around semantics.
4. **Strict scripted-model contract: fail on unexpected or unconsumed steps** | openai-agents-python | `src/agents/testing/__init__.py`: `UnconsumedModelSteps` (script had steps the run never used) and `UnexpectedModelCall` (run asked for a model call the script didn't define). Copy: turn drift between test script and agent trajectory into hard failures, not silent pass-throughs.
5. **Scripted sandbox for tool side effects** | openai-agents-python | `src/agents/testing/sandbox.py`: `ScriptedSandboxSession`, `scripted_sandbox_session`, `SandboxStepSpec`, `InvalidSandboxStep`, `UnexpectedSandboxCall`. Copy: deterministic doubles must cover tool execution, not just the LLM.
6. **LLM-client mocking at the provider adapter layer with scripted retry sequences** | smolagents | `tests/test_models.py` lines 334, 435–458, 509–516: `MagicMock()` on `InferenceClientModel.client.chat_completion`, `patch("smolagents.models.LiteLLMModel.create_client")`, `completion.side_effect=[rate_limit_error, rate_limit_error, mock_success_response]` for retry tests, `patch("litellm.router.Router")`. Copy: assert retry/backoff behavior via side-effect sequences.
7. **Snapshot tests for graph/agent outputs** | langgraph | `libs/langgraph/tests/__snapshots__/`, `libs/prebuilt/tests/__snapshots__/`. Copy: snapshot full agent state/stream output to catch unintended trajectory changes.
8. **Checkpoint conformance suite run against every state backend** | langgraph | `libs/checkpoint-conformance/tests/` (same suite exercised over sqlite/postgres/etc. backends); per-package tests at `libs/checkpoint/tests`, `libs/checkpoint-sqlite/tests`, `libs/checkpoint-postgres/tests`. Copy: nondeterminism-relevant state (checkpoints, resumability) needs a backend-agnostic conformance harness, not per-backend ad-hoc tests.
9. **Cross-LLM reliability tests with an LLM-judge and YAML model matrix** | dspy | `tests/reliability/README.md` (runs the same DSPy programs across multiple LLMs "regardless of model size or capability", with a configured judge model like GPT-4o), `tests/reliability/reliability_conf.yaml`, `tests/reliability/test_generated.py`, `tests/evaluate/test_auto_evaluation.py`, `tests/evaluate/test_evaluate.py`, `tests/evaluate/test_metrics.py`. Copy: separate reliability (behavioral, judge-graded) from unit tests; declare the model matrix in config, not code.
10. **Eval harness as a product feature, tested itself** | dspy | `tests/evaluate/` (test harness for `dspy.Evaluate`, metrics, auto-evaluation). Copy: if the framework ships an eval API, its own CI must exercise it.
11. **Serialization round-trip fixtures with versioned agent dicts** | smolagents | `tests/fixtures/agents.py` (`AGENT_DICTS["v1.9"]`, `["v1.10"]` — full agent serialization dicts used in tests). Copy: versioned fixtures catch schema drift in save/load of agent definitions.
12. **CI split: unit vs integration, per-package matrices, benchmarks in CI** | langgraph | `.github/workflows/`: `_test_langgraph.yml`, `_integration_test.yml`, `_sdk_integration_test.yml`, `bench.yml` (benchmarks as a workflow), `ci.yml`, `_lint.yml`. AutoGen: `.github/workflows/` has `integration.yml`, per-package workflows (`python-package-0.2.yml`, `single-python-package.yml`), service-backed test workflows (`pytest-redis-memory.yml`, `pytest-mem0.yml`). smolagents: `tests.yml`, `quality.yml`. Copy: unit tests cheap and always-on; integration (incl. Docker-backed: langgraph `tests/compose-*.yml`) and benchmarks gated separately; monorepo packages get their own workflow.
13. **Dedicated test-utils package** | autogen | `python/packages/autogen-test-utils/` (with `src/autogen_test_utils/telemetry_test_utils.py`). Copy: extract shared test scaffolding (tracing/telemetry assertions) into a package the tests import, rather than copying helpers across test files.

## Notes / caveats (be honest about thin evidence)

- **Trend breadth vs depth:** trend evidence is star-count + same-day push activity. Only LangGraph has verified production-adopter names (Klarna, Replit, Elastic, Ally from langchain.com's announcement; Klarna/Replit/Elastic corroborated by langfuse docs citing the langgraph README). Adopter claims for other frameworks are not verified here.
- **AutoGen is stale-ish:** last push 2026-04-15 (5 months before check). A secondary comparison article says development continued as AG2/Microsoft Agent Framework — unverified at the repo level. Do not cite autogen's main repo as "actively maintained" without that caveat.
- **MetaGPT dropped:** `MetaGPT/MetaGPT` 404'd on the API (renamed/moved/deleted); no replacement name was verified, so it is not cited at all.
- **Thin test evidence for crewAI and agno:** verified only the test-dir layout (crewAI: `lib/crewai-core/tests`, `lib/crewai-tools/tests`, `lib/cli/tests`) and existence; I did not enumerate their testing techniques, so practices from those two are not claimed.
- **Rate limit / method:** unauthenticated GitHub API (60 req/hr); all file pointers above were individually fetched and confirmed to exist. Star counts are point-in-time (2026-09-23 ~10:35 MDT).
- **What no repo showed clearly:** no project had an obvious record/replay (cassette) harness for LLM calls (smolagents uses hand fakes, not VCR-style cassettes); agent benchmark suites (e.g., WebArena-style e2e) were not found in the surveyed repos' test trees. That is a gap a clean-room project could fill rather than copy.
