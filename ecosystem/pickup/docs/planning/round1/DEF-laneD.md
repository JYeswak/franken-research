## Tier semantics

DEF-D-1 [P1] pickup-agent-memory.md:Evidence tiers + claim table — Tier mapping contradicts the playbook. The companion defines "T0 vendor · T1 independent · T2 self-reported · T3 aspirational," while the playbook mandates T0=[Verified], T1=[CI-observed], T2=[Maintainer claim]/[External], T3=[Inference]. Effect: file-verified in-tree evidence (e.g. CLAIM-5's `tests/llms/` counts, CLAIM-11's verified-absence adopter check) lands at T1, while vendor/maintainer material occupies the top tier T0. A reader applying the companion's legend would treat vendor self-reports as stronger than direct inspection — the inversion the Rulebook's v1.1 flavor rule ([CI-observed] stays Tier 2, never promoted) was written to prevent. Fix: replace the companion's tier legend with the playbook's T0–T3 mapping verbatim (or an explicit "per playbook §Claim/evidence governance" citation) and re-tier all 14 rows.

DEF-D-2 [P1] pickup-rag-frameworks.md:Evidence tiers + claim table — Same inversion as DEF-D-1 ("T0 vendor (Microsoft repos count as vendor here), T1 independent, T2 self-reported, T3 aspirational"). CLAIM-6 (azure-search-openai-demo CI-gated eval suite), CLAIM-10 (chunker snapshots), CLAIM-14 (graphrag monorepo) are tiered T0 with the companion's gloss "admissible as process evidence without further verification" — weaker than the playbook's T0 ([Verified] requires direct inspection of a fresh clone/API/live page), so maintainer material is over-tiered relative to the constitution. Fix: adopt the playbook mapping; these three rows become T0 only if re-pointed at file/API-verified evidence, otherwise T1 ([CI-observed]) per the Rulebook.

DEF-D-3 [P1] pickup-vector-dbs.md:Evidence tiers — Same inversion ("T0 vendor / T1 independent / T2 self-reported / T3 aspirational"). T1-independent is declared "the only tier admissible for 'faster than X' claims," but third-party harness results are Rulebook [External] (Tier 4 of 5), which the playbook maps to T2 — so the companion's admissibility rule contradicts the constitution's tier discipline. Meanwhile T0-vendor ("code-verified in-vendor artifacts") conflates [Verified] with maintainer-origin content. Fix: restate to the playbook mapping; make the competitive-claims tier T2-with-GATE-VDB-01–04 (as the playbook's T2 admits [External] with receipts), not T1.

DEF-D-4 [P1] pickup-eval-harnesses.md:Initial claims (CLAIM-*) table + Evidence tiers — Three colliding tier schemes in one file. The table header says "T0 vendor / T1 independent / T2 self-reported / T3 aspirational" (12 of 14 rows are labeled T2, including CLAIM-EH-01/02/03 whose evidence pointers are file/API-verified repo paths — i.e. self-reported per the header's own definition, while the Evidence tiers section defines "Tier 2 (CI-observed)" and "Tier 3 (maintainer/self-reported)"). So CLAIM-EH-01's T2 means "self-reported" under the header but "CI-observed" under the section — neither of which is [Verified], the tier the file-verified evidence actually supports. Fix: pick one scheme — the playbook's T0–T3 — and re-tier all rows consistently; under it, CLAIM-EH-01 through CLAIM-EH-12 (file/API-verified) are T0, CLAIM-EH-13 is T3, CLAIM-EH-14 is T0 (verified absence) or T2 per the playbook's [External]-absence rule.

DEF-D-5 [P1] PROJECT-PICKUP-PLAYBOOK.md:Claim/evidence governance — The parenthetical "(T2 merges the two 'asserted but unreproduced' classes; the mapping below is stated in every companion file)" is false as of this review: none of the four reviewed companions states the playbook mapping; all four substitute incompatible schemes (DEF-D-1 through DEF-D-4). DEF-D-6 [P2] pickup-agent-memory.md:Evidence tiers — `[External]` is listed as a parallel bullet ("The benchmark dataset repos when used as selection signals or third-party context rather than local oracles; absence of coverage is a finding") without being mapped to T0–T3, while the playbook explicitly merges [External] into T2.
