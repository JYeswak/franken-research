# IF-ENTRY: the index entry, `fr.search.entry/v1`

Owner: S03. Machine form: `IF-ENTRY.schema.json` (JSON Schema 2020-12). Examples: `IF-ENTRY.examples.json`.
Ids: IF-ID.md. Where each field is stored: IF-SHARD.md. Honesty rules on the values: IF-HONESTY.md. Prompt text: IF-PROMPT.md. Evidence mapping for fh and rigor-atlas: TIER-MAP.md.

The schema describes the **logical** entry, the one a result card renders. On disk the `quote` field lives in a separate shard (IF-SHARD.md); everything else ships in the core or deep shard.

## 1. Fields

R = required, O = optional. "Our words" means text written by Franken Research (this repo, or the snapshot catalogs our own agents authored), never verbatim text from Jeffrey's repositories; verbatim text only ever appears in `quote`.

| Field | R/O | Meaning |
|---|---|---|
| `schema` | R | Always `fr.search.entry/v1`. A client refuses entries of an unknown major version (IF-SHARD.md §5). |
| `id` | R | Namespaced stable id (IF-ID.md). The schema pattern is the union of the IF-ID regexes. |
| `kind` | R | One of 17 kinds (§2). The schema ties each id family to its kind, so `crate:` can only be `crate`. The kind picks the prompt template. |
| `title` | R | 3–140 characters, our words. For crates: `<name> <version>, Rust crate`. |
| `summary` | R | 20–600 characters, our words: what it is and why it matters. No verbatim text from Jeffrey's repositories (gate rule HON-12). |
| `copy.targets[]` | R | What to copy: 1–8 pinned targets `{label, repo, path, lines?, commit, url}`. `commit` is a 40-hex commit for any other repository and the release tag `v<version>` for this repository's own files (§4). `lines` is `N` or `N-M`. |
| `copy.command` | O | One shell command worth pasting (for example `cargo add asupersync@=0.6.0`). Allowed only where the posture permits adoption (HON-04). |
| `prompt.template` | R | Template id `<kind>/<variant>@<n>` that produced the text (IF-PROMPT.md). Gates use it to check the posture-to-template rule. |
| `prompt.text` | R | 40–1,600 characters: the "tell your agent" instruction, built at index time from our own fields by the template. Never generated by a model at query time (charter non-goal). |
| `posture` | R | What the reader may do with the thing the entry points at: `practice` (a pattern to adopt; no software dependency), `use`, `use-wrapped`, `pilot`, `patterns-only`, `do-not-depend`, `watch`, `reference-only`, `unassessed`. The schema requires `practice` for pattern kinds and forbids it for software kinds (repo-verdict, stack-verdict, crate, repo-profile, capability). Any verdict-derived posture requires `evidence.verdict`. |
| `evidence` | R | How far to trust it (§3). |
| `license` | R | License of the copy targets, from the repository's root `LICENSE` at the pinned commit (DEC-006), never from `Cargo.toml` or crates.io. `{class, label, rider, url, metadata_license?, checked}`. `class` ∈ `MIT`, `MIT+rider`, `Apache-2.0`, `none` (no LICENSE file: link only), `proprietary` (an explicit all-rights-reserved text), `other` (anything else, e.g. CC BY-NC-ND). `rider` is true exactly when the class is `MIT+rider`. `url` points at the LICENSE file at the commit, and is null only for class `none`. `metadata_license` records a conflicting manifest string (333 crates say `MIT` in metadata while their repo ships the rider; intake-IntakeEco2 §1c) so the card can say so. |
| `source_url` | R | GitHub blob or tree URL at a 40-hex commit (or this repo's release tag), with an optional `#Ln-Lm`. Never a branch; the schema pattern rejects `main`. |
| `url` | O (R for `fr:`) | On-site page relative to `site/`, e.g. `rigor/index.html#rp-009`, `briefs/asupersync.html`. It must resolve on disk with its fragment (gate Q1, same rule as gate E). |
| `links.crates_io`, `links.docs_rs` | O | Only for the 216 crates owned by Jeffrey's crates.io account (intake-IntakeEco2 §1b); name matching alone is forbidden because 4 of 30 sampled names belong to unrelated projects. |
| `credit.repos[]` | R | The upstream repository or repositories the item comes from, each `{name, url}`, per the charter's credit constraint. For our purely internal items (e.g. a failure mode across all 44) it lists this repository. |
| `provenance` | R | `{generator, source{name, path, sha256}, snapshot_date, pinned?}`. `generator` is `<script path>@<semver>`. `source.name` ∈ `fr-repo`, `fh-snapshot`, `ra-snapshot`, `crate-snapshot` and must match the id namespace. `sha256` is the hash of the source file the entry was built from (for the snapshots, the vendored file; IF-SOURCES.md §3). `snapshot_date` is the date the source was read. `pinned{commit, date}` is required for `fh:` and `crate:` entries and shown on every external card (UNK-009: pins are old and the card must say how old). |
| `quote` | O | A short verbatim quote (DEC-009): `{text, repo, path, lines, commit, url, license_class, license_notice, rider_flag}`. At most 480 characters and at most 6 lines (lines limit checked by gate Q3); `commit` 40-hex; `license_class` ∈ MIT, MIT+rider, Apache-2.0 (no quote from a repository with no grant); `rider_flag` true exactly for MIT+rider; `license_notice` carries the copyright line and a link to the LICENSE at the commit. Lives in the quotes shard only. |
| `facets` | O | Engine facets (repo, areas, language, crate class, downloads, ...). Non-normative until S05 contracts ranking; S05 may add keys under a minor schema version. |

A pattern kind has posture `practice` even when the repository it came from carries a do-not-depend verdict: studying a pattern is not depending on the software. The prompt still says where the pattern came from and its license.

## 3. Evidence

`evidence` = `{scheme, tier?, label?, flavor?, confidence?, basis, source, mapped_from?, verdict?}`.

- `scheme: rulebook-tier` means the entry carries one of RULEBOOK.md §1's five tiers (RULEBOOK.md:27-33): `tier` 1–5, `label` the tier's exact label (the schema pins label to tier), optional `flavor` such as `[Code-verified]` (RULEBOOK.md:35-42), and `confidence` High, Medium or Low (RULEBOOK.md:44).
- `scheme: verdict` means the entry is a judged repository or stack area: `verdict{ring?, trl?, stack_verdict?, assessed_commit?, assessed_date, verdict_url, posture_source{path, lines}}`. `posture_source` points at the line of the packet or verdict file that justifies the posture (IF-HONESTY.md HON-05).
- `scheme: ungraded` means the source item carries no tier of its own. `tier`, `label` and `confidence` are null and `basis` says so. 104 of the 136 rigor practices cite a source line with no tier tag (IF-SOURCES.md §2); they are ungraded until the maintainer decides otherwise (proposed DEC-P08).
- `basis` (20–400 characters, our words) is the one sentence a reader sees next to the badge.
- `source` is where the evidence lives (not what to copy).
- `mapped_from{system, label, rule}` records the original rigor-atlas or fh label and the TIER-MAP rule that converted it, so a reviewer can audit the conversion.

Which scheme each source uses: IF-SOURCES.md §2. How rigor-atlas and fh labels become tiers: TIER-MAP.md.

## 4. Pins

- Jeffrey's repositories: always a 40-hex commit. For the 44 verdicts and cohorts, the packet's pinned commit; for crates, the head the crate collector read; for fh and rigor-atlas rows, the revision recorded in the row.
- This repository's own files: the release tag `v<package.json version>`, the rule make-stack.mjs already uses (`site/scripts/make-stack.mjs:26-33`) so a committed, deterministic index needs no knowledge of its own commit. Lines can drift between releases for files edited after the tag (FR intake U13); the on-site `url`, which deploys with the index, is always current and is the primary link for `fr:` entries.

1. `fr:RP-009`: a rigor practice, tier taken from its cited source line, pinned at the release tag, on-site url with fragment.
2. `crate:asupersync/asupersync`: a published crate inheriting its repository's Pilot verdict, rider license from the repo LICENSE with the manifest string kept in `metadata_license`, owner-verified crates.io link, and a two-line rider-flagged quote.
