## Unreleased

The daily watch now flags a verdict only when a computed class moves, instead of opening one issue per event. On its first day, 2026-09-24, it opened twelve issues (#1 to #12), and only #5 led to a correction. The new behaviour is specified in [`watch/freshness/SPEC.md`](watch/freshness/SPEC.md) and tested against it by gate W3.

### Added

- **Freshness contract** (`watch/freshness/SPEC.md`): clauses with stable ids for the classifier (FR-C), class triggers (FR-T), `watch/live.json` and the live card (FR-L), the dashboard issue (FR-D), the weekly digest and the crossing ledger (FR-G), scheduled jobs (FR-O), and the harness (FR-H).
- **Class triggers and live data**: `node watch/watch.mjs --apply` computes the CI, release and license classes of each assessed repository at its pin and now, writes `watch/live.json`, and appends opened, resolved and withdrawn crossings to the append-only `watch/crossings.jsonl`. A crossing is resolved only by a dated re-check under `updates/`; a class crossing whose class returns to its baseline for two consecutive daily observations is withdrawn.
- **Live card on every brief** (`site/scripts/make-live.mjs`), rendered at build time from the committed `watch/live.json`, with no JavaScript.
- **One dashboard issue** (`node watch/freshness/dashboard.mjs --sync watch/live.json`), `[watch] Freshness dashboard`, edited in place under the watch's trust rules, and a **weekly watch digest** entry in `site/feed.xml` listing the crossings opened, resolved and withdrawn that week.
- **Freshness harness** (`watch/freshness/harness/run.mjs`, `bun run freshness`): reads the clause list from `SPEC.md`, runs every case in `watch/freshness/cases/`, allows an XFAIL only against a `DISCREPANCIES.md` entry with a resolution and a review date, and writes `watch/freshness/REPORT.md` (coverage per clause, fidelity against the master matrix, labelled-event precision and recall, replay noise, mutation score; a metric no case reports reads "not measured"). Runbook: [`watch/freshness/README.md`](watch/freshness/README.md).
- **Mutation runner** (`watch/freshness/harness/mutate.mjs`): plants each mutant in `harness/mutants.json` in temporary copies (one per worker, up to 8) and requires every named case to fail; an unmutated baseline must pass first, and a mutant whose text is missing or ambiguous, or that crashes the harness, is an error, not a kill. The harness case HAR-H6-mutants runs it and reports the score to `REPORT.md`.
- **Schedule** (`ops/schedule.tsv`, `ops/schedule.mjs`): one row per generated artifact this work adds, with its generator, workflow, cadence and gate. The check fails when a generator is not run by its workflow, a gate does not exist, or a script under `watch/freshness/` writes files without a `// writes:` header naming them.
- **Gate W3**: the harness with `--check-report` (including the mutation score from HAR-H6-mutants), the schedule check, and `make-live.mjs --check`. The chain now prints 23 gate lines (gate K prints five).
- **Deploy smoke step** warns (never fails) when `watch/live.json` is more than 36 hours old (`ops/stale-run.mjs`).
- **The Independent 100 study** (decision D4, 2026-09-25) at `/study/independent-100/`: an index, one page for each of the 99 people on the Independent 100 list curated by dan (@irl_danB, https://independent.prose.md/), and one page per deep dive (Mario Zechner and Pi; Geoffrey Huntley; dex and HumanLayer; Omar Khattab and alex zhang on GEPA and RLMs; the Hermes Agent group). The ranks and section names are his; the study is ours and not endorsed by him or anyone listed. Sources in `study/independent-100/` (`people.jsonl`, `deep/*.md`, `README.md` with the method, relevance rubric, limits and how to request a correction); pages by `node site/scripts/make-study.mjs`. The public edition carries no raw X data, locations, contact details, family, health, financial or legal details, images, identity resolution or local paths, and every link was checked on 2026-09-25. The correction form gained an "Independent 100 study" option, the page list in `shell.mjs` gained the study, and the Beyond page links it.
- **Gate N**: `make-study.mjs --check` (drift, page count, `people.jsonl` schema, and a scan for local paths, emails, phone numbers, images, X API field names, internal ticket ids and gendered pronouns on pseudonymous records), plus an independent page count. The study pages join `SITE_PAGES` (gates B, C, E, F, G, H) and the index joins gate I. The chain now prints 24 gate lines.

### Changed

- **Gate W** runs 18 cases, down from 22: the four that exercised the retired per-event issue sync (dedupe, issue trust, the since-pin backfill) went with it.
- **The scheduled watch** (`.github/workflows/watch.yml`) runs as two jobs, both only on `main`, neither keeping a token in `.git/config`. `build`, with a read-only token, installs, runs `node watch/watch.mjs --apply`, `make-live.mjs`, `make-feed.mjs`, `run.mjs --report` and the gate chain, and uploads only the generated files. `publish`, which alone can write, installs nothing and runs only dependency-free repository scripts: it copies in the generated paths from the artifact (`ops/take-build-output.mjs`, which refuses anything else), commits after `ops/briefs-guard.mjs` (a brief may change only inside its live card), pushes, and last syncs the dashboard, so a failed gate or push leaves the issue unchanged. `ops/write-job.mjs`, run by gate W3, checks the split: build holds only read or none permissions, every action is pinned to a full commit SHA, and publish sets no env variable but the token on its push and sync steps and calls node only as `node <allowlisted script>`; every publish run body must equal its reviewed text in `ops/write-job.mjs` byte for byte, so a publish change needs a checker change in the same commit. `ops/take-build-output.mjs` refuses a destination path that holds a symlink, before writing anything.
- **`--issues` and `--backfill-since-pin` are retired** for assessed repositories (usage error, exit 2). Issues #1 to #12 stay as filed.
- **Every workflow's token boundary** (decision D2, 2026-09-25). The weekly discovery (`.github/workflows/discover.yml`) runs as two jobs like the watch: a read-only `build` that installs, sweeps with `watch/discover.mjs --apply` and gates, and a `publish` that installs nothing, copies in only `watch/discovery/*.json` (`ops/take-build-output.mjs discover`), commits, pushes, and last syncs the week's rollup issue with the new `watch/discover.mjs --sync-issue <committed week file>`, which refuses an uncommitted file or a checkout that is not the GitHub tip of main, before any issue lookup. `watch/discover.mjs --issues` is retired (usage error). `triage.yml` names its `issues: write` on the job, not the workflow. `verify.yml`'s checkout no longer persists credentials. `deploy.yml`'s job checks main itself (`github.ref` and, for a workflow_run, the run's `head_branch`) on top of the `production` environment's branch policy, which is attested with `gh api` in `site/BUILD-GATES.md`.
- **`ops/write-job.mjs` checks every workflow**, not only the watch: any job holding a write permission must be a write job with a reviewed policy (actions, dependency-free scripts, env variables, token steps, and each run body byte for byte); any other job holds only read or none; every checkout sets `persist-credentials: false`; every action is pinned to a full SHA; nothing holds `id-token: write`; and no secret other than `GITHUB_TOKEN` appears anywhere except `CLOUDFLARE_API_TOKEN` on the three reviewed deploy steps, whose bodies are pinned too. Gate W2 gains four cases for `--sync-issue` (16 now).

## v1.2.0 (2026-09-24)

The project now runs itself: a daily watch of the 44 repositories, issue forms on every page, a feed, a weekly Rust discovery sweep, and automatic deploys after every change that passes the gates. The site was rebuilt from two independent audits and re-audited afterwards.

### Added

- **Daily watch** (`watch/`, `.github/workflows/watch.yml`): a scheduled job at 11:23 UTC reads the GitHub API for the 44 assessed repositories (pins parsed from `packets/`) and every public repository their maintainer owns. It writes `watch/state.json`, a dated census (`watch/census/`), and the changes new since the previous run (`watch/changes/`), and commits them only when the full gate chain passes. Material events (a release or tag, a license SPDX or LICENSE-text change, a workflow file added or removed (narrowed the same day to removals and first workflows; see Changed below), archived, renamed, deleted, a pin no longer an ancestor of HEAD, a new `franken*` or Rust repository) open one deduplicated GitHub issue each, capped at 20 per run, with the pinned matrix cells they may affect and the re-check checklist. Commit volume is informational only. The watch never edits pins, packets, or counts; the loop from issue to dated, independently reviewed re-check is in `updates/METHOD.md`. The first local run on 2026-09-24 is the baseline: 44 repositories checked, 215 public repositories discovered, 11 material events since the pins in 8 repositories, none since a previous state because there was none. The first run on GitHub (run 36008427571, manually dispatched, 1 min 40 s, success) committed its census (`e46c124`) with 0 new material events.
- **Gate W**: `node watch/watch.mjs --selftest` replays recorded GitHub API responses (`watch/fixtures/`) through the watch's own collect, diff, dedupe, and issue-sync code, offline, and fails if any of its cases fails or none run (21 at this release, including the issue-trust cases; corrected after the release by the independent reviewer). Shown to trip on a planted wrong expectation in a scratch copy.
- **Since-pin backfill** (`--backfill-since-pin`, with `--issues`): the first state was taken after the pins, so the material events between pin and baseline never reached a daily diff. The backfill files one issue per material-since-pin event, with the same titles, labels, body, dedupe, and 20-per-run cap as the daily path. When a dated re-check under `updates/` already names the release, it adds one comment linking it and leaves the issue open for the analyst. Run once on 2026-09-24, it filed issues #1 to #11: one release, six workflow-set changes, and four tags. #1 (`franken_code_browser` v0.1.0) got a comment linking `updates/franken_code_browser-2026-09-24.md`. A second run filed nothing and reported all 11 as already filed.
- **Live watch on the site**: the front door and the Updates page read `watch/latest.json` and the open watch issues from GitHub at view time ("Daily watch, 2 h ago: 33 moved since the pin, 1 issue open"), with a static fallback and no console errors when GitHub is unreachable.
- **Automatic deploys** (`.github/workflows/deploy.yml`): every push to `main`, and every successful watch or discovery run on `main`, runs the full gate chain and then deploys `site/` to Cloudflare Pages. The deploy is smoke-tested on its own `pages.dev` URL, and the Pages API must confirm it is the production deployment for this commit on `fr.zeststream.ai`.
- **Issue forms and triage**: forms for a correction, new evidence, a project to assess, an idea, and a site problem; every page's footer links a form with the page (and on a brief, the repository) already filled in. `.github/workflows/triage.yml` posts one acknowledgement per reader issue explaining what happens next. `docs/PIPELINE.md` describes the loop from issue to deploy. Also added: `CODE_OF_CONDUCT.md`, `SECURITY.md` (private vulnerability reporting is on), `CITATION.cff`, and a pull request template.
- **Feed and follow page**: `https://fr.zeststream.ai/feed.xml` (Atom: releases, dated re-checks, one entry per daily census) and `/follow/` with an OPML file that follows the releases and tags feeds of all 44 repositories. Gate M fails if the committed feed or OPML is stale or malformed; the watch run regenerates the feed.
- **Weekly Rust discovery** (`watch/discover.mjs`, `.github/workflows/discover.yml`, Mondays 12:17 UTC): searches for active public Rust projects with agent-built signals and files one rollup issue of candidates per ISO week; the screening rule is in `candidates/README.md`. Gate W2 replays recorded search responses.
- **Shared shell**: one navigation, footer, and page directory on every page, generated by `site/scripts/shell.mjs` (`bun run build:shell`) and enforced by gate S. The footer says who made the site and its relationship to the maintainer.
- **First dated re-check from the watch**: `updates/frankengit-2026-09-24.md` (watch issue #5). `frankengit` deleted 71 of its 78 GitHub workflow files four hours after the pin and made the other seven manual-dispatch only; at the re-check pin its CI class would be C5, not C3. Independently reviewed (`stack/reviews/frankengit-recheck.md`, accept with ten corrections, all applied). Published counts are unchanged. New rigor practice RP-136.

### Changed

- **The watch no longer flags workflow files added to a repository that already had some.** They cannot move the CI cell on their own and arrived almost daily; they are still counted in the census. Removals, and workflows appearing where there were none, are still flagged. Five of the first eleven issues were additions only and were closed with that reason.
- **Front door rebuilt from two independent audits** (desktop, and phone/accessibility/performance). A larger headline with three actions under it (Explore the map, See all 44 verdicts, Use the method on your repo); filters and legend behind one toggle, cutting the first desktop screen from 36 controls to 12; on phones the page scrolls normally instead of trapping the intro in a clipped box; map labels are real buttons with a wider touch radius (the audit measured 2 of 110 taps opening a repo); the repo panel is inert until opened; the render loop pauses when hidden; small text meets 4.5:1; the map key explains the cages and the centre. An independent re-audit of the live site afterwards scored clarity 8, polish 7, navigation 6, trust 9, delight 8, shareability 9, and "would I send this to a colleague" 8 (the first audit: 7, 6, 5, 7, 6, 7, 6).
- **Every brief opens with its verdict**: a strip under the title with the ring (in the map's colour), TRL, CI class, license, the brief's own "Use it? / Learn from it?" answers, a "Why" link, and "Spot an error? Correct this brief". Generated from the map's data by `site/scripts/brief-strip.mjs` and checked by gate V. The "what would change the verdict" lists that ran together in 27 briefs now show one item per line (markup only; the words are unchanged). Share cards use the map's ring colours; `/starter-kit/` and `/self/` have their own cards.
- **Starter kit**: a New repo / Existing repo chooser at the top. The existing-repo path was run as printed on a clone of a public crate, including a commit the hook accepts and one it refuses.
- **Starter kit claim checker** now fails, naming the row, when an `enforce=yes` row's `readme_pattern` is not in the README, and fails when a claims file passed as an argument does not exist. franken_markdown only warned about such rows and left them unchecked, so the gate stayed green while an enforced claim went unverified, and a hook pointing at a wrong path passed silently. `enforce=no` rows are still skipped. Tested with four planted registries (match, unmatched, violated, missing) on bash 3.2, dash, zsh 5.9 and bash 5.3, plus the starter-kit steps run as printed. Recorded in `starter-kit/README.md` under "Changes since the 2026-09-22 import" (`48a8c53`).
- **Security hardening from an independent review by a different model lineage** (GPT-6-Luna, 2026-09-24, before this release was tagged): the watch and discovery bots now act only on issues their own token opened, with the expected labels and machine markers, so a same-titled issue from anyone else is never commented on or edited (gates W and W2 cover it); repository and tag names are escaped before they reach issue tables; the Cloudflare token is readable only by deploy jobs on `main` (a `production` environment with a main-only branch policy); every page sends `X-Frame-Options`, a permissions policy, and host-only HSTS. The review also asked for a Pages-only deploy token; the maintainer chose to keep the existing account token, now confined to that environment.
- **Asset caching**: every stylesheet and script URL now carries a content hash (`assets/shell.css?v=<hash>`), stamped by `bun run build:shell` and checked by gate S, so a deploy can never pair new HTML with a cached old stylesheet or script. An independent re-audit hit exactly that: the new phone menu rendered with a four-hour-old `shell.css`, because the domain raises asset `max-age` to four hours whatever the site sends. `site/_headers` also asks for revalidation, which the `pages.dev` deployment URLs honour.

### Corrected

- **Starter kit: `scripts/check-claim-discipline.sh` could not read its registry on macOS (2026-09-24).** It split rows on `\001`, which macOS `/bin/sh` (bash 3.2) cannot split on, so it read zero rows and the pre-commit hook blocked every commit in a repository with a README. It now splits rows with `awk -F'\t'`. Found by running the existing-repo steps on a clone of dtolnay/itoa; tested under bash 3.2, dash, zsh 5.9 and bash 5.3 (`20337ec`).
- **The license rider was misread as at odds with the maintainer's use of AI agents (2026-09-24).** Several pages called the Claude-family co-authorship trailers in the maintainer's commits an "irony", a "tension", or "self-defeating" given the MIT + OpenAI/Anthropic rider, and some said the rider bars a project's own agent users. That conflated a customer using a lab's model with the lab itself. The rider withholds rights from OpenAI, Anthropic, their affiliates, and anyone acting on their behalf, and forbids use in ML training corpora or evaluation harnesses (`synthesis/briefs/maintainer-writing.md:43`). A developer building his own code with those labs' agents is not acting on their behalf, and neither is anyone else who uses their models on their own projects. No written statement of the maintainer's motive was found (`maintainer-writing.md:49`), so none is asserted. The facts and counts stand: the co-authorship trailer counts, the non-OSI (source-available) status, and the fact that the two labs, the parties most able to validate the code independently, cannot benchmark, test, evaluate, or build on it. Failure mode P10 is retitled "Who the rider bars, and who it does not"; twelve briefs, the frankenpandas map blurb, and the README's third finding are reworded, and each changed page carries a dated correction note. Evidence files (packets, synthesis, RULEBOOK) are unchanged (`69f782b`).
